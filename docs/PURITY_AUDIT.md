# Calculation boundary audit

EQ046/R3/issue52 audits corepair0.0.4a4 with CPython3.12, NumPy2.2.6 and PyArrow20.0.0. No formula, unit, timing, initialization, coverage, API, schema, algorithm or implementation version changes. Caller-supplied facts/configuration and caller-owned incremental state remain the calculation boundary. Source acquisition, adapter delivery, scheduling, cancellation, file publication, build/install and diagnostics stay outside it.

## Independent execution evidence

[Audit fixtures](../tests/unit/test_purity_audit.py) rerun existing independently derived numerical/admission tests instead of generating new expected values from the kernels. The full suite has631 top-level tests: prior628 plus three audit tests. Within those tests,619 existing cases run with Python file/network/clock/process entrypoints denied and a precisely scoped Arrow environment exception;593 of those cases additionally run with every selected environment read denied. These are repeated executions, not1212 new independent tests. Sixteen positive controls prove the guards reject before opening a file, obtaining a clock value, reading environment, connecting or starting work. Three external packaging/benchmark/resource diagnostic modules are excluded because their intended jobs use files/clocks/native diagnostic APIs; the new audit module is excluded to avoid recursion.

Guarded entrypoints: builtins.open,io.open,os.open,os.getenv,os._Environ.__getitem__,socket.socket/create_connection,threading.Thread.start,multiprocessing.process.BaseProcess.start,subprocess.Popen and time.time/time_ns/perf_counter/perf_counter_ns/monotonic/monotonic_ns. Modules, synthetic fixture drivers and NumPy/Arrow including pyarrow.compute are initialized before denial. Import startup can read files/environment and is not claimed pure. CPython3.12 unittest uses its own duration clock; only its local timing facade is replaced by a constant so the actual time module remains denied to calculations. No calculation receives that facade.

The current full calculation suite includes session batch/incremental/restore/legal-merge, all historical/composition/breadth/relative families, contracts/admissions/quality/evidence and trusted synthetic custom/adapter fixtures. Existing independent Fraction/hand-derived goldens and negative contracts remain authoritative. The separate123-reference mathematical checks remain mandatory. Passing fixtures do not prove every branch or arbitrary extension.

## Observed backend exception

The initial strict run failed Arrow sequence conversions on environment access. [Arrow20 source, _sequence_to_array](https://github.com/apache/arrow/blob/apache-arrow-20.0.0/python/pyarrow/array.pxi#L26-L43) reads PYARROW_IGNORE_TIMEZONE on each sequence conversion, not only startup. Lazy Arrow compute imports also invoked sysconfig environment discovery; preloading pyarrow.compute properly moves this backend initialization outside the execution audit. The full619 run permits only the existing PYARROW_IGNORE_TIMEZONE lookup, records which cases use it and requires the explicit26-case inventory to match. All other environment keys/getenv entrypoints remain denied. The strict593 run excludes precisely that inventory and allows no environment lookup. This exception is an observed third-party bridge behavior, not a hidden core clock/source dependency or a blanket environment exemption. Arrow conversion and native allocator/thread behavior are not certified free of backend environment/native state. Do not patch global environment inside calculations or advertise universal environment independence.

## Static and mutable-data evidence

Existing [fail-closed boundary policy](../tools/check_boundary.py) inspects all43 owned .py modules with38 negative and10 positive import/call fixtures, restricting owned code to declared in-memory Python/backend APIs. It rejects filesystem/database/network/clock imports, dynamic loading/reflection, prohibited backend I/O, escaped backend namespaces and unreviewed backend operations. [Pure import checks](../tools/verify_imports.py) separately verify base public imports without optional/source dependencies. Static admission covers unexecuted owned branches; it is not a security sandbox.

Before/after snapshots inspect43 loaded owned modules, declarative builtin scalar/container values and dataclass fields, including built-in catalog data/identities. Import machinery, modules, classes/callables and unknown/native object internals are excluded. Both guarded suites leave the snapshot equal. A deliberately inserted mutable dictionary changes the snapshot when mutated and is removed afterward, demonstrating detection and restoration. Caller-owned accumulators/results/registries may evolve according to their explicit API; this does not establish immutability of arbitrary Python objects or native/global state outside the snapshot.

[Resource audit](RESOURCE_BEHAVIOR.md) separately checks supplied caller stop/cancel/limits, retained dimensions and observed Python thread/process creation for six owned reducer families. Optional backends can own native pools; initialization/native globals/all C entrypoints and trusted custom callbacks are outside these Python guards. No database driver is an owned dependency; acquisition adapters and any provider/database integration remain separate future scope. No new worker, job, credential, output publication or R4 capability.
