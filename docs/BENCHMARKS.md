# Representative experimental benchmark baseline

EQ041 measures the existing checked Python implementation, not a proposed accelerated backend. Corepair0.0.4a4 and consumer0.3.0 are unchanged. [Plan](stories/EQ-041_PLAN.md), [harness](../benchmarks/run_baseline.py). Inputs are synthetic, supplied in memory; harness timing, process inspection and result publication are outside both core packages.

## Reproduction and workloads

Install matching actual contracts/features wheels or sdists into a clean environment, plus pinned NumPy2.2.6/PyArrow20.0.0. Run `python -I benchmarks/run_baseline.py --output baseline.json` from the matching repository. The script itself is an external repository tool; every child requires actual installed core paths, uses isolation and public APIs. `--quick --repetitions 2` executes the small installation/CI smoke. Full default uses three independent child processes serially:128uniform,16384uniform and16384skewed trades, seed41001, K8, chunk sizes128/1024, three repetitions. Each case additionally measures128or512 governed daily sessions (bounded separately from trade N), SMA/EMAperiod20 with explicit S0anchor, and returnperiod19. All input prices/shares are positive exact coefficients in USD scale0, complete coverage and original causal knowledge; no private data or provider acquisition.

Uniform trade prices draw integers100..200 and sizes1..100 using local seeded Random. Skewed sizes are100000every97th row and1otherwise, with the same seeded price sequence. Strict event times/order/IDs and supplied source/scope/config are deterministic. JSON SHA256 of the canonical field list records the fixture independently of calculation outputs. Small/large are relative synthetic test sizes, not proof of production or billion-row capacity. Inputs are not intended to represent an empirical market distribution.

## Correctness before timing

Untimed independent checks compare count, integer volume/notional and Fraction-derived VWAP/mean-size; full sorted topK ranking uses(-size,event_ns,order_key,event_id). Chunked final results must match batch values/quality and the independent totals. Historical SMA/EMA and return use independent exact rational sums/recurrences/endpoints and final rtol/atol1e-12. Failed parity raises instead of publishing measurements; optimized Python that suppresses assertions is rejected in the child. Independent unit fixtures freeze eight seeded trades/totals and verify a deliberately incorrect result is rejected. Existing mathematical/reference/full-unit gates remain separate; a benchmark samples representative families rather than claiming coverage of all39 IDs.

## Timing and copy measurements

One untimed execution/check warms each operation; min/median/max and every sample in nanoseconds are retained. Rows/sec equals supplied rowcount divided by median wall duration. [Python3.12 perf_counter_ns](https://docs.python.org/3.12/library/time.html#time.perf_counter_ns) measures elapsed time, including scheduling contention; clock implementation/resolution and default enabled garbage collection are recorded. Full public checked calculation calls include admission/validation/output construction. Fixture construction and chunk materialization are separately timed; timed streaming includes accumulator construction, all updates and finalization of already materialized chunks. No fixture/conversion time is silently included in calculator time or subtracted from a measured number.

Outward/inward Arrow and NumPy conversions are separately timed after untimed roundtrip equality. NumPy mutation probes verify original/restored canonical prices remain owned; reported array/mask count and total nbytes, plus Arrow visible-buffer nbytes, measure exposed representations only. They do not count hidden temporaries, Python object overhead or every internal copy. Copy timings include each public conversion's work; no zero-copy claim. Retaining full materialized chunks/input and previous backend objects contributes to whole-process memory, not to accumulator state alone.

## Native memory, hardware and thread provenance

Each case reports process-lifetime peak resident bytes after imports, after the trade fixture and at completion. Windows uses [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo) and [PROCESS_MEMORY_COUNTERS.PeakWorkingSetSize](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters) in bytes; Linux uses [getrusage(RUSAGE_SELF).ru_maxrss](https://man7.org/linux/man-pages/man2/getrusage.2.html) in KiB multiplied1024. Other platforms reject. These cumulative high-water values include interpreter/imports/input/reference/backend/transient/result memory. Their difference is not an isolated calculator allocation or current resident size; Python tracemalloc alone would miss native allocations. EQ042 separately studies retained state and resource controls.

System/release/machine/CPUidentifier/logicalCPU/Python/core/backend versions and source/harness SHA256 are recorded without host/user/private paths. Harness hash uses UTF8 with normalized LF, making checkout line endings explicit. Children request OMP/OPENBLAS/MKL/NUMEXPR budgets1 before imports and explicitly set/report Arrow CPU/I/O counts1. Other backend effective pools are not independently introspected; requested environment values do not prove hardware affinity or exclusive CPU allocation. No hidden core threadpool is introduced. Each baseline records actual measurements on its environment; concurrent machine activity, CPU scaling, warm caches and virtualization can change results. No universal speed, platform comparison or invented pass threshold. Optimization requires separately measured benefit with parity under these declared semantics.
