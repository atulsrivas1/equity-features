Public MCP tools expose no caller-selected path, SQL, executable code, origin, token, TLS policy or provider callback. ## Failure and resource limits

Supported exact replay invokes only the accepted retained calculator and compares complete original bytes. A supported replay calls once, including a valid result whose original quality is unavailable/missing_input/future_knowledge; reproducing that quality can match without making the value available. An absent retained input batch instead returns unavailable with zero calculator calls; a calculator-absent light installation returns incompatible with zero calls; explicit pre-entry cancellation returns cancelled_before_start with zero calls. Inconsistent supplied reports refuse before calculator entry. These outcomes remain distinct. There is no automatic replay of a sent mutation or ambiguous ledger append. Unknown commit state requires the documented manual reconciliation against retained proposal/terminal context.

The synthetic narrative grammar is `session.trade.count=<nonnegative decimal integer>`, bounded to at most128ASCII bytes. Unsupported prose stays unsupported/DEFER even when an explicitly requested replay matches. This example's selected advisory unknown-diagnostic policy leaves admission `not_applied`; this is not a general rule for strict policies that can deny unknowns. DEFER or REJECT never grants action, trading authority or human approval. Missing model identity, unknown evidence, content coverage, replay match and anchor/retention state remain visible independently.

Application bounds on event bytes, nodes/depth, tuple sizes, report/frame/chunk bytes, call counts, ledger events and canonical bytes are logical admission limits. They do not establish total RSS, SQLite physical page/journal/cache size, disk bytes/nodes, kernel allocations, hard execution/cleanup deadlines or hostile-Python isolation. Qualified process-death/reopen tests do not prove power-loss durability or arbitrary network-filesystem correctness. Active synchronous callbacks/DNS cannot observe EOF until returning; partial output may expose a prefix and fail closed. No atomic replacement, hard cancellation or generic recovery guarantee follows.
