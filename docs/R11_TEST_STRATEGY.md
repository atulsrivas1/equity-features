# R11 verification strategy

Companion to [handoff](R11_AUTONOMOUS_HANDOFF.md), [release plan](R11_RELEASE_PLAN.md), [GOV023](https://github.com/atulsrivas1/equity-features/issues/406) and original EQ106–110 criteria. This file specifies future checks; it reports no runtime test pass. Literal fixture counts, source maps and supported dependency versions are frozen in each story before qualification.

## EQ106 — contracts and authority

Hand-author minimal canonical event bytes, exact node/depth/byte counts and expected SHA256 with an independent standard-library oracle before production encoder/hash code. Include every supported kind and subject; empty/missing optional identity; late/equal occurred times; real execution distinct from historical C/K/E; correction/cancellation/error references; complete, unavailable, redacted and truncated evidence; privacy allowlist and fixed errors. Mutate each bound field, sequence, chain, schema/canonicalization and previous hash independently. Unsupported enums/versions, unknown or duplicate JSON fields, ambiguous numbers, nonfinite values, booleans-as-integers, surrogates, limits and trailing bytes refuse explicitly.

Compare full immutable objects and canonical bytes, not a subset or only metadata digests. Mutating original caller sequences after construction must not alter records. Pure contracts must not read time, environment, files, databases, credentials, network, models or provider services. Reference validation distinguishes malformed, missing context and a genuinely verified retained earlier event. No guessed actor/model identity or synthesized source proof.

## EQ107 — chain and storage

Use independent two/three-event chains and trusted external expected heads. Alter, reorder, duplicate, omit an interior event, introduce sequence gaps or cross-chain references and require exact failures. A valid shortened prefix is internally consistent but lacks terminal anchor coverage; test this positive distinction, anchored suffix deletion and whole-chain replacement. Continuation/checkpoint verification must require enough explicit context; arbitrary as-of filtering is not an intact chain. Corrections preserve originals and their linkage.

Test append without copying the whole chain; quota boundaries and bounded lookup/index work; transactional uniqueness/reference checks; two separate processes competing for the same next sequence/event ID; controlled busy/lock failure; incomplete construction and closed-store errors. Freeze actual database journal/transaction/ack semantics and injected crash cut points. Kill only owned test writers before transaction/inside uncommitted transaction/after committed data and before acknowledgment, reopen and verify exact state plus unambiguous caller recovery. Do not infer power-loss durability, network filesystem correctness or hostile-host security from process-crash fixtures. Preserve real ambiguous outcomes rather than automatically replaying a possibly committed append.

Use only synthetic owned temporary stores; no arbitrary caller cleanup, recursive deletion of borrowed roots or production storage. Separate application byte/event bounds from actual SQLite pages/journal/cache/resource observations. Tests must not declare a physical bound from a local counter.

## EQ108 — existing MCP integration

Exercise the exact worker-owned server through the official SDK and public RemoteClient with actual synthetic loopback/native service fixtures. Verify discovery and advertised schemas, all new tools' complete structured/text consistency, original producer/quality/receipt references and absence of invented native-envelope evidence. Include unsupported/unavailable evidence, requested-but-unknown diagnostics, mismatched full fingerprints despite equal metadata, changed current backend authorization, principal isolation, expired/retired handles, reference exhaustion/tombstones and always-read artifact followup.

Oversized input/frame/arguments, excessive nodes/depth, extra credential/URL/path/provider/code fields and malformed output refuse before unauthorized actions. Test existing callback/EOF/partial-output and explicit manual same-key followup semantics without claiming hard cancellation or automatic replay. New tools must not invoke model/calculation/source/sink code inside handlers or write the ledger. Fake wire/unit tests are not the official-SDK/native composition proof. Fix capability/schema/bounds versions before source review and qualify parent AND child installed origins.

## EQ109 and EQ110 — consumer and delivery

A fresh external synthetic consumer records request, tool response evidence, diagnostic/admission state, declared model identity or its absence and action/approval references. Verify the ledger against an independently retained expected head; replay only the accepted supported R9 calculator with complete original input/config/result/quality/receipt comparisons. Deliberately wrong narrative, changed value with equal metadata, unsupported replay, unknown evidence and missing retained bytes must remain distinct. Matching unknowns must not become safety or execution permission.

Qualify wheel/sdist pure and integration forms on Windows/Linux with exact Git source/payload maps, repeat builds, package metadata/licenses/dependencies, RECORD and installed origins. Light forms must actually lack optional native/service dependencies where declared. Preserve existing R7/R9/R10 cohort and public typing/consumer parity as relevant; declare overlapping tests and shared environments honestly. Audit downloaded current artifacts by actual head/tree/size/digest/expiry/every entry, not old filenames or green check tokens. Independently verify actual published main and attribution after each guarded merge, then original acceptance criteria/lifecycle/current evidence and exact milestone membership at release closure.

All performance claims require measured comparisons and parity; no speedup is required for R11. Source independence and authoritative backend access are mandatory. No compliance, universal leakage, source truth, model reasoning, unique-market, hard deadline or production-hosting certification follows from these tests.
