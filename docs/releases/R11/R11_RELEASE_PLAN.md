## Outcome and unchanged scope

A synthetic external research consumer can record declared requests, model/tool identities, actual calculation evidence, diagnostic findings and action/approval references; verify a canonical event chain against an independently retained expected head; use evidence-aware tools on the existing MCP server; and replay the supported retained calculation. These capabilities do not prove truthful or complete logging, source authenticity, identity, profitability or compliance.

Preserve original EQ106–110 allocation/dependencies and31 provisional complexity points. GOV023 is three additional governance points; exact milestone membership is epic195, runtime206–210 and governance406. No deadline, velocity or release date is invented. ## Architecture decisions to resolve per story

EQ106 owns new pure event contracts and reference verification; EQ107 owns external SQLite persistence, global uniqueness/reference indexes, transactions and checkpoint export; EQ108 owns the compatible extension of existing worker MCP/client-facing composition; EQ109 owns the external synthetic agent demonstration; EQ110 owns current integrated delivery and positioning. Proposed package allocation and exact version/import constraints in the handoff must be frozen in EQ106 before code. New event hashes use their own domain and canonicalization; they never reinterpret ResultMetadata.identity_digest or a R9 fingerprint domain.

Select standard-library SQLite for the first local store, subject to EQ107's concrete design and independent fixtures. Define schema/version migrations, transaction boundaries, locking/busy failure, append acknowledgment, ambiguous commit/reopen handling, supported journaling mode and crash cut points before implementation. Store validation and integrity checks must reject malformed or mismatched chain/head/reference state; never repair an unknown prefix silently. A record/application quota is not a universal physical storage guarantee. Configuration choices and measured behavior must be documented on the actual supported OS/filesystem.

Expected heads/checkpoints are explicit trusted caller inputs. No signing keys, blockchain, external witness service or R13 trust product is implemented. Define missing/covered/mismatched checkpoint states and anchor ownership. Demonstrate that internal consistency alone accepts a valid shortened prefix; only a separately retained expected terminal identity permits detecting that suffix loss. Corrections are new retained events; redaction occurs before recording or as explicit disclosure, not silent history mutation. Do not promise erasure of previously stored plaintext or replay of absent content.

Use immutable closed kind-specific event subjects and declared actor/model/time fields. Reject unsupported types and generic nested arbitrary objects. Default examples contain synthetic bounded facts or content references, not credentials, hidden reasoning, model prompts or private datasets. Typed allowlists reduce accidental capture but do not authenticate label contents or detect every secret a caller mislabels; document that responsibility. Separate recording order from event occurrence and simulated availability; equal or decreasing supplied occurred time is not itself a sequencing error.
