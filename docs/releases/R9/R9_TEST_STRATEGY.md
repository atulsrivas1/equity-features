# R9 verification strategy

Prepared with [R9 release plan](R9_RELEASE_PLAN.md), [GOV021#391](https://github.com/atulsrivas1/equity-features/issues/391). This is a proposed protocol, not executed R9 test or acceptance evidence. Each story freezes exact support/limits/fixtures before Ready. Existing source-independent calculation definitions remain unchanged.

## Receipts and fingerprints

- Independently specified canonical bytes and known digests cover empty/single/multiple rows, int64 extrema and values above2^53, exact UTCns, float64 signed zero/subnormals/nonfinite policy, Decimal representation where supported, bool versus int, null validity, units/scale and enum/schema/domain versions. Expected bytes/hashes are independently derived, not generated by the production helper being tested.
- One mutation at a time changes a value, null bit, unit, row/tie ordering, entity/session/namespace, formula/config, quality, evidence, cutoff, revision or basis. Metadata-equal/value-different inputs/results must differ. Allowed presentation permutations remain invariant only where explicitly normalized; semantic order never disappears.
- Reject duplicate roles/keys/identities, unsupported types/extensions, malformed digests, unknown schema/canonicalization/algorithm versions, ambiguous JSON, cyclic/nested-over-budget records and inconsistent references. A valid digest does not assert authenticity; privacy-sensitive hashes are not authorization or secrecy.
- Verify immutable construction and mutation isolation, optional import independence, closed deterministic errors and complete status/quality/evidence content. Reuse accepted core/R8 identities under their original domains; never replace full-content verification with metadata-only equality.
- Measure separately canonicalization/materialization, hash-only cost and complete receipt generation for fixed supplied synthetic populations. Retain raw samples, input bytes/rows, environment and limits. Streaming/chunking must preserve identities and demonstrate declared memory behavior without pretending observed RSS is a physical quota.

## Bundles and replay

- A fresh installed public consumer creates a real core result, exports permitted data-only material, verifies manifest/entry identities, reconstructs only supported records and explicitly invokes a trusted installed feature registry. Compare complete result/identity/status/quality/evidence and specified numeric fields, then mutate each binding and prove refusal or the documented unknown/unavailable outcome.
- Reject traversal, absolute/drive/UNC paths, alternate separators, NUL/control spellings, duplicate/case/normalization aliases under supported platform rules, symlinks/hardlinks/reparse tricks, undeclared entries, inconsistent sizes/hashes, decompression bombs, excessive nodes/depth/records and unsupported encodings before unsafe materialization. Use newly owned roots and nofollow cleanup; preserve borrowed inputs and conflicting foreign entries. No executable-object deserialization, code/module paths, credentials, automatic installs or arbitrary URL fetching from manifests.
- Test missing/unavailable external immutable references separately from changed content. Wrong dependency/registry/algorithm version refuses replay before execution. Allowed cross-platform tolerance is explicit and cannot relax input content identity, precision/time/unit checks or status/quality/evidence equality. Unknown cleanup/cancellation outcomes remain explicit; no automatic replacement execution after uncertainty.
- Test fresh Windows/Linux wheel and sdist consumers, wrong source-tree origins, optional-package absence and explicit supported imports. Actual artifact hash/size/head/expiry, complete archive/RECORD/sdist/source maps and installed package provenance bind claims; not every platform or future dependency combination is qualified.

## Explanations and evidence completeness

- Independently expect formula/version/config/input references, C/K/E cutoffs, quality/coverage/exclusion reasons and admitted/unknown facts. Metadata identity, content equality, replay parity and mathematics/source verification have distinct outcomes.
- Boundary cases cover zero retained items, exact truncation limits, oversized summaries, missing references, omitted retained detail, genuinely not-supplied evidence, contradictory links and unavailable source material. Truncation must not silently become a complete proof or a fabricated calculation reason.
- Explanations use typed supported facts and deterministic templates/records; they do not add model-generated claims, hidden chain-of-thought, wall-clock facts or ledger/agent authority. Complete evidence lives outside numerical kernels.

## Release and review

Run meaningful unit/negative/compatibility/import/typing/boundary tests for changed packages; independent numerical goldens establish actual producer parity. Keep author results, separate final-head review, CI, installed forms and release acceptance distinct. Record original failures and changed corrections; never invent a pass or rerun an unchanged failed native/operational workload for status.

R9's final qualification composes the five accepted capabilities, reports measured overhead and bounded threat/rights/retention limits, and verifies actual source/artifacts on the delivered defaults before Released/Done. Existing R8 measurement/acceptance and R7 operational receipts stay frozen. R10 leakage diagnostics, R11 ledgers/MCP, stronger platform isolation, provider rights and production/registry work remain out of scope.
