# EF3 relative statistics and realized variance implementation

[EQ-153 #487](https://github.com/atulsrivas1/equity-features/issues/487) and [EQ-154 #488](https://github.com/atulsrivas1/equity-features/issues/488) library layer: the pure `ef3.relative_stats` (`relative.beta`, `relative.correlation`, `relative.residual_return`) and `ef3.daily_log_volatility` (`history.log_return_volatility`) producers in `packages/features` (module `equity_features.ef3`, next to `ef2`) and the pure `ef3.intraday_realized_variance` producer (`intraday.realized_variance`, `intraday.realized_volatility`) in `packages/intraday`. The frozen [contract](RELATIVE_RV_CONTRACT_PROPOSAL.md) (versions `ef3-rel1`, `ef3-dlv1`, `ef3-rv1`, decisions DP-S1 to DP-R8, rulings O1 to O12 and its coordinator freeze) governs; this slice implements it and redefines nothing. The EF3 I/O mapping (#611), worker (#612) and release acceptance (EQ-157) layers remain separate.

## Structure

`packages/features/src/equity_features/ef3/`: `_common` (daily grid context, close-only BAR admission, quality vocabulary), `_relative` (config, exact mathematics, readiness, evidence), `_logvol` (config, Decimal120 mathematics, readiness, evidence), `_definitions` (own discovery), `_dispatch` (`compute_ef3`). `packages/intraday`: `_rv_config` (builder, closed decoder over the R17 context), `_rv_registry` (own catalog and digest), `_rv` (readiness, Decimal120 mathematics, evidence, dispatch). The R17 admission and context are reused unchanged; the R17 catalog is untouched, so `describe_intraday()` still lists exactly the eight accepted R17 IDs and its digest is unchanged. The shared validators, the default registry, the existing `history.return_volatility` and `relative.market_return`, and every EF1/EF2 output are unchanged; no package version is bumped.

## Daily grid context

`equity-features` does not depend on `equity-features-intraday`, so the daily producers carry a local `DailyGrid` (the R17 grid and slot-coverage conventions: one slot per governed session with exact `[open, close)` bounds, slot coverage entries named `slot:<index>`, the instrument, calendar, grid and revision identities and the target slot). The config binds it by schema and SHA-256 (`grid_schema`, `grid_sha256`) instead of embedding it (the R17 transport bounds of 64 sessions and 64 KiB would not hold a 4096-return window); the grid is supplied again to `decode_*` and `compute_*`. The target slot may precede later governed sessions, which are structurally admitted but can never influence the target (the prefix property); the market cutoff must follow the completed target session.

## Mathematics and numeric policy

Relative statistics use exact rationals only: returns `(C_j - C_{j-1}) / C_{j-1}` as unreduced integer pairs summed pairwise, centered sums as `n * sum(xy) - sum(x) sum(y)` (the declared `n-1` denominator cancels in every published ratio), one binary64 rounding (`int / int` true division). Correlation is the exact rational root when numerator and denominator of `Sxy^2 / (Sxx Syy)` are perfect squares, otherwise a Decimal120 square root of the exact rational; it is never clamped. Zero tests are exact (`Fraction`), so the near-constant benchmark of RS17 is available. Daily log volatility and realized variance evaluate each `ln(C_i / C_{i-1})` in Decimal120 (precision 120, `ROUND_HALF_EVEN`, R17 traps) from the exact ratio, so ratios within 1e-15 of one keep their accuracy; the variance is two-pass; volatility is `sqrt(A * variance)` in Decimal120 and one guarded float64 conversion.

**Exact-zero limit (release-gate item).** `+0.0` is guaranteed where the mechanism is exact: relative statistics return `+0.0` for beta, correlation and residual whenever the exact rational is zero (RS05, RS07; `Fraction` zero converts to the positive zero); daily log volatility returns `+0.0` whenever all N close ratios are equal, decided by integer cross-multiplication before any logarithm (DV06, DV07), because the Decimal120 centered sum of identical logarithms could otherwise leave a residue of about 1e-120; realized variance and volatility return `+0.0` exactly for a flat epoch, because an equal-close step contributes exactly zero and every other step contributes a positive square (RV04). Correlation of exactly plus or minus one is bit-exact only through the perfect-square path (RS03, RS04, RS23); every other correlation is irrational and carries the R17 tolerance. No other value is snapped, and there is no absolute floor.

**Memory and time.** Batch API only; the window is materialized (O(W) rationals). A 4096-return relative window with 9-digit closes computes all three outputs in about 2.7 s in the scratch check; the contract's O(1) state requirement belongs to a future incremental API.

## Readiness, counts and evidence

Per-slot causes follow the contract precedence `absent_input`, `unknown_availability`, `future_knowledge`, `null_field`, `governed_gap`, `insufficient_history`, `no_eligible_observations`, `zero_denominator`; every applicable reason is reported in enum order and the status follows the first. Knowledge uses the original `known_at` against the knowledge cutoff in every availability mode (`known_at = K` is known). An absent role (`None`) gives only `absent_input` with observed 0. Reasons are the causes of the lost slots only; `insufficient_history` is added only when the window is not wholly inside the grid (relative: `t - W < 0`; daily: `t - N < 0`; intraday: `t = a`). The residual additionally requires the target pair, and a lost target pair gives it the causes of the target slots while correlation and beta stay available. Daily grids have no empty-slot state, so a declared-empty daily slot is a governed gap; only the intraday producer maps a coverage-proven empty slot to `no_eligible_observations`. Evidence rows (available outputs only) use the id `slot:<index>` with boundary `completed_interval`, truncated to the result-wide `evidence_limit`.

Admission runs the shared `validate_batch` first, so a repeated interval is `DUPLICATE` before the slot-bound check, then the producer checks: namespace, unit (`INVALID_UNIT`), adjustment (`UNSUPPORTED_ADJUSTMENT`), scope, row instrument (`INCONSISTENT_IDENTITY`), grid membership, cutoff and order (`INVALID_ORDER`, a producer admission check against the grid order), and exact per-slot coverage. The two relative roles are also checked batch against batch with `require_compatible_inputs`.

## Notes under contract Amendment 1

1. **Available with lost pairs (RS09, RS11).** An available relative output publishes `expected = observed = n` used pairs (the window length is not published); the causes of the lost pairs are reasons on the available row and excluded evidence rows (existing rows only, after the consumed witnesses). An unavailable output keeps `expected = W`.
2. **Evidence limit is result-wide.** A single-output selection reproduces each fixture's witness list; a joint selection truncates in lexical output order.
3. **Evidence row ids** are `slot:<index>`; the role is carried by the input id of the supplied batch.
4. **Prefix property for realized variance.** The R17 context requires the target to be the final governed slot, so PX03 is verified through its base fixture RV21; PX01 and PX02 run with later sessions on the local `DailyGrid`; they are constructible only when the market cutoff is at or after the end of those later sessions.
5. **RF43** is raised by the config builder (`BOUNDS`); the per-row bar-end check cannot trigger under a valid config.
6. **Roles and counts.** More than two relative role slots is `INVALID_CONFIG` (a third role); fewer than the fixed slots is `INVALID_SCHEMA`.

## Author source validation

A standalone manual script (not committed, no test files added) built canonical batches for all 62 result fixtures, the 3 prefix-property fixtures and the 48 refusal fixtures and compared every value (R17 tolerance, bit-exact including `+0.0` where the fixture says bits), status, reasons, counts and witnesses (including excluded rows) with the amended contract: the author reports 62/62 result fixtures, 3/3 prefix-property fixtures and 48/48 refusals matched (author-reported; not independently confirmed here). Both availability modes give the same values and quality rows (knowledge uses the original `known_at` in every mode). One documented exception to the contract `mode_rule`: the shared `FeatureResult` validator (unchanged) rejects an excluded `unknown_availability` or `future_knowledge` evidence row when the availability mode is reconstruction, because `knowledge_reason` is `None` there; so `ef3.relative_stats` emits those excluded evidence rows in `known_at` mode only, and the evidence tuple of a reconstruction result omits them. Emitting them in both modes needs a change to the shared validator or an amendment. Random series (900 relative, 200 daily, 400 realized checks) matched an independent exact/Decimal oracle within the R17 tolerance. A before/after snapshot of R17 results, the EF2 money-flow, momentum, channels and retracement producers, `describe_intraday()` and its digest was byte-identical. The author reports mypy strict clean on the new modules (author-reported). `CONTRACT.json` is not amended here.

## Cost

The cost of `ef3.relative_stats` grows with the magnitude of the closes, because the exact rational arithmetic keeps unreduced denominators. For a 4096-return window it takes about 0.2 s with 4-digit closes, about 2.5 s with 10-digit closes and about 10.5 s with 16-digit closes. Log volatility and realized variance take about 0.7 s on 4096 slots. These figures are author-observed timings on one machine, not a performance claim or gate.
