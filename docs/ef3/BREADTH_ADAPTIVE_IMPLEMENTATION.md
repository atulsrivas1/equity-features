# EF3 breadth and adaptive volume implementation

[EQ-220 #598](https://github.com/atulsrivas1/equity-features/issues/598), [EQ-242 #667](https://github.com/atulsrivas1/equity-features/issues/667) and [EQ-237 #626](https://github.com/atulsrivas1/equity-features/issues/626) library layer: the pure `ef3.session_breadth` (16 `breadth.session.*` outputs), `ef3.observed_breadth` (7 `breadth.observed.*` outputs) and `ef3.adaptive_volume` (10 `adaptive.volume.*` outputs) producers in `packages/features` (module `equity_features.ef3`, next to the daily-grid and robust producers). The frozen [contract](BREADTH_ADAPTIVE_CONTRACT_PROPOSAL.md) (versions `ef3-breadth1`, `ef3-obsbreadth1`, `ef3-adaptive1`, decisions DP-*, rulings Q* and its coordinator freeze) governs; this slice implements it and redefines nothing. The EF3 I/O mapping (#611), worker (#612) and release acceptance (EQ-157) layers remain separate.

## Structure

`packages/features/src/equity_features/ef3/`: `_breadth_common` (reference-id grammar, closed fact admission and price-column modes, fact resolution with the contract reasons, Kleene conjunction, member evidence), `_breadth` (config, declared population admission, the 16 outputs), `_observed` (config, roster scope and group filter, the 7 outputs), `_adaptive` (config, admission, the exact recurrence, the 10 outputs), `_breadth_definitions` (own discovery) and `_breadth_dispatch` (`compute_ef3_breadth`, routed by config identity). It reuses E's `_robust_common` helpers (`parameter_map`, `check_policy`, `check_features`, `check_slots`, `check_entity`, `reduced_pair`, `make_config`, `first_status`, `ordered`, `_check_meta`) and `_stats.to_float`; the existing modules are unchanged and `__init__` only gains an appended import and `__all__` block. The R17 catalog, `describe_intraday()` and its digest, the shared validators, the default registry and every EF1/EF2/EF3-D/EF3-E output are unchanged; no package version is bumped.

## Public surface

For each producer: `build_*_config` (explicit keyword parameters, no default except `evidence_limit`; the target `SessionSpec`, availability, adjustment and a mandatory `PriceUnit`), `decode_*_config` (closed envelope, byte-identical rebuild) and `compute_*` taking the fixed nullable role slots (nine for `session_breadth`, four for `observed_breadth`, one for `adaptive_volume`), the result `entity` and the selected `features`. A selection fixes the optional parameters: `near_high_tol_*` exactly when `breadth.session.near_high_fraction` is selected and `near_low_tol_*` exactly when `breadth.session.near_low_fraction` is selected (any other combination is `INVALID_CONFIG`). Roles that no selected output needs are neither examined nor bound. `ef3_breadth_definitions(config)` and `require_ef3_breadth_capability` provide discovery and the batch-only capability check.

## Mathematics and numeric policy

Counts, sums, comparisons, proximity and rank run on exact integers; no float participates in a decision. A declared or observed float is `int / int` (one correctly rounded division). The adaptive baseline is kept as an integer pair `B = P / Q` with `P' = tau P b + d a Q`, `Q' = Q b (tau + d)` for a rate `a / b` (an unchanged baseline when the elapsed time is 0, a gcd reduction every 32 steps); the relative rate and acceleration are integer ratios. A peak is compared by its correctly rounded float first (rounding is monotone, so unequal floats decide) and by cross multiplication of the exact integers only on equal floats, so an exact near tie (AD28) is decided exactly and the earliest observation wins an exact tie. Published adaptive floats are the single rounding of the exact value (the verification found them bit identical to the contract floats, inside the contract tolerance). Sums are unbounded Python integers; only a published `up_volume`/`down_volume` above 2^63-1 is `OVERFLOW` (RB23, RB27).

## Admission, readiness, counts and evidence

The shared `validate_batch` runs first on every examined role (so a duplicate or unordered row is `DUPLICATE` or `INVALID_ORDER` before any identity check), then the 4096-row bound (checked before it), the metadata and unit checks (every role batch, including the population and roster, must carry the config `PriceUnit`; RB30), fact kind, reference grammar, session, price-column mode and the identity checks, all with existing codes (RB01 to RB30, RO01 to RO15, RA01 to RA17). Per-member causes follow the contract precedence; every applicable reason is reported in lexical order and the status follows the first. Population-level findings (role `None`, incomplete coverage, an expected row with null or later knowledge) make every output unavailable with `expected` `None` and `observed` 0; `N = 0` gives `not_applicable`/`empty_universe` with 0/0. Evidence rows are emitted for available outputs only: the deciding fact rows of the first contributing members in population (roster) order with the ids `member:<instrument_id>`, and for adaptive outputs the witness observation with the id `seq:<sequence>`. Count and fraction outputs cite the role named in the contract (`prior_reference_availability`, `current_return`, `cumulative_volume`, `endpoint_price`, `momentum`, `qualifier_price`, `change`); derived outputs cite none.

## Notes, gaps and contract nits (recorded, nothing redefined)

1. **Evidence limit is result-wide**, as in E: the shared `FeatureResult` bounds the total evidence rows by `evidence_limit`; a single-output selection reproduces each fixture list and a joint selection truncates in lexical output order.
2. **Witness boundary.** Evidence is bound to the REFERENCE role input with boundary `ordinary` (the shared validator admits `completed_interval` only for BAR and DAILY); the event time is the fact `effective_start_ns`.
3. **Reference-id grammar.** The contract writes `stint6` and `seq19`; they are implemented as a 6 and a 19 digit zero padded decimal component (so the lexical `(effective_start_ns, reference_id)` order equals the numeric order), `B(x)` being base64url without padding. The observed fact roles (`change`, `qualifier_price`, `qualifier_volume`) carry `ob1:B(record_set_id)` like the roster (the contract fixes only the roster), the declared fact roles `bf1:B(population_id)`, the declared static population `x1:B(population_id)`. These identifiers are implementation-chosen; the amendment and I/O #611 must pin them. No per-slot `IntervalCoverage` entry names are used (coverage is the batch-level declaration the contract specifies).
4. **Coverage reading.** A role that declares incomplete coverage makes every one of its facts `governed_gap` (even a declared-unavailable VWAP row); a missing row of an incomplete role is `absent_input` and `governed_gap`; a complete role with a missing row is `absent_input`.
5. **Observed roster knowledge.** Roster-level `unknown_availability`/`future_knowledge` is assessed for every record with an event time before the cutoff, before the group filter (a literal reading of the contract); records at or after the cutoff never block.
6. **Strictness beyond the text.** A rational factor on a fact kind that carries none (everything except `ef3.member.vwap` and `ef3.adaptive.rate`), a price or factor on a state, roster or population kind, a fact row whose `session_id` is not the target session, a population row whose `text` is not the batch snapshot (as E) and an adaptive row whose instrument is not the result entity are refused. Fact roles of the declared producer must share one snapshot id (RB06); `source_id` is not compared.
7. **RB28.** The `factor_den <= 0` clause cannot be reached with `INVALID_SCHEMA`: the shared validator refuses a non-positive factor first with `UNSUPPORTED_ADJUSTMENT` (the RB10 shape); RB28 is exercised through a non-positive notional coefficient. RB08 can only be raised for a multi-stint population or the adaptive stream, as the contract states.
8. **Unknown contribution reasons.** When a direction class is unknown for a member, its volume input is also listed if unresolved (the union of the unresolved inputs); the contract fixtures never combine the two.
9. **Adaptive null rate with warm-up.** A null rate in scope is `null_field` with `expected` = in-scope rows even when fewer than W rows exist (no fixture combines them).
10. **Builders.** `evidence_limit` defaults to 0 although the contract says no defaults (as EF3-D and EF3-E). The result `entity` is caller supplied (an aggregate label for breadth; the observation instrument for adaptive).
11. **Whole-tree boundary check.** `tools/check_boundary.py` fails on the base commit at `ef1/_reference_close.py` (`import base64`); the `violations` policy applied to every file of `equity_features.ef3`, including the new modules, reports nothing.
12. The header-ledger amendment and the shared `CONTRACT.json` are not amended here.

## Author source validation

A standalone manual script (not committed, no test files added) expanded the compact fixture notation into canonical REFERENCE batches and compared every output cell (status, reasons, `expected`, `observed`, int64, bool, exact float bits for declared and observed, the contract tolerance and `+0.0` for adaptive) and every witness list (single-output runs under the fixture evidence limit) with the frozen contract. The author reports 49/49 declared, 20/20 observed and 30/30 adaptive result fixtures (1224 output cells, 778 witness lists), the exhaustive prefix property of AD06 for j = 0..6 (7/7) and 62/62 refusal fixtures (73 variants) matched, with no mismatch (author-reported, not independently confirmed here). Known-at and reconstruction availability give identical values, quality and evidence. A before/after snapshot (base commit versus this branch) of the core registry, the R17 result, describe and digest, the EF2 money-flow, momentum, channels and realized-variance catalogs and digests, the EF2 retracement discovery, the EF3-D relative, log volatility and realized-variance configs, discovery and results and the EF3-E mean, robust history and pace discovery and results was byte-identical. mypy strict is clean on all 20 `ef3` modules (author-reported).

## Cost

Author-observed on one machine, not a performance claim: 4096 declared members for all 16 outputs about 0.8 s; a 4096-observation adaptive stream with random rational rates about 2 s, a constant-rate stream about 0.1 s, and an adversarial stream of float-equal near ties (every comparison falls back to exact integers) about 13 s. Batch only; no incremental state.

See the [session breadth](../api/EF3_SESSION_BREADTH.md), [observed breadth](../api/EF3_OBSERVED_BREADTH.md) and [adaptive volume](../api/EF3_ADAPTIVE_VOLUME.md) APIs. No acquisition, source rights, installed, cross-layer, performance or release claim follows from this source result.

## Review notes (contract nits, for the EF3 shared amendment)

1. The implementation-chosen ids `member:<id>`, `seq:<n>`, the 6 and 19 digit `stint6`/`seq19` components and the observed fact-role grammar `ob1:B(record_set_id)` need pinning in the amendment and in EF3 I/O #611.
2. The evidence cap is result-wide, the witness boundary is `ordinary` and builders default `evidence_limit=0` (as EF3-D and EF3-E); limited fixtures were reproduced one output at a time.
3. RB28's non-positive `factor_den` clause is unreachable behind RB10 (the shared validator refuses first with `UNSUPPORTED_ADJUSTMENT`).
4. The extra refusals (fact `session_id`, adaptive instrument versus result entity, population `text` versus snapshot, rational factors on kinds that carry none, price or factors on state, roster and population kinds) are implementation additions, not contract text.
5. RULING NEEDED: in `_observed.py` (roster loop, about line 175) a roster row of another group, before the cutoff, with null or future `known_at` blocks a group-scoped result; the contract is ambiguous and no fixture covers it. Also: roles that no selected output needs are never validated, and the declared snapshot-id check includes the population batch (`source_id` is not compared).
6. Incomplete coverage with a missing row (`absent_input` and `governed_gap`) and a null rate with warm-up are not fixed by a fixture.
7. The roughly 13 s adversarial adaptive case, the other timings and the mypy strict result were author-observed only; the reviewer did not reproduce them (mypy was not installed there).
