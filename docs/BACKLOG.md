## Planning rules

Each numbered story below has exactly one release assignment and a concrete acceptance condition. Delivery state and actual ownership are in the live Project; new R4.1 implementation stories start Backlog. Release labels are planning milestones, not promises of published version numbers or dates. Estimates follow formula/scope decisions and the first implementation benchmark. Later releases remain visible but cannot bypass earlier gates. Public package publication is separate from internal artifact delivery.

Story completion follows the eight-stage lifecycle in PUBLIC_DEVELOPMENT.md and requires implementation or explicit decision evidence, required tests/documentation, a reviewed change, declared release delivery and post-release verification. Documentation is updated alongside every story. Test results must show what they establish; no source admission from file presence, no performance claim without measurements. A release requires every assigned story complete, dependencies satisfied and a recorded release acceptance checklist. Deferred scope must become a named later story rather than disappear.
