# I/O publication design v1 / no mathematical impact

Owning story [EQ123#280](https://github.com/atulsrivas1/equity-features/issues/280), E19 / R4.1. [Repository separation decision](IO_REPOSITORY_SEPARATION.md) remains the boundary authority. This decision records the [companion normative design](../IO_PUBLICATION_V1.md); separate final-head semantic review and actual publication are recorded on the canonical issue.

Retain canonical input/acquisition/result/schema/validation objects in equity-feature-contracts0.0.4a4. Companion interfaces depend inward and use existing objects instead of duplicating schemas. Freeze a closed, versioned ASCII JSON codec for complete FeatureResult trees, exact integer strings/finite binary64 hex/enum labels, preserved sequence order and canonical-constructor validation. SHA256 content uses domain-separated length-framed canonical results; a separate identity binds destination/generation/job/partition/canonical and calculation/input/config descriptors. Content changes under a reserved key conflict. Physical layout/compression, transient bounds and caller timestamps cannot silently alter logical result identity. Corrections explicitly create a new generation and preserve earlier receipts.

The first implementation receives bounded complete-result units; one FeatureResult is not row-fragment streamed in v1. Oversized units fail RESOURCE_LIMIT, and cumulative canonical bytes/cells/evidence/results are admitted before acceptance. This finite limit is an explicit design tradeoff, not a backend memory/throughput claim. Later row fragmentation requires a new protocol/fixture decision.

Begin/write/commit/abort/lookup/read separates staged visibility, uncertain commit and committed replay. Backends must qualify declared writer topology, visibility, persistence/retention, corruption checks and resource behavior; no universal filesystem atomicity or worker exactly-once guarantee. Source acquisition errors and data-admission semantics stay canonical; sink errors are separate. EQ123 delivers the reviewed specification and expected traces; EQ124 factories and EQ125 runtime types/codec/conformance remain their assigned implementations.

Mathematical impact: none. No formula, denominator, unit, initialization, coverage, cutoff, availability, feature/config/algorithm identity or supported39batch/23update-restore/22conditionalmerge inventory changes. Signed zero/null/exact UTCns/scaled integers/partial structured values and all evidence remain supplied facts, never inferred or repaired by storage. Package versions/dependency metadata and accepted R4 source/rights/privacy limitations are unchanged. Serialization admission does not certify numerical correctness, provider truth or private historical generation.

Revisit for new canonical schemas/fields, row-fragment streaming, changed digest/ordering/equality policies or capability/process/storage guarantees. Version changes require independent vectors, supported-combination evidence and a numbered story; silent automatic registry widening is prohibited.
