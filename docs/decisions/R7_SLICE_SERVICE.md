Decision for [EQ077 #87](https://github.com/atulsrivas1/equity-features/issues/87), before runtime implementation. [Pre-code plan/review disposition](../stories/EQ-077_PLAN.md) owns evidence. Optional equity-feature-service lives in the existing worker companion; calculations, existing workers and I/O dependencies are unchanged.

Closed1.0 raw slice fields cannot carry full native feature diagnostics. Freeze and explicitly advertise a separate optional1.1 feature_slice wrapping full original result payload plus immutable dataset/scope/selected pairs. Do not modify1.0, infer versions, fabricate calculation commands, drop native evidence or relabel aggregates to a narrower time window.1.1 schemas remain design evidence until actual codecs/native/installed/service tests and review pass.

Accepted DuckDB source identities are exact acquisition facts. Request_id/range/limits/config/file observations determine original-read2 identity; normalization adds retained-map/mapped content suffixes, while batch envelopes add separate chunk identities. The first service supports a server-approved exact bounded query per dataset registration, with its actual full canonical source binding/receipt frozen at explicit owned-source admission. Runtime repeats that same stable server-owned request and verifies full identity before selecting approved columns. All complete native rows/metadata/coverage stay intact; different scopes need separate admitted immutable query bindings. An HTTP correlation ID never enters the native acquisition request. Do not replace actual bindings with logical catalog IDs or strip suffixes. Actual parameterized source reads and failure/adversarial qualification are still required.

This is a deliberate small qualification profile: exact registered scopes, one instrument/session, at most100 rows, finite byte caps, explicit raw/derived/discover grants and owned synthetic identity/source fixtures. It does not implement pagination, dynamic range rebinding, jobs, deployment, provider/private rights, general sandboxing or cross-process durable quotas. R7 downstream stories retain their acceptance. Public deployment/identity/rights and paid/registry/stable operations remain separately gated.
