## Public in-memory contract

Frozen exact record types, concrete tuples/lists copied to tuples, exact built-in scalars; bool is not int. Reject lazy iterables, subclasses, duplicates, unknown fields/checks/versions and contradictory record shape with payload-free `DiagnosticsError`: invalid_schema, unsupported_version, inconsistent_binding, duplicate, limit_exceeded. Constructors preserve supplied identity; no sorting semantic rows or mutating source/results.

`DecisionContext(namespace, entity:EntityKey, availability:AvailabilitySpec)` uses an exact known_at-mode causal requested context with C<=E and K<=E. This is the requested simulation bound, not a clock reading. `DiagnosticPolicy(policy_id, mode, unknown_action)` requires explicit mode advisory/strict and unknown_action allow/deny; no hidden default that changes admission. `evaluate_diagnostics(context, policy, checks)` accepts a nonempty bounded tuple of the seven fixed check records below and returns `DiagnosticReport`. Every check has unique check_id and nonempty subject_id; also reject duplicate(kind,subject_id) requests, even with distinct check IDs. Different cited observations/scopes need distinct subject IDs. This prevents literal repeat-count inflation, not detection of malicious semantic aliases. A check names caller-declared selected/cited content, not verified actual consumption. Optional common `content:ContentFingerprint` is a supplied R9 content reference (null if absent), copied into the finding without claiming verification. Pure evaluation never fetches or authenticates it; EQ103 separately verifies content binding before projecting facts. A nonrequested class is recorded in `not_requested` and is never counted as passed.

`ReferenceDeclaration(namespace, entity:EntityKey, fact_kind, source:SourceBinding, observed, complete)` declares one homogeneous target-entity population of either universe_membership or sector_membership. It is not a second acquisition receipt. `observed` is nonnegative int64; complete is exact bool. Namespace/entity must match context; all source labels are bounded. For any complete membership conclusion the supplied facts must cover this entire declared population, with unique row_index covering exactly0..observed-1; aggregate source completeness alone does not prove that a projection contains every row. Partial projection remains unknown. EQ103 must verify the full raw population/content binding and homogeneous scope before projecting this declaration; a mixed source cannot be marked complete by retaining only selected rows. Absence is represented by null, never a fake empty snapshot.

## Finding precedence, counts and admission

Evaluate all directly visible conditions of a selected check. Preserve every distinct reason in fixed lexical order. A visible violation yields failed even if another prerequisite is unknown; preserve the unknown reasons too. Without a violation, missing required proof yields unknown; otherwise passed. Exact unsupported shape/identity conflicts abort with a typed error before findings. This prevents incomplete coverage from hiding a directly observed later-known active fact, while excluded future rows do not taint a governed population.

Closed reasons: market_bound, missing_market_fact; late_knowledge, missing_knowledge; market_cutoff_mismatch, knowledge_cutoff_mismatch, evaluation_mismatch, reconstruction_context, missing_context; future_effective_query, membership_absent, membership_scope_mismatch, ambiguous_membership, missing_reference, incomplete_reference, incomplete_projection, historical_proof_unknown, missing_membership_text; revision_mismatch, missing_revision_identity, missing_effective_start, outside_effective_interval; adjustment_mismatch, missing_adjustment; future_observation, stale_observation, missing_observation; missing_session. No free-form error/narrative or payload echo.

`CheckFinding(check_id, subject_id, kind, content, status, severity, reasons, assessed, unknown_prerequisites, age_ns)` is immutable. status passed/failed/unknown; severity info/error/warning respectively. `unknown_prerequisites` is the count of missing categories in the table below, not undisclosed records or reason strings. `assessed` means all required supplied comparison prerequisites are present: exactly unknown_prerequisites==0. A failed check can retain unknown prerequisites and assessedFalse while still exposing a visible violation; counts by status remain independent. age_ns is null except a nonfuture supplied freshness observation. Reasons are empty iff passed; partial assessment never becomes complete proof.

Visible comparisons run whenever their own operands are supplied; unknown categories do not suppress them. For membership only explicit complete/historical/full projection with zero active rows yields membership_absent. Partial observed10/completeTrue/facts[] yields incomplete_projection/unknown, never absence or pass. No-active rows in complete observed0 snapshot yield explicit absence failure; source completeness is still a declaration. Excluded future reference rows remain in the complete population but their knowledge does not taint active rows.

`DiagnosticReport(schema_version='1', context, policy, findings, requested_count, passed_count, failed_count, unknown_count, assessed_count, unknown_prerequisite_count, not_requested, admission, source_authenticated=False, historical_acquisition_verified=False)` reports exact reconciling counts. requested_count=passed+failed+unknown=len(findings); assessed_count=sum(f.assessed); unknown_prerequisite_count=sum(f.unknown_prerequisites). Findings preserve request order; not_requested is the lexical tuple of fixed kinds absent from requests. No aggregate leakage ratio or score is implemented in this release. Zero completed assessments never implies zero leakage: a directly visible violation still fails; missing proof without a visible violation yields unknown. Optional content references remain declared, not verified by this report.

Admission is separately `not_applied` in advisory mode; strict mode is denied if any finding failed or unknown_action=deny and any finding unknown, otherwise admitted. An admitted strict request with allow-unknown retains every unknown finding; it does not report universal safety. Policy cannot lower a finding's severity or change observed facts. A typed validation error produces no report/admission. Environment/original execution/source rights/content truth are not authenticated by diagnostics.

## Bounds and transport decision

Initial API is in-memory only. No diagnostic JSON decoder, generic serializer, filesystem, network, credential, clock, publication, resolver, ledger or executable import hook. The JSON file delivered by EQ101 is a test oracle, not an accepted transport format. There is no new diagnostic wire digest/canonicalization in this release; later transport must get its own schema and independent byte fixtures rather than reuse metadata hashes.

Maximum256 check requests; maximum4096 reference facts in aggregate; maximum1024 facts for one membership check; maximum32 distinct reasons per finding; identity strings128Unicode code points/512UTF8 bytes, nonblank/no controls/surrogates; maximum128 session intervals. Apply identity bounds to every nested SourceBinding/ReferenceFact.text/SessionSpec/ActionPolicy/PriceUnit label and exact supported nested versions, not just outer IDs; ContentFingerprint retains its accepted fixed64hex/domain/version and int64 byte-length schema. Exact int64 UTCns, nonnegative counts/tolerances; derived freshness difference bounded0..2^64-1. Count/string preflight precedes per-fact iteration; reject aggregate overflow before retaining a result graph. No truncation hides a finding: over-limit requests fail typed limit_exceeded. These are application work bounds, not whole-process memory/time or interruption guarantees. EQ102 must independently test each at/one-above limit and immutable source/result parity before acceptance.

Validate schema/IDs/allseven kinds, equality and nanosecond neighbors, reconstruction/policy mismatch, included/excluded membership revisions, absence/current-only/incomplete proof, adjustment/known policy differences, freshness extremes, reason precedence and advisory/strict unknown decisions. ## Partial-market reference clarification

Every supplied bound comparison remains visible when another operand is absent. A completed interval end101>C100 with unknown start fails market_bound and retains missing_market_fact/unknown_prerequisites1/assessedFalse. An ordinary observation atC fails even when session proof is absent. A supplied session that disables the selected closing-auction convention fails even if observation time is absent. No completed full assessment is needed to expose a directly visible violation. [The oracle](../stories/EQ-101_TRUTH_TABLE.json) adds these three independent controls after source review; the original35expected vectors remain unchanged, for38check vectors plus6admission aggregates.
