# Remote transport contract 1.0

[EQ076 #86](https://github.com/atulsrivas1/equity-features/issues/86), [PR357](https://github.com/atulsrivas1/equity-features/pull/357), [pre-code plan](../stories/EQ-076_PLAN.md). This freezes a data-only design for later R7 service/client/MCP implementation. It ships a [closed JSON Schema](../schemas/remote-v1.schema.json), owned [examples](../examples/remote/calculate.json), and an executable reference verifier. It does not ship a server, client, production codec, authentication, scheduling, dataset rights or external deployment. The accepted [access policy](REMOTE_ACCESS_POLICY.md) remains mandatory.

## Framing and exact values

Use UTF-8 `application/json`, one envelope per message, no BOM, duplicate object names, unpaired surrogate characters, NaN or infinity. The entire request is at most 16,384 bytes; a response/chunk at most 262,144 bytes. Count actual encoded bytes before parsing. Reject container depth above32 and more than10,000 parsed nodes including object keys; these defensive wire limits do not establish CPU/RSS isolation or shared service quotas. Only JSON is decoded; no pickle, uploaded state, Python object hooks chosen by the caller, callable, import or executable object deserialization. Record names are literal vocabulary labels and never import paths.

JSON's interoperable integer range is narrower than signed int64. This contract therefore uses decimal strings for integer data and exact bit strings for float64, with no float epoch conversion. This choice follows the interoperability concern in [RFC8259 sections4/6/8](https://www.rfc-editor.org/rfc/rfc8259); the stricter duplicate/Unicode rules are this contract's decisions. Structural vocabulary follows [JSON Schema Draft2020-12](https://json-schema.org/draft/2020-12/json-schema-validation). Both the schema and semantic rules below are required, since a structural pattern cannot establish integer bounds, finite bit patterns or cross-message identity.

| Value | Wire representation | Required semantics |
| --- | --- | --- |
| UTC nanoseconds, scaled-price coefficients, counts, ordering keys | Canonical base10 string, e.g. `"9007199254740993"` | Signed int64 `[-9223372036854775808,9223372036854775807]`; count roles additionally nonnegative. No `+`, exponent, whitespace, leading zeros, `-0` or non-ASCII digits. Times preserve ns and declared interval/C/K/E rules. |
| Nullable typed cell | JSON `null` | Unknown/unavailable remains distinct from integer zero, empty observations and an omitted field. Required null-capable fields must still be present. |
| int64 cell | `{"type":"int64","value":"1"}` | Exact bounded integer; JSON numeric1 and Boolean true are not integer substitutes. |
| float64 cell | `{"type":"float64","bits":"3ff0000000000000"}` | Exactly16 lowercase hex digits, IEEE754 binary64 network byte order. Reject exponent-all-ones NaN/infinity encodings. Preserve signed zero/subnormals; do not round-trip through decimal formatting. |
| decimal128 cell | `{"type":"decimal128","coefficient":"123","scale":2}` | Exact coefficient magnitude less than10^38 and scale integer[-38,38]; numeric value is coefficient times10^-scale. Native integer Decimal128 result coefficients encode with scale0; physical units/price-scale conventions stay in canonical metadata/config rather than being inferred from this tag. |
| String / Boolean | Tagged `string` / `bool` with `value` | Strings are data, not references to files or code; no coercion. |
| Structured cell / tuple | `record` with an approved `name` and tagged `fields`; `list` with ordered tagged `items` | Preserve all original fields, nested quality/evidence/timing/units, exact rational numerator/denominator and nulls. No dynamic class lookup or executable registration. A label is not native semantic validation. |

The permitted structured names cover current result cells and provenance companions: breadth counts/fractions, quote states/observations/durations/spreads, top-k trades, interval rows/tables, entity/evidence rows, source/coverage/unit/adjustment/scope/input bindings, availability and result metadata. They encode actual stored fields, not computed properties or screenshots. Native schema/type/precision/structured-diagnostic validators remain required at the actual service boundary; generic tagged records do not implement those equations or authenticate the facts. The reference verifies tag/dtype correspondence and selected identities, while downstream tests must prove complete native conversion, including all structured diagnostic exceptions.

## Envelopes and requests

Every envelope has exactly `schema="equity.remote"`, `version="1.0"`, `kind`, `request_id` and `payload`. Six closed kinds are `request`, `discovery`, `slice`, `job`, `result`, `error`. Extra fields reject. The request ID is an opaque bounded correlation label, not authority or an idempotency key; an error may carry null when no trustworthy ID could be parsed. Authentication and grants come from the server, never envelope fields.

| Request operation | Payload fields beyond `operation` | Interpretation |
| --- | --- | --- |
| discover | None | Only authorized metadata; response carries actual supported transport version, registry snapshot and approved feature/algorithm pairs. |
| slice | dataset, scope, columns, cursor | Exact admitted dataset revision/snapshot/mapping/source/input, instrument/session and half-open `[start_ns,end_ns)` bounds. Columns are approved logical names; cursor is opaque/null, never SQL/path/offset authority. |
| calculate | context, scope, idempotency_key, command_digest | Pin namespace, exact dataset, approved config ID/revision/schema/digest/algorithm, registry snapshot, math policy, selected feature/algorithm pairs and C/K/E/mode/reconstruction reason. |
| job_status / job_cancel | job_id | Opaque ID subject to current owner authorization. |
| result_read / artifact_read | result_id, cursor | Opaque admitted resource reference; actual scope/expiry/download enforcement is EQ079. |

Selecting a config reference does not upload or alter a ConfigSpec. The server must resolve its exact approved immutable object, verify its unchanged canonical digest and configuration/timing/session/unit compatibility, and deny missing or changed revisions. The native [version policy](../VERSIONING.md) is retained; this wire representation does not redefine ConfigSpec.to_json or its float.hex/SHA256 digest. Caller claims, hashes, IDs and successful schema parsing confer no rights. Server-approved dataset/component/column/config admission, filters, grants and cumulative quotas are later executed EQ077–080 requirements.

The calculation `command_digest` is SHA256 of the payload excluding only `command_digest` and `idempotency_key`, serialized using sorted object keys, compact separators, ASCII JSON escapes and no NaN, with array order preserved and no Unicode normalization. Values are restricted to the frozen wire schema. It is a distinct wire identity, not the canonical config digest or a worker receipt. Recompute it rather than trusting the caller. The server adds principal/grant/policy scope to idempotency accounting; repeated or altered keys cannot bypass current rights. Existing worker planning/approval/receipt identities must be bound independently, not replaced by this digest.

## Responses, provenance and failures

Slice responses carry exact dataset/scope, typed named columns, full canonical metadata and a nullable opaque next cursor. All columns in a slice chunk have equal lengths. Dataset scope and unit/sampling/coverage/known-at facts remain supplied facts; transport does not fabricate completeness. Per-chunk structural caps are not permission to exceed total job/result/transfer quotas.

Result responses echo the accepted calculation context and command digest, identify actual backend/version and full tagged ResultMetadata, and preserve typed FeatureColumn entities/values, quality and bounded evidence separately. `executed_features` identifies supported actually co-produced feature/algorithm pairs, distinct from requested pairs. Every requested pair must be included; every returned column must agree with its executed pair. Chunks may contain a subset of columns/rows, but their exact value/quality keys must match. Full-result assembly requires provenance/duplicate/completeness verification in EQ079/081/083, never silent concatenation or schema-based completeness inference. Cursors/content/expiry/artifact representations require separately versioned downstream schemas; this design does not claim downloadable artifacts are implemented.

Reference validation checks complete ResultMetadata field presence and agreement of namespace, config digest, C/K/E, math/schema and backend identities. Request/result comparison additionally checks request ID/context/command digest and target entities/session. Actual source/input/mapping/snapshot/unit/quality/evidence identities must survive full native admission and producer comparison downstream; successful reference validation alone cannot establish them. The owned count fixture pins a real native ConfigSpec digest/registry and reconstructs its complete metadata through an explicit test-only constructor allowlist.

Job state is independent of mathematical availability: queued, running, succeeded, failed, cancel_requested, cancelled, expired. Only succeeded carries a result ID; only failed carries a typed error. Cancellation request is not proof that durable publication was rolled back; expiry/revocation visibility and accepted receipt behavior stay governed by worker/access contracts. A successful job may produce unavailable mathematical cells; success never manufactures available quality.

Quality preserves every native status (`available`, `insufficient_history`, `missing_input`, `incomplete_coverage`, `not_applicable`), expected/observed counts and typed reasons. Available requires complete declared coverage and nonnull value; unavailable scalar cells are null with reasons. Structured diagnostic exceptions need the canonical validators. Errors preserve category and code: transport, authentication, authorization, quota, contract, internal. Contract errors retain the exact current ErrorCode vocabulary. Responses expose fixed codes and Boolean retryability, no free-text exception, payload, private path or secret. Retryability is advisory; idempotency/current rights/remaining budgets still apply. Internal errors never serialize Python exceptions or stack traces.

## Version and migration policy

Transport1.0, canonical schema1, math policyv1, feature algorithm versions, registry snapshot, config digest, dataset revisions and backend/package versions are independent identities. This design introduces no numerical/algorithm/package revision. Receivers accept only explicitly advertised exact supported wire versions; absent/unknown/future versions reject `transport/incompatible_version` before domain execution. Unknown fields reject even within a recognized version. A capability advertisement is itself subject to current authorization and actual implementation.

Freeze1.0 bytes/meanings on acceptance. A compatible optional representation addition requires a new explicitly advertised minor version and a separate schema; do not add it silently to this closed1.0 schema. Changed required fields, types, units, error/status meaning or identity rules require a major version. During migration maintain an explicit tested set of versions or reject unsupported ones; no automatic downgrade, inferred feature/math migration, checkpoint conversion or lossy fallback. New transport support must retain native math/config/data version admission and independent fixtures.

## Reproducible qualification and limits

From the repository root, install documentation tooling with `python -m pip install -r tools/requirements-transport.txt`, then run `python tools/verify_remote_transport.py`. The dedicated wire CI runs this on Windows/Linux; ordinary documentation/math/core checks remain required. Tool dependencies are outside calculation/worker/I/O packages. Seven frozen envelopes plus a trusted approved-config fixture cover exact large ns, original source/coverage/unit/adjustment identities, lossless values, error/quality/job distinctions and native config/metadata agreement.

Independent positive/negative tests include int64 extrema and2^53+1, adjacent ns, null versus0, signed-zero/subnormal/max-finite binary64, decimal128 bounds, noncanonical/overflow/numeric integers, nonfinite bits, duplicate keys/invalid UTF-8/BOM/surrogates, byte/depth caps, unknown fields/versions/direction, changed command/config/entity/algorithm identities, C/K/E/interval boundaries, quality key/coverage/null rules and job/error contradictions. Executed evidence belongs to [delivery](../stories/EQ-076_DELIVERY.md). This is design/reference qualification, not installed-client/service, native all-result codec, authentication, authorization race, physical retention, provider or deployed-host proof. Those remain their real downstream release gates.
