# Rolling endpoint proof population and window outputs

2026-10-21. Coordinator proposal for fresh independent review. This closes the evidence population for the existing rolling endpoint algorithm without adding records, fields, formulas, profiles or consumers. All earlier sealed inputs remain unchanged; no fixture freeze or implementation grant follows.

For `b64-rolling-BD1`, DirectionalObject.premiums and Evidence.eligibility.witnesses retain the full admitted session raw population needed to establish the strict positive endpoint r, in the existing stable event/admission order. EligibilityEvidence.raw_contracts/raw_trade_count, observed_positive counts, zero/unresolved identities and positive_complete describe that full session endpoint-proof population. They do not assert that every such root is in the resulting rolling interval M.

Once r and M are certified, the directional positive_eligible count Metrics, monetary folds, signs and Evidence.member_ids/member_revision_ids describe only known-positive members selected inside M. Those window count Metrics may therefore differ from the full-session observed-positive evidence counts. The actual session boundary and full capture make the endpoint-proof domain explicit; no raw-window count is fabricated or implicitly substituted. Existing consumers admit only CurrentActivityOp, so this does not widen their count basis.

Evidence.excluded_ids retains known-zero roots and full-session roots outside M with the actual raw execution/PremiumCore dependencies needed for their dispositions. A derived window exclusion does not invent an external eligibility Control. In particular a latest known-zero raw root remains in the full-session premium/witness proof even when it lies outside M and does not advance r. Actual necessary endpoint-proof knowledge still enters availability. If unknown premium or incomplete raw capture prevents certifying r, retain the already defined full-session envelope and labelled observed evidence; dependent window Metrics remain unavailable under the existing priority rules.

CurrentActivityOp, session directional and checked-integer directional evidence retain their existing population rules. Independent full-input cases must distinguish an excluded positive lower endpoint, an older positive root outside M, a later known-zero endpoint witness, unresolved endpoint membership and complete-empty envelopes before final review and freeze.
