# Proposed R26 portable raw mathematics — draft 3

2026-10-21. Source design for fresh independent review, not adopted/frozen/implemented or numerically qualified. Coordinator design direction selects these mathematics under existing EQ188/EQ189/EQ215 responsibilities. Existing 44-profile family, all its golden wire bytes and released R25 interfaces remain unchanged. This standalone proposed `option-flow-variants1` family requires new closed types, schemas and hash domains. No original-source equivalence, compiler/formatter parity, provider truth or release acceptance is claimed. This public-safe proposal uses symbolic policy operands and contains no private source identifiers, private presets or real data.

## 2. Values, numeric operations and deterministic admission

Every fact and result binds currency, underlying, contract, session, action/deliverable/definition basis, population, numeric/sign/temporal policy, and immutable identity. Quantity is a positive integer in contracts. Price is currency per payoff unit; positive multiplier is payoff units per contract; premium is currency. Ratios have unit ratio; MAD z has mad_z; durations/clocks are integer nanoseconds; civil DTE is days. No implicit multiplier, currency conversion, definition repair or corporate-action normalization.

`B64`: each finite IEEE754 binary64 operand/result is encoded as exactly sixteen lower-case hexadecimal digits in most-significant-bit order, preserving signed zero. Exponent-all-ones NaN/Inf is rejected. RN denotes rounding exactly one operation to binary64 nearest/ties-to-even, preserving subnormals with no FMA, extended retention, reassociation or flush-to-zero. Integer conversions use RN. Fold order is part of the policy/input identity. Every accumulator starts positive zero. Check finite after each arithmetic operation: nonfinite/overflow fails the whole request before any partial publication. Numeric zero comparisons equate signed zeros; wire bits retain them. Exact integer operations use explicit signed64 checked bounds where stated; these have a different failure contract from B64.

`Fixed_d(x)` converts the exact value of already B64 x into an ASCII fixed-point key with exactly d fractional decimal digits, nearest/ties-to-even, dot separator, no exponent/plus/grouping. Retain the minus sign for negative values rounding to zero, including negative zero. d is an explicit bounded nonnegative integer policy operand. This is formatting binary64, not rounding a decimal intention or quantizing the summed contribution. Locale/process decimal context is irrelevant. An exact integer price has supplied positive scale S in integer ticks per currency/payoff unit; its exact value is n/S and its key is n. No B64 round-trip substitutes for that key.

All d, epsilon e, finite sentinel F, MAD scale c, price scale S, short-DTE maximum Dmax, ages, window w, lateness L and bucket definitions are explicit identity-bound policy, without hidden defaults. Public schema/bounds for these symbols require boundary freeze; no implementation may guess a default. Source-specialization claims require separately admitted private evidence.

Deterministic stages: (1) bytes/UTF8/shape/closed field sets/types/duplicate keys; (2) finite/scalar/range/cardinality bounds; (3) identity/reference/revision graph and scope/units/order compatibility; (4) selected control/context clocks/cursors and capture coverage; (5) population completeness and feature readiness; (6) arithmetic then result coherence/canonical encoding. Structural errors fail the whole request before values/statuses. Within a stage use closed record field order, input array index, then lexical identity; never map iteration. Nonfinite input is scalar admission error; nonfinite intermediate is numeric failure. Unknown valid economics is typed unavailable/unknown, not a structural error. New closed error tokens/paths/class and limits must be independently frozen; the stage precedence here is normative mathematics, not permission to reuse or extend existing44 wire enums silently.

## 4. Pure premium recipes and derived-fact composition

B64 price recipe: take admitted positive finite price bits p, positive integer q and positive finite causal multiplier bits m; qf=RN(q), t=RN(p*qf), P=RN(t*m), with checks after each operation. For an integer raw price input, first nf=RN(n), sf=RN(S), p=RN(nf/sf), then that same product. Exact-price key retains n regardless of the B64 monetary calculation. p/q/m and every intermediate/definition provenance are bound. These profiles admit positive price/premium, matching their own raw activity route; original44 zero-price behavior remains unchanged.

Checked integer recipe: positive n,q,integer multiplier m; sequential checked products u=n*q, P_ticks=u*m within signed64. Definition eligibility, causal multiplier and scalar deliverable must be established before monetary availability. Invalid/missing/future/nonstandard definition or product overflow gives typed unavailable premium fact (with reason) and preserved raw input identity. Downstream integer group membership survives unavailable premium, while total premium becomes null/unavailable. It does not silently coerce to zero or use the B64 product. Some scalar-only products may require structural rejection of invalid raw operands; their closed distinction must be frozen.

Reducers can consume an independently qualified derived P fact with recipe/input hash, or a separately admitted genuine externally supplied monetary premium fact. No such external fact is presumed from an internal struct member. Both entry points retain units, causal basis and provenance. Adapter maps n/p/q/m/definition/receipt fields; calculation performs conversion/product when it affects feature mathematics. Prior baseline daily premium may be a qualified calculated aggregate with full population/formula provenance; it cannot be labelled a raw provider field without evidence.

## 5. Distinct signing and directional operations

Epsilon quote: finite p,b,h and e>0; p>0,b>0,h>=b required, otherwise unknown. Ordered branches p>=RN(h-e) =>+1; else p<=RN(b+e) =>-1; else z=RN(RN(b+h)/2), p>RN(z+e) =>+1, p<RN(z-e) =>-1, else0. Ask-first precedence applies to locked/narrow markets and overlapping epsilon zones. Missing/inadmissible context =>unknown with distinct reason, never fallback. Valid dead-band equality and invalid quotes are distinguishable. Select original causal quote/reference context at A and current price at K under the declared origin specialization.

Paired boundary: exact positive integer p and explicitly paired valid positive b<h quote, with original causal pairing/control at A. p<=b =>-1; p>=h =>+1; strictly inside =>0. Missing pairing, one-sided/locked/crossed/invalid quote =>0 with specific quality. An event-time-near quote is not proof of pairing. Excluded/unknown undefined provider sentinels must be mapped as typed missingness, not admitted as valid integer prices.

Float directional: initialize bullish B,bearish D,unknown U and independent call/put and ask/bid premiums at +0. Call/+ or put/- folds B=RN(B+P); put/+ or call/- folds D=RN(D+P); other sign folds U=RN(U+P). Net=RN(B-D); classified=RN(B+D); total=RN(RN(B+D)+U). Independent right/sign totals use their own folds, not reconstruction. Session profile order is admitted successful call ordinal. Rolling profile order is (event time,admission ordinal), equal-time arrival stable. Its selected event endpoint r is the maximum event instant in the admitted session state, bound by visible session population/control evidence, and positive supplied horizon h defines (r-h,r]; positive event times at/below r are admitted when r-h<=0. The source lower-cutoff comparison is active only when r-h>0. Checked signed timestamp subtraction uses an explicitly admitted signed cutoff intermediate; it cannot wrap. Source-compatible profile requires complete admitted state through r; an arbitrary requested emit endpoint is not r. This endpoint/profile is separate from the old44 half-open window and from parent-window exclusive or candidate inclusive rules. Neither is a binary64 signed contribution fold. Sign is a proxy, never proof of customer intent/dealer exposure.

Paired checked integer directional: the request explicitly declares positive event start and end with 0<start<end<=K. Reconstruct the unique active economic root set at selected K/cursors from the full immutable ledger, retaining each root event instant and stable root execution ID across economic replacements; cancellation removes a root, relocation requires cancel plus new root. Select start<=event_ns<end. Full capture/population evidence must cover this half-open interval and every expected root before a complete claim; K-hidden records cannot prove exclusion. Homogeneous output partition binds underlying, session, compatible capture population/scope-universe, currency, action/deliverable/definition basis,numeric and sign policy. Contract/right/strike/expiry may vary only where compatible within that declared underlying/basis group; no mixed incompatible or silently substituted population is admitted.

Validate full record identities and immutable revision graph before member filtering. Explicit adapter/idempotency normalization may collapse byte-identical duplicate immutable record ID/content with a receipt before unique canonical construction; same ID/different content fails. Typed snapshots themselves reject repeated identity entries. Select one current revision per root, then sort the selected roots by (immutable event_ns,stable root execution ID), including equal-time lexical-ID order; selected replacement revision IDs do not replace root order keys. Filter the stated interval from this ordered set, preserving its order. This matches the witnessed standalone ordered-then-half-open-filter rule for unique nonrevision executions, while K-ledger reconstruction is a new explicit specialization, not original correction-parity evidence. No caller-supplied arbitrary fold order, float rolling arrival tie or parent-window grouping rule substitutes.

Initialize signed-call,signed-put,ask,bid,unknown and selected nonnegative premium group totals at integer0. For each admitted member in that exact order: unavailable premium increments explicit unavailable count and does not inject zero into a complete monetary claim; otherwise use valid nonnegative signed64 P_ticks, perform selected nonnegative accumulator range checks, update ask/bid/unknown by side, then separate checked signed-call or signed-put sum of P_ticks*side; unknown signed contribution is0. If full source-compatible rollup fields are selected, precheck P addition against ALL ask,bid,unknown,per-contract,per-strike,per-expiry current totals in that fixed order before updating, then update their corresponding group totals after signed accumulator step. These conservative source checks are observable even for an accumulator the current side does not update; omitting them defines another profile. Counter arithmetic/bounds are separately closed and cannot wrap. A scalar-only signature that drops those source checks must explicitly identify itself as noncompatible; it is not the selected checked-product rollup profile. Final right-adjusted tide=checked(signed_call-signed_put). Intermediate signed accumulator and final subtraction overflow fail the whole rollup request; an earlier unavailable premium is instead retained as explicit premium coverage missingness and prevents a complete monetary result. No rearrangement to float B/D arithmetic or single signed fold. Cancellations and reconstruction must preserve each profile's explicit selected order and K/A dependencies, not assume original source revision parity.

## 6. Joint observed reference measures

For complete eligible economic population, J_i iff positive causal compatible spot/strike plus valid event-local civil date and expiry ordinal exist at A. d_i=expiry_ordinal-event_local_day_ordinal, days; z_i=RN(strike/spot). Short member J_i and 0<=d_i<=Dmax; OTM member J_i and ((call and z_i>1) or (put and 0<z_i<1)). Negative DTE can leave J and OTM valid; ATM false. Missing either spot or expiry suppresses both memberships. An exact rational comparison is not substituted for this B64 ratio boundary.

In admitted profile order fold T=sum P_i,Q=sum J_i P_i,D=sum short P_i,O=sum OTM P_i. Outputs RN(D/T),RN(O/T),RN(Q/T) plus unknown-reference count/premium/IDs and selected reference/absence evidence. Complete empty or nonempty zero total =>undefined/zero_denominator, with distinct population evidence. Incomplete economics =>unavailable before ratios. Unknown references remain in T and explicitly unknown; observed shares do not claim full-reference classification. No new all-reference joint output is selected. Timezone/civil mapping, Dmax, spot age and definition compatibility are explicit policy. Reference absence must be honestly observed/coverage-labelled and cannot be repaired using future A-hidden facts.

## 7. Baseline producers and finite consumers

Both pure producer routes accept canonical full-session observations with explicit contract/day eligibility, prior civil dates, dimensions and per-metric missingness. Preserve proven zero activity. Required volume/contracts, trade count/executions and premium/currency are finite>=0; NaN is never a portable missing marker. Optional reference/model metrics, if carried, use explicit missingness. Duplicate normalized contract/day fails. AsOf is a supplied civil-date exclusive boundary; same-date/future observations are excluded with known evidence and never counted as prior. Date cutoff alone does not establish known-at; every accepted prior fact must also be visible at K with compatible basis and certified prior-slot policy.

Producer key: scope(contract/underlying), canonical identity, right, PURE calculated DTE/moneyness buckets, minute/session interval and compatible economic basis. A bucket string alone is not an admitted producer. The following closed symbolic membership policy is part of the mathematical profile; source-specific threshold values remain private.

DTE helper takes integer d with operand provenance and a nonempty finite sequence of strictly increasing positive integer upper cutpoints u_1<...<u_k. Missing d or d<0 yields typed unknown bucket; d=0 selects the separate zero-DTE bucket. For d>0 choose the first j with d<=u_j, otherwise the overflow bucket above u_k. Thus positive bucket j is (0,u_1] for j1 or (u_(j-1),u_j] thereafter; zero is never in positive bucket1. Category names are policy-bound unique identities, not inferred numerical display labels. Strict producer admission requires d>=0 and known, so helper unknown does not silently enter a complete baseline series. A genuinely supplied unknown reference remains explicit producer unavailable/missing_reference, never a fabricated date or zero.

Moneyness helper takes finite positive B64 ratio v, valid call/put right and strictly increasing positive finite B64 distance upper cutpoints b_1<...<b_l. Missing/nonfinite/nonpositive v maps to typed unknown in this helper's input/missingness layer; direct NaN/Inf bits remain scalar admission errors under section2 and are never admitted finite data. Compute distance=abs(RN(v-1)) with IEEE absolute value removing a negative-zero sign. Select first j with distance<=b_j, else overflow distance category. First distance bucket is ATM and has NO ITM/OTM prefix even for v just above/below1. All remaining finite/overflow categories get OTM iff (call and v>1) or (put and v<1), otherwise ITM. Equality at every distance threshold goes to the lower/first-matching bucket. Equality v=1 belongs ATM. Positive subnormal v and near1 representable neighbors use these B64 rules, not exact-decimal distance. Unknown helper output has no directional prefix; invalid right is structural, not guessed ITM. Strict full-session producer rejects unknown/missing/nonpositive ratio before grouping, preserving absence/incomplete reference evidence rather than pooling unknown into a complete bucket. Optional helper APIs may return unknown without claiming producer acceptance.

DTE operand derivation is pure library civil arithmetic: d=expiry_civil_ordinal-event_local_civil_ordinal, with calendar/timezone version and causal supplied civil/expiry references bound. Ordinals are integers under one declared civil calendar; no duration-hours or implicit timezone arithmetic substitutes. Moneyness operand derivation is pure RN(strike/spot) from positive compatible B64 strike/spot and known causal definition/reference. For a historical daily observation those reference controls must be admissible at its declared immutable observation boundary A_day<=K, separately from K-selected economics. The operation and reference-selection profile must be identified, including missing/future status. A prederived d or v is allowed only as an independently qualified calculation fact with producer/formula/profile/input/reference hashes, units and A_day/K provenance. Adapter maps original fields and clocks; it cannot silently compute d,v,buckets or change pooling counts. Distinct external raw DTE/ratio inputs require genuine source-field evidence rather than a computed label presented as raw. Joint-reference route, when reused, must satisfy its own joint A references; independent-reference route must name its compatible producer. No source bitemporal parity is inferred.

Bucket outputs retain d/v/distance, chosen index/category, endpoint equality branch, right-adjustment and raw-or-derived provenance. Group counts and both pooled routes use exactly these calculated memberships. Different threshold profiles or unknown-reference dispositions cannot share a baseline key/provenance. Contract route has one activity vector per admitted contract/day. Underlying route is per-eligible-contract daily bucket mean, not full-chain total. For group count n:

- Divide-before-fold: sort by (civil date,canonical contract), divide each member x by RN(n), then add RN(x/RN(n)) from +0 in that canonical order.
- Fold-before-divide: accumulate each x from +0 in explicitly bound observation ordinal order, then RN(sum/RN(n)). This route is distinct; no equivalence claim to the preceding route. File/cache access merely supplies that ordinal and qualified facts.

All contract observations including explicit zeros determine n. Eligible but absent contract requires missingness/coverage evidence, not automatic denominator reduction. Generic legacy minute-observation aggregation, if used, must declare its per-day ordered folds and distinct key/window profile rather than masquerade as either full-session route. Core selected obligations here are both evidenced full-session routes and the common statistical primitive.

For finite nonnegative series v, sort ascending by numeric value. Define portable equal-zero tie order negative zero before positive zero, then stable slot identity for equal-bit values; this makes fixtures deterministic without asserting an original sort tie guarantee. All other equal numeric finite B64 values share bits. n=0: numeric primitive returns zero metric fields with Samples0; wrapper readiness is empty/insufficient, never complete ready baseline. For n>0 and explicit quantile probability p in [0,1]: x=RN(p*RN(n-1)); lo=floor(x),hi=ceil(x); q=RN(v_lo+RN(RN(v_hi-v_lo)*RN(x-RN(lo)))). No FMA or even-middle (low+high)/2 substitution. Median uses symbolic exact probability one-half; even case is low+(high-low)*half under that operation tree. Iterate sorted v to fold mean sum from+0 and compute deviations abs(RN(v_i-median)), mapping abs(-0) to+0. Sort deviations by same zero policy, then MAD=q(deviations,half). Mean=RN(sum/RN(n)) if requested. Other requested quantiles use same q; no private preset probability list is copied.

Retain per-day slot identities and each daily reduction provenance in outputs, not just sorted values. `observed_series` means only observed admitted days; absent day contributes no sample and quality states observed coverage. `certified_expected_slots` requires every declared eligible slot visible/complete; missing slot/metric =>unavailable/incomplete_baseline before numeric readiness. Explicit proven zero slot is real0. These modes are distinct and never claim each other's coverage. Complete baseline requires n>=explicit minimum plus all completeness/identity conditions for selected mode. Empty/insufficient/incomplete differ. A supplied operand API is optional; implementing it alone does not deliver this producer.

Finite consumers: supplied F>0,c>0. R(x,d;F)=F if d<=0,x>0; +0 if d<=0,x<=0; else RN(x/d). Z(x,m,a;c,F)=F if a<=0,x>m; +0 if a<=0,x<=m; else RN(RN(x-m)/RN(c*a)). Unit ratio and mad_z respectively. Output branch ordinary/finite_sentinel/nonpositive_baseline_zero. Missing/incomplete/unready baseline takes precedence over sentinel evaluation. Producer's nonnegative operands and the optional raw signed-operand helper are separate closed types; do not silently widen producer domains. Sentinel is an explicit finite convention, not an approximation proven equal to infinity. No private defaults selected.

## 8. Parent windows, repeated subsets and venue evidence

Partition key: captured population/scope-universe, underlying, contract, session, currency, action/deliverable/definition basis and numeric/sign policy, inferred side nonzero. Quote identity is not an implicit key. Positive admitted price/quantity; known ID duplicate normalization must occur with explicit idempotency receipt before unique snapshot, while conflicting duplicates fail. Within a lane sort (event_ns,stable ID); this sorting is membership order, not proof of causal quote order.

Parent membership_complete requires full prefix and exclusive M coverage. Repeated subset contains parent members sharing exact integer price, quantity not key, count>=2. Venue evidence contains unique admitted venues; missing venue is explicit coverage, not a fabricated venue. A multi-venue group needs >=2 known distinct venues. Kinds may overlap members; successive parents within a lane are disjoint.

Publish parent_anchor and subset_start separately. Source-backed selected finality uses subgroup first member g: final iff membership_complete and admitted frontier>=g+w+L, L>=0. Frontier-known-at and capture/exclusion control requirements in section3 apply; final output availability=max(member availability,selected frontier known_at,all necessary certificate/control dependencies), not just frontier event time. Pending retains complete observed-at-cut membership evidence where available but no promise late members cannot arrive; incomplete M yields unavailable full value with observed evidence and never final. Checked timestamps/products/sums cannot wrap. Invalid/unavailable member premium or checked nonnegative signed64 sum overflow gives premium null/unavailable with membership retained, rather than discarding group or publishing partial total.

## 9. Explicit-anchor inclusive-span candidate (VM2)

Anchor must be an admitted active positive-premium print with nonzero inferred side and explicit immutable ID. Homogeneous anchor partition fixes population, underlying, contract, session,currency,action/deliverable/definition basis,numeric and sign-policy identity. Compare records only inside that partition. Opposite-side records inside it are skipped, not a break; unrelated partitions are outside population and cannot extend/split the interval. Sort (event_ns,stable ID), find exact anchor index; include same-side records with index>=anchor, event<=asof and event-anchor_event<=w. Equal-time lower-ID records precede anchor and do not join. Source order used for arithmetic is this candidate order; no causal sign inference comes from lexical IDs.

Asof is an explicit K-visible common-clock control, not request K synonym. M=[anchor_event,min(asof,anchor_event+w)] inclusive; full same-time endpoints and anchor identity need capture coverage. Asof>=anchor_event required; otherwise incompatible anchor/control. `membership_complete` certifies this asof-bounded M only. `horizon_reached` states asof>=anchor_event+w; it is not a late-arrival finality claim. If horizon not reached, candidate is observed/pending asof evidence even if bounded M complete; never claim full span horizon complete. If M incomplete, monetary value unavailable/incomplete_capture with partial observed evidence. This primitive does not invent a finalization rule absent from its witness. Any later final sealed-span profile needs explicit additional controls/contract.

Return anchor, selected interval endpoint flags, asof/control known-at/cursor, member IDs/order, count, RN premium fold, latest event, distinct nonempty venue count/coverage, all-exact flag with unknown exactness explicit, membership_complete/horizon_reached and availability<=K. Valid anchor ensures at least one member; no zero candidate for an invalid anchor. Unknown venue/exactness does not erase monetary members. The primitive accepts one explicit anchor or an explicitly bounded list of anchors; it does not claim an original producer emits all overlapping candidates. First-qualifying premium/count screen and confirmed/approximate selection remain EQ207.

## 10. Three concentration families

Complete declared contract/session/currency/basis population and explicit arithmetic order are mandatory; no temporal clustering implicit. Exactly one key: (exact integer price,quantity); (Fixed_d(B64 price),quantity); or (quantity,Fixed_d(B64 premium)). d and S are symbolic identity-bound parameters. Values with equal displayed premium but differing quantity remain different third-family keys. Repeated window price subsets omit quantity and remain separate.

Fold unrounded positive supplied/qualified premium into T and each B_k from+0 in bound admission order. Compute each share RN(B_k/T) independently and maximum starting+0; do not replace with an alternative max-total/divide operation. All tied maximum keys sorted by canonical key bytes; preserve exact member order and bucket bits. For complete empty or admitted complete nonpositive-total population, C=+0 with distinct complete_empty/nonpositive_total branch; strict positive-premium route only has empty T0. If a profile admits zero contributions that extension must be explicit and compatible with recipe domain; no silent original44 domain reuse. Incomplete population =>unavailable before maximum. Output C unit ratio and T/B currency, key policy/order, all buckets/members/ties, latest event and known-at. Session call-order evidence is not automatically event-sorted; corrections require whole selected population reconstruction under explicit order. An old source timestamp field is not proof event_latest equals that field.
