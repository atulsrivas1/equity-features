## 2. Closed notation and scalar domains

Every declaration `T(fields...)` is a frozen slotted record with exactly those fields in declaration order. JSON uses objects with those exact keys; record names below are the codec names. `[]T` is an immutable tuple/JSON array, `?T` is explicit null or T. Tagged unions below use exactly their declared `kind` and fields; all other keys fail. No arbitrary map, subclass, callback, native float/Decimal, bool-as-int, object loader or extension registry is admitted.

`id`: ASCII `[A-Za-z0-9][A-Za-z0-9_.:/-]{0,127}`. `hash`: 64 lowercase hex. `text`: NFC Unicode scalar text, no Cc/Cf/Cs, 1..1024 UTF-8 bytes. `currency`: `[A-Z]{3}`. `u`: exact int 0..9223372036854775807; `i`: exact signed64 int; `pos`: u >0; `day`: int 1..3652059; `bool`: exact Boolean. Timestamps are u nanoseconds on the one explicit common clock. Checked signed64 timestamp intermediates may be negative; published instants cannot. Count/quantity/scale/price ticks are u, positive where stated. Price ticks and exact monetary totals use signed64 nonnegative bounds, never arbitrary big integers in published fields.

`bits`: exactly 16 lowercase hexadecimal ASCII digits, most significant byte first, finite IEEE754 binary64 only. Preserve every bit including negative zero. No JSON floating numeric tokens, decimal text coercion, NaN/Inf or implicit integer-to-bits conversion. `B64Number(kind:'b64',bits:bits)` and `I64Number(kind:'i64',integer:i)` are the only Number alternatives; unit is separately fixed by the containing metric. Signed zero numeric comparisons equate the zeros; canonical encoding preserves their bits. All finite arithmetic is per-operation nearest/ties-even, subnormals retained, no FMA/reassociation/extended retention/flush-to-zero. Nonfinite intermediates fail with the exception specified below unless the selected integer premium/group profile explicitly returns premium missingness.

Suggested hard limits, independently review before freeze: envelope 16777216 bytes, total recursive records 100000, depth 32, roots 4096, references/quotes each 8192, streams 128, scopes 128, operations 128, output objects 8192, prior slots 3660, contracts per scope 4096, quantiles 32, formatting digits 0..18. `Limits(wire_bytes:u,records:u,depth:u,roots:u,quotes:u,references:u,streams:u,scopes:u,operations:u,outputs:u,prior_slots:u,contracts:u,quantiles:u,format_digits:u)` accepts positive values no greater than these hard caps, except format_digits can be zero. Limits are admission policy, never mathematical defaults. Inputs have at most 19-digit integer strings; bounded allocation precedes integer parsing and record expansion. Full checkpoint plus suffix and repeated encoded publication fields share byte/record budgets; references count once as logical identities but encoded duplication counts every byte. No unsupported implementation resource margin may reject an otherwise admitted operation.

## 24. Explicit-root premium evidence and checkpoint preflight precedence

PremiumOp is an explicit nonempty sorted unique list of active regular root IDs, not a population aggregate. Empty root_ids fails invalid_scalar at `/request/operations/{o}/root_ids` before evaluation. For each successful root output Evidence.member_ids/revision_ids is that one selected root/revision, capture_complete **false** and context_complete **false**: neither full population capture nor a quote/reference signing context was requested or certified. Its actual original-A definition/absence evidence is still validated and retained; false here means no claimed population/context certificate, not a numerical prerequisite. sign/reference unknown/excluded ID arrays empty, eligibility null, bucket_domain_evidence empty. control_ids is exactly selected DefinitionUnavailable control if any, otherwise empty; an admitted supplied fact's own declared source controls are dependency provenance, not fictitious population proof.

PremiumOp row dependencies are exactly the generated proof input set from section23 plus the Binding descriptor of each actually consumed stamped source record (selected/original execution, definition/control, supplied fact when used). Include Scope and Policy with clock0 as stated; no unrequested capture certificate, quote, Reference composite or bucket/venue fact. ProducerProof input set itself excludes these additional Binding descriptors because its selected stamped record hashes already bind binding_id; Evidence adds the exact descriptors to expose rights/provenance. Include any actually consumed external supplied Core/source proof qualification identity through Request/admission provenance, not a fabricated economic knowledge timestamp. available_at is max of those actual source/table clocks. OperationReceipt joins these row dependencies, member IDs in root_ids order, no invented capture/control, and aggregates row statuses under section12; explicit-root available outputs can have available receipt with capture_complete false. No batch complete-empty inference is made from that flag.

Restore has an explicit checkpoint-first gate overriding ordinary later digest order where necessary, so two-defect fixtures are deterministic. CP0: validate the supplied evaluator cohort scalar and the checkpoint envelope/record byte/type/shape/scalar limits with the ordinary earliest parsing rules. CP1a: validate stored checkpoint history/prior Request closed identities/references/revision graph/cut completeness/policy/formula constraints (no numerical evaluation and no suffix merge). CP1b: verify internal hashes in checkpoint declaration order: history_sha256,prior_request_sha256,policy_sha256s in policy-ID order, then prior Request's producer_admission_sha256 against stored admission/nullness; mismatched stored digest is digest_mismatch at that exact checkpoint/internal Request field. Outer wire canonical/digest validation, when bytes are used, has already completed before a typed restore call. CP2: compare actual current evaluator cohort to checkpoint.evaluator_cohort_sha256; mismatch checkpoint_cut_mismatch at `/checkpoint/evaluator_cohort_sha256`. CP3: validate current supplied admission and monotonic extension of stored entries, then suffix/current Request shape/reference/temporal admission and immutable merge under existing rules; only afterward numerical evaluation and output construction. No suffix arithmetic or publication before these phases.

Thus a checkpoint history digest mismatch beats evaluator mismatch; coherent checkpoint with evaluator mismatch beats a malformed/missing-ancestor suffix discovered only in CP3. Earlier checkpoint parsing/identity/cut errors still beat its internal digest comparison. Current cohort mismatch is a restore identity gate, not an invented ordinary stage7 temporal condition. Stored prior admission self-coherence is checked against the checkpoint's own evaluator identity before CP2; comparison with the **current** externally verified evaluator is CP2. Worker input_invalid preserves exact underlying code/path, and failed checkpoint preflight never calls the sink. This order closes exception precedence only; it grants no checkpoint/fixture/runtime execution.
