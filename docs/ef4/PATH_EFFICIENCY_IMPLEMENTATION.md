# EF4 path efficiency and choppiness implementation

EQ-161 (#495) library layer: the pure `ef4.path_efficiency` producer (`path.choppiness_fraction`, `path.efficiency_ratio`, `path.log_efficiency_ratio`, `path.net_displacement`, `path.path_length`, `path.true_range_sum`, `path.window_range`) in `packages/intraday`. The frozen [contract](PATH_EFFICIENCY_CONTRACT_PROPOSAL.md) (version `ef4-path1`, decisions DP-E1 to DP-E17, rulings OQ-E1 to OQ-E5 and its coordinator freeze) governs; this slice implements it and redefines nothing. The sibling projections contract (EQ-172) is a separate library slice. The EF4 I/O mapping (#613), worker (#614) and release acceptance (EQ-163) layers remain separate.

## Structure and hosting

`packages/intraday/src/equity_features_intraday/`: `_path_config` (builder and closed decoder over the R17 context), `_path_registry` (own catalog, digest and capability check), `_path` (readiness, exact mathematics, Decimal120 logarithms, quality, evidence, dispatch). Public names carry the `_path_efficiency` suffix (`compute_path_efficiency`, `describe_path_efficiency`, `require_path_efficiency_capability`). The R17 context, BAR admission and governed grid are reused unchanged, and the R17 catalog is untouched, so `describe_intraday()` still lists exactly the eight accepted R17 IDs and its digest is unchanged (checked before and after: the catalog digests of R17, money flow, momentum, channels and realized variance are identical). The shared validators, the default registry and every EF1/EF2/EF3 output are unchanged; no package version is bumped. `tools/check_intraday_boundary.py` lists the three new internal modules and passes.

**Deviation from the contract hosting line.** The contract text names `packages/features` (EF4 module, namespace `ef4.*`). The producer reads the R17 `IntradayContext` and the R17 BAR admission, which live in `packages/intraday`, and `equity-features` does not depend on `equity-features-intraday`; hosting it next to `ef3.intraday_realized_variance` avoids a new package dependency and a duplicated admission. It therefore does not touch `equity_features/ef4/__init__.py`. The config namespace is still `ef4.path_efficiency` and the catalog is separate. Moving it is a mechanical follow-up if the owner prefers the other package.

## Configuration

`build_path_efficiency_config(context, policy_version, window, epoch_profile, evidence_limit, availability, adjustment, price_unit)` and `decode_path_efficiency_config` follow the realized-variance envelope (context bound by schema, SHA-256 and chunked transport; the decoder rebuilds the final envelope and refuses any difference). Nothing has a default. Every shape or range fault (missing, bool, float or text `window`; `window` outside 2..4096; unknown or missing `epoch_profile`, including `carry`; `evidence_limit` outside 0..10000; a missing `policy_version`; any surplus parameter) is `INVALID_CONFIG`; a well-formed unsupported label is `INCOMPATIBLE_VERSION`. `epoch_profile` fixes the R17 context mode: `session_reset` needs `reset`, `governed_history` needs `carry` (the supplied daily grid is one epoch from its anchor; no value crosses a session boundary).

## Mathematics and numeric policy

Prices are exact int64 coefficients; net displacement, path length, window range and the plain-sum true range (predecessor close mandatory for every one of the N bars, base close included in the range) are exact integer sums divided by `10^scale` once at publication. The efficiency ratio is an exact integer ratio (one correctly rounded float64 by Python integer true division). The log efficiency ratio and the choppiness fraction are Decimal120 logarithms of exact integer ratios (`ln(C_i / C_(i-1))`, `ln(TRS / WR)`), so ratios within 1e-14 of one keep their accuracy (fixtures PE27 and PE31); the choppiness is `ln(q) / ln(N)` and no clamp is applied (`1 <= q <= N` holds for every valid input). Exact zeros are decided on integers: equal closes, `TRS = WR`, a zero path or a zero range never go through a logarithm; `+0.0` is always positive. A monotone window returns exactly 1.0 for the log efficiency ratio because the sum of same-signed logarithms is exactly the net logarithm. `path = 0` gives `zero_denominator` for both ratios and `WR = 0` for the choppiness, while the operands stay available with value `+0.0`.

## Readiness, counts and evidence

Each slot is READY iff its row exists, the output's own fields are non-null, its coverage is complete and original `known_at <= K` (`== K` is known); the same rule applies in `known_at` and `reconstruction` modes. Causes: no row and no coverage `absent_input`; null `known_at` `unknown_availability`; `known_at > K` `future_knowledge`; null field `null_field`; declared incomplete coverage `governed_gap`; a coverage-proven empty slot (or zero volume) `no_eligible_observations`; a missing column `absent_input`; `t - N < anchor` `insufficient_history`. Precedence and status follow the contract table; every applicable reason is reported in lexical order. Expected is `N + 1`; observed is the READY slots among `max(a, t - N)..t` for the output's own closure (close group: closes `t-N..t`; range group: closes `t-N..t` plus high and low of `t-N+1..t`), so a close-only delivery keeps the four close outputs available while the three range outputs are `missing_input/absent_input` with observed 1 when the base close is READY (PE20). Evidence (available outputs only) lists the target, the base, then the interior ascending, as `slot:<index>` with boundary `completed_interval`, truncated to the result-wide `evidence_limit` in lexical feature-id order.

Refusal order follows the contract: shared `validate_batch` first (`DUPLICATE`, `INVALID_ORDER`, `BOUNDS`, OHLC `INVALID_SCHEMA`), then selection and capability (`UNKNOWN_FEATURE`, `UNSUPPORTED_CAPABILITY`), then the configuration (`INVALID_CONFIG`, `INCOMPATIBLE_VERSION`, `INVALID_UNIT`), then the R17 admission (`INVALID_UNIT`, `UNSUPPORTED_ADJUSTMENT`, `BOUNDS` for a forming bar, `INCONSISTENT_IDENTITY` for another session, instrument or an off-grid bound). Wire faults (float or oversized cells, ragged columns) are raised by the unchanged `CanonicalBatch` constructor. Coverage is always declared explicitly per slot by the author builders (a slot without a coverage entry is an absent slot).

## Rulings beyond the contract text, limits and open points

1. **Prefix fixtures (PE25).** The R17 context requires the target to be the final governed slot, so slots delivered after the target are not expressible; PE25 is run with the slots after its target dropped and is verified identical to PE04 (the contract's prefix equivalences PE04/PE25 and PE01/PE17 both hold).
2. **Window versus context bound.** The R17 context holds at most 4096 slots, so the largest window with a possible available result is 4095 (N+1 = 4096 slots); `window = 4096` is a valid config whose result is always `insufficient_history`. The 64-session context bound limits `governed_history` to 64 daily slots (N up to 63) per context when each daily slot is its own session as in the contract expansion.
3. **Close-only reasons beyond PE20.** For the range outputs of a close-only delivery the library reports every cause of every lost slot (for example a governed gap in the window in addition to the undelivered high and low). Status, counts and values equal the contract fixtures and PE20 is exact; the contract text fixes only the PE20 shape, and the author recompute harness reports only `absent_input` (plus the base cause) in the mixed case, which is the only difference seen in the random comparison. The wording could be tightened in an amendment.
4. **`governed_history` context mode.** The contract does not name the R17 mode of a daily epoch; `carry` is used because `reset` would force the anchor to the target session's first bar.
5. **Exact monotone log efficiency.** A window whose moves all go one way returns exactly 1.0 without evaluating logarithms (an exact identity, not a snap).

## Rulings to pin in the EF4 shared amendment

1. **governed_history cap.** The R17 context holds at most 64 sessions, so `governed_history` is capped at N <= 63 daily returns per context (one governed slot per session, enforced by the builder: a carry context with more slots than sessions is `INVALID_CONFIG`). No code split is made; the cap is a coordinator decision.
2. **Carry context mode.** `governed_history` requires the R17 `carry` mode context (anchor at the start of the supplied daily grid); `session_reset` requires `reset`.
3. **Hosting.** The producer lives in `packages/intraday` (OQ-E5 hosting reading), because it consumes the R17 context and admission; the config namespace stays `ef4.path_efficiency`.
4. **Close-only range outputs.** Every cause of every lost slot is reported (missing column, null in a delivered field, gap, knowledge); status and counts follow the contract.
5. **Refusal order within config.** Shape, range and unit faults (`INVALID_CONFIG`, `INVALID_UNIT`) precede the policy label (`INCOMPATIBLE_VERSION`); a missing price unit is `INVALID_UNIT` from both builder and decoder.

## Author source validation

A standalone manual script (not committed, no test files added) built canonical R17 inputs from the author fixture-expansion harness for all 31 result fixtures (203 outputs) under two bindings (instrument, session, namespace, calendar, grid ids and epoch time all differ; the second binding runs in `reconstruction` availability) and for all 39 refusal recipes under both bindings (the configuration recipes also through the builder), and compared value (per acceptance rule: bit-exact `exact_float64`, bit-exact `+0.0`, R17 tolerance), status, reasons, counts and witnesses: 31/31 result fixtures and 39/39 refusals matched under both bindings (author-reported; not independently confirmed here). 400 random cases (2800 output checks) matched the author's exact evaluator in value, status, counts and witnesses; the only differences are the close-only reason lists of note 3. Windows of 4095 and 4096 ran in about 0.6 s and 0.2 s for all seven outputs. A before/after check of `describe_intraday()` and the R17, money-flow, momentum, channels and realized-variance catalog digests was identical. `CONTRACT.json` is not amended here.
