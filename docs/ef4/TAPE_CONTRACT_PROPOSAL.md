# EF4 tape contract: rolling trade windows, tick-rule signed volume and notional-ranked largest prints - proposal

Prepared for EQ-158 [#492](https://github.com/atulsrivas1/equity-features/issues/492) (rolling trade windows and tick-rule signed volume) and EQ-162 [#496](https://github.com/atulsrivas1/equity-features/issues/496) (deterministic notional-ranked largest prints), for consumption by the EF4 I/O and worker tasks and release acceptance EQ-163. **This is a contract proposal, not accepted by any review; every convention (DP-*) and every former open question (OQ-*) below is an author decision pending independent review and owner review, and the document carries a proposed freeze statement for the coordinator.** It is contract preparation only: it admits no Ready state, implementation, numerical acceptance, release or performance claim. EQ-172 [#513](https://github.com/atulsrivas1/equity-features/issues/513) is specified by another contract and is not specified here.

Companion data: [TAPE_CONTRACT_PROPOSAL.json](TAPE_CONTRACT_PROPOSAL.json) holds the machine-readable producers, headers, roles, the seed fact schema, mathematics, quality table, 50 window, 25 top-K and 7 partition-merge result fixtures, 3 generated differential fixtures and 75 typed-refusal fixtures, each refusal with an executable construction recipe. Expected values are hand-derived: each headline value is typed by hand in the fixture definition as an exact fraction (or exact integer), and float64 results also carry `float.hex` and a per-output acceptance rule. An independent standard-library harness (`ef4g_fixture_expand.py`, kept with the reviewer notes and not part of the repository) expands every fixture under two unrelated identity bindings, recomputes every listed output with two independently written oracles that must agree, and executes every refusal recipe through a model of the documented admission order. The equity library was not imported, run or tested. Fixtures use compact notation (not canonical wire) and need expansion into canonical packets.

Read-only inputs: the accepted foundations `docs/features/INTRADAY_FOUNDATIONS.md` (governed observations, reset epoch, late corrections need a new revision and recalculation, exact arithmetic, typed overflow), `EF1_PATHS.md` and `EF1_OBSERVABLES.md` (original knowledge in both modes, ordered original trade identity, bounded deterministic evidence, no hidden truncation), `docs/features/SESSION_FORMULAS.md` (total trade order `(event_ns, order_key)`, notional `sum(p*q)` as a checked decimal128 coefficient, the size-ranked top-K key and its stable ties, partition merge of disjoint sets), `docs/api/SESSION_TRADES.md` and `SESSION_TOP_K.md` (the accepted trade admission, scope, coverage and the `TopKTrades` cell, which this contract reuses unchanged), `docs/EQUITY_DELIVERY_REPLAN.md` section EF4 (tick-sign carry and true per-identity order, deterministic notional ties, EQ-172 operands), the frozen shared boundary `docs/ef1/CONTRACT.json`, the merged EF3 contract `docs/ef3/ROBUST_PACE_CONTRACT_PROPOSAL.md` (structure, fixture rigor, reason precedence, numeric policy), and the shared validators and enums in `packages/contracts` (`validation.py`, `inputs.py`, `errors.py`, `results.py`) so that every refusal is constructible with existing codes. A policy label names the whole convention set of its version (window endpoints, order, sign rule, seed rule, eligibility, expiry, readiness closure, rounding for the window producer; notional, rank key, tie key, merge rule for the top-K). ## Inputs and roles

Value basis. Prices are positive int64 coefficients at `ConfigSpec.price_unit.scale` (0..18) in one currency and one adjustment basis; eligible sizes are positive int64 shares. Every comparison, sum and ranking runs on exact integers; the kernel never divides a price by `10^scale`. There is no acquisition, clock or I/O, no sorting and no deduplication. The trade batch must satisfy the accepted trade admission unchanged: one entity and session, `[open, C)` scope (an ordinary print at C is `BOUNDS`), strictly increasing `(event_ns, order_key)`, unique `event_id`, coverage whose observed count equals the delivered rows, positive eligible price and size, matching price unit, adjustment and eligibility policy.

| Role | Kind | Content |
| --- | --- | --- |
| `trades` | TRADE | the ordered prints of the target entity and session; the price and size columns may be absent, which makes the outputs that need them `absent_input` (an absent column is distinct from a null cell, which is a refusal for an eligible row); `known_at_ns` may be absent, which makes every row `unknown_availability` |
| `seed` | REFERENCE | exactly one `ef4.tick.seed` fact, delivered exactly when `seed_policy` is `supplied`; a `None` slot is an absent delivery; any fact when the policy is `none` is `INVALID_CONFIG` |

The `ef4.tick.seed` fact (JSON `reference_fact_schemas`): `instrument_id` target entity, `session_id` target session, `reference_id` `x1:B(seed_set_id)` supplied by the caller, `effective_start_ns` the event time of the last eligible print before the open (strictly before the open), `effective_end_ns` the open, `text` the carried sign `+`, `-` or `0`, `price` that print's price coefficient (positive, same price unit and adjustment as the trades), `factor_num` and `factor_den` null, `known_at_ns` the original knowledge, nullable. Because the fact carries a price, the seed batch needs a price unit and the shared compatibility checks apply between `trades` and `seed`. The seed is a caller-governed fact: v1 publishes no output that carries the end-of-session price and sign forward (OQ-3).

Parameters are never hardcoded (DP-P1). Entity, instrument, session, the seed `reference_id` and the role bindings come from `EntityKey`, `ConfigSpec`, the input bindings and the fact rows; there is no grid or bucket identifier in this contract. Fixtures carry only the placeholders `$ENTITY`, `$SESSION`, `$SEED_REF`, `$OTHER_ENTITY` and `$OTHER_SESSION`, which the expander binds, and every fixture must give identical results under two unrelated bindings.

## Exact mathematics

### Window and order (#492)

For cutoff C, window length W and session open O, the window is `[C - W, C)`: a print with `event_ns >= C - W` is inside, one with `event_ns < C - W` is expired (the prefix), and nothing at or after C exists in a valid batch (DP-T3). If `C - W < O` every output is `insufficient_history` (W05d): the window is never clipped to the open and never reaches into the prior session; `W = C - O` is the longest valid window (W05e). The total order is `(event_ns, order_key)` exactly as supplied; prints that share a nanosecond are processed one at a time in `order_key` order and are never netted (W02, W14; DP-T4).

### Tick sign with carry and seed (DP-T5 to DP-T7)

Let e_1 .. e_m be the eligible prints of the epoch (the whole session up to C) in order, with prices p_i. Let the reference be `(p_0, s_0)` = (seed price, seed sign) when a seed is supplied and "none" otherwise. Then `s_i = 0` if there is no reference; otherwise `s_i = +1` if `p_i > p_{i-1}`, `-1` if `p_i < p_{i-1}`, and `s_i = s_{i-1}` when the price is unchanged (the carry); the reference then becomes `(p_i, s_i)`. Without a seed the first print is 0 and an opening run of unchanged prints stays 0 until the first change (W03, W03b). A price change from the seed overrides the seed sign (W07c); a neutral seed sign behaves like no seed for the signs and differs only in counts and witnesses (W07d). Ineligible prints take no part in the chain, so the next print is compared with the last eligible print (W04). Expiry affects only the totals: the first in-window print inherits its sign from the expired prefix (W05, where t4 at exactly `C - W` carries `+` from t3 at `C - W - 1`).

### Totals and imbalance

With the in-window eligible prints S, sizes q, prices p and signs s: `count = |S|`, `volume = sum q`, `notional = sum p*q`, `up = sum q (s = +1)`, `down = sum q (s = -1)`, `neutral = sum q (s = 0)`, `net_volume = up - down`, `net_notional = sum s*p*q` (neutral contributes 0), and `imbalance = net_volume / volume` as an exact rational rounded once to float64 (half-even), null with `zero_denominator` when `volume = 0`; it is exactly +0.0 when `net_volume = 0` (W12b). Neutral volume stays in the denominator so it dilutes the ratio. Worked example (W01): prices 100, 101, 101, 100, 100, 100 with sizes 5, 3, 2, 4, 6, 1 give signs 0, +, +, -, -, - so up 5, down 11, neutral 5, net -6, notional 2105, net notional 505 - 1100 = -595, imbalance -2/7.

### Corrections and replay (DP-T11)

A correction is a new tape revision: the cancelled print is re-delivered ineligible and its replacement is a new row; the library never patches. Because a changed price flips every later carried sign, the corrected revision is recomputed from the seed over the whole epoch (W09b: replacing t2 at 101 by t2c at 99 flips t3 and t4 from down to up, imbalance -2/3 becomes +2/3). The earlier result stays immutable (W09a). A replacement that becomes known after K is `future_knowledge` (W09c). Batch and replay of the same revision are identical.

### Notional-ranked largest prints (#496)

`notional = price_coefficient * size`, an exact integer in currency/10^price_scale, at most `(2^63-1)^2 = 85070591730234615847396907784232501249 < 10^38`, so it always fits decimal128 (TK09). The rank key is `(-notional, event_ns, order_key, event_id)` with `event_id` compared by Unicode code point; equal notional is therefore broken by earlier time and `order_key`, never by size or price (TK02). The result holds `min(K, n)` rows (K explicit 1..10000, `evidence_limit` K..10000); a fully covered empty or all-ineligible population is an available empty table (TK04, TK05). Products above 2^53 are ranked exactly although float64 would collapse them (TK08). The rows keep the accepted `TopKTradeRow` fields (price coefficient and size); the notional is derived exactly by the consumer and no cell field is added (OQ-6). The size-ranked `session.trade.top_k` is a different ranking and is unchanged: TK01 shows K=3 notional ranking d, a, c against the unchanged size ranking e, b, d and no equivalence is claimed (DP-K4).

### Partition merge (DP-K6)

Compatible available partials (same policy_version, K, evidence_limit, price unit, adjustment, eligibility policy, entity, market cutoff and knowledge cutoff) are concatenated, sorted by the rank key and cut to K. For disjoint partitions of a canonical batch this equals the single pass (PM01, PM02, PM03), it does not depend on partition order and it is associative (PM04b, PM06); counts are summed. An unavailable partial makes the merged result unavailable with the union of reasons (PM05). The same `event_id` retained by two partials is `DUPLICATE`; disjointness of rows that were not retained cannot be proved from summaries and is certified by the caller. Partitions that collide on `(event_ns, order_key)` (for example one counter per venue) are separated by `event_id` (PM04); such a union is not a valid single canonical batch and has no single-pass equivalent.

## Pinned edge cases

- **Window boundary.** `C - W` is inside, `C - W - 1` is expired, C is outside the scope; `C - W < open` is `insufficient_history` for every output, including count (W05, W05b, W05c, W05d, W05e).
- **First print without a seed.** Sign 0; unchanged opening prints stay 0 (W03, W03b). With a seed the first print compares with the seed price (W07, W07c, W07d).
- **Same nanosecond.** Sequential by `order_key`, never netted (W02, W14); equal `(event_ns, order_key)` is `DUPLICATE`, decreasing is `INVALID_ORDER` (RF03, RF04).
- **Ineligible prints.** Not counted, not signed, not a reference; knowledge still applies to every delivered row (W04, W10i, TK10d).
- **Empty windows.** Totals and splits are 0, imbalance is `not_applicable/zero_denominator`, the only witness of a sign-based output is the seed (W11a to W11d).
- **Static closure.** Sign-based outputs depend on every row from the open to C even when the window is empty; count, volume and notional depend only on in-window rows (W10d, W10g).
- **Absent column versus null cell.** An undelivered price or size column is `absent_input` for the outputs that need it (W10a, W10b, TK12a); a null price or size on an eligible row is a refusal (RF07); an ineligible row is not an operand. TK12b: no eligible row means no column is needed.
- **Overflow.** Per selected output, never for the prefix (W13a, W13c, W13d, RF39, RF40, RF74).
- **Evidence limit.** The seed witness counts toward `evidence_limit` and is listed first, so a limit of 2 keeps the seed and one print (W22); a limit below the witness count cuts the tail (W21); 0 emits none (W22b).
- **Undelivered column with no eligible row.** Static closure for the window producer (W10j); the top-K needs a column only when an eligible row exists (TK12b).
- **R17 scale.** Epoch-scale nanoseconds above 2^53 and a one-hour window (W18), near-cancelling signed volume over a huge non-dyadic denominator (W20), reconstruction mode (W17, TK10e).
- **Top-K and auctions.** The top-K keeps the accepted auction admission (a closing-auction print at C = close is admissible when the session includes it, TK15); the window producer refuses auction inclusion (RF30).
- **K above n and K bounds.** K larger than the eligible count returns all (TK03); K = 10000 with `evidence_limit` 10000 is valid (TK14); K = 0, above 10000, a bool, or `evidence_limit` below K is `INVALID_CONFIG`.

## Availability, coverage, quality, evidence and refusals

Typed refusal precedes assessment, in this order (an output that is already unavailable never forms its sum, so it cannot raise `OVERFLOW`, W13e; fixtures isolate one fault, and coexisting faults follow this order, for merges the order of DP-K6): unsupported capability, unknown feature, configuration (parameter set, types and ranges, label, auction flags, seed role against policy), batch construction and admission in the order of the shared code (cell types and int64 range, batch kind, price unit, adjustment, scope policy, scope bounds, coverage count, entity and session, then per row duplicate `event_id`, order, bounds, positive eligible price and size), seed admission, and finally the arithmetic of the selected outputs (`OVERFLOW`). Quality uses existing `Status` and `Reason` only. All applicable reasons are retained in lexical order and the status follows the first applicable reason in the accepted precedence (DP-Q1): `absent_input`, `unknown_availability`, `future_knowledge`, `null_field`, `ineligible` (all `missing_input`), `governed_gap`, `future_market`, `partial_universe` (all `incomplete_coverage`), `insufficient_history`, `no_eligible_observations`, `empty_universe`, `zero_denominator` (the last three `not_applicable`), else `available`. A value is null exactly when the status is not available, and `available` implies `observed == expected`. Reachable here: `absent_input`, `unknown_availability`, `future_knowledge`, `governed_gap`, `insufficient_history` and `zero_denominator`; `null_field`, `ineligible`, `future_market`, `partial_universe`, `no_eligible_observations` and `empty_universe` are unreachable by design. Slot mapping: no batch or an undelivered required column or an absent seed is `absent_input`; a null `known_at` is `unknown_availability`; `known_at > K` is `future_knowledge` and `known_at == K` is available (W08d, TK10c); coverage with `complete` false or an expected count different from the delivered count is `governed_gap`. Mode rule (DP-M1): in `known_at` mode the knowledge reasons above are raised; in `reconstruction` mode (a separate config identity) the accepted `AvailabilitySpec.knowledge_reason` returns None, so none is raised and every delivered row is an operand (W17, TK10e).

Counts (DP-T12). Window outputs: `expected` is the declared coverage count, `observed` the delivered rows minus the rows not ready inside the output's row closure, 0 when a required column is not delivered, and 0 and 0 with no batch. Sign-based outputs: the closure is every row from the open to C, plus a seed slot (expected + 1, observed + 1 when ready) when the policy is `supplied`. Top-K: expected is the coverage count, observed the delivered rows minus unready rows, 0 when price or size is not delivered while eligible rows exist (this convention belongs to the new producers; the counts of the existing size-ranked output are unchanged). Merged: sums.

Evidence (available outputs only, unavailable outputs emit none). Window outputs: `seed:<reference_id>` first for sign-based outputs when the policy is `supplied`, then `trade:<event_id>` of the eligible in-window prints in canonical order, cut to `evidence_limit`; prefix prints are consumed but not listed and the cut is visible because `tape.window.count` exceeds the witness count (DP-T15). Top-K: the retained rows in rank order, boundary `closing_auction` for a print at `event_ns == C` with condition `closing_auction`, else `ordinary`; never more than `min(K, n) <= evidence_limit`, so there is no truncation.

Refusals (no `FeatureResult`) RF01 to RF75 in the JSON, 75 fixtures, each with `base`, `scenario`, an ordered `mutate` recipe and a `construction` sentence, and each saying whether an existing shared validator, constructor or the library raises it: `BOUNDS` 6, `DUPLICATE` 4, `INCOMPATIBLE_VERSION` 3, `INCONSISTENT_IDENTITY` 10, `INVALID_CONFIG` 22, `INVALID_ORDER` 2, `INVALID_SCHEMA` 9, `INVALID_UNIT` 3, `OVERFLOW` 5, `UNKNOWN_FEATURE` 3, `UNSUPPORTED_ADJUSTMENT` 3, `UNSUPPORTED_CAPABILITY` 5. Every code was checked against `packages/contracts/.../errors.py` and the shared validators; no new code or validator change is needed.

## Numeric policy and acceptance

Exact integer arithmetic throughout; the only float is `tape.tick.imbalance`, one correctly rounded (half-even) float64 of an exact rational (DP-R1, compatible with the R17 numeric error contract). int64 and decimal128 outputs and top-K rows are exact. Acceptance rule per fixture output (field `acceptance` in the JSON):

- `exact_float64`: dyadic rational with numerator below 2^53; the published float64 must equal the hex bit for bit (5 outputs).
- `exact_plus_zero`: exactly 0 from exact integer arithmetic; bit-exact +0.0, never -0.0 (4 outputs).
- `tolerance`: `abs(y - r) <= max(8 ulp(r), 1e-12 |r|)` with r the fixture float64, the R17 numeric error contract (`docs/api/INTRADAY.md`) (20 outputs, non-dyadic rationals such as -2/7 or -1/10).
- `exact_integer`: int64 and decimal128 coefficients (285 outputs); top-K and merge rows (price, size, notional) are exact integers by structure.

Total 314 classified scalar outputs. No documented exceptions. Bounds proof: every price is below 2^63, so once a summed volume is at most 2^63 - 1 every notional sum is below 2^126 = 8.507e37 < 10^38 and decimal128 cannot overflow; a selected volume sum above 2^63 - 1 is `OVERFLOW`, a typed failure and never a null or a wrap. Measurement of cost is not part of this contract; any speed claim belongs to the release baseline.

## Layer responsibilities

- **Library (#492, #496).** Admission of the supplied facts, window and closure selection, the tick chain, totals, ranking, merge, quality, evidence and every library refusal above; pure and deterministic with exact integer intermediates and one final float rounding. The two producers share only the trade admission.
- **EF4 I/O.** Maps ordered TRADE rows with `order_key`, `event_id`, eligibility and original `known_at`, the optional seed fact and the session scope exactly as supplied; maps results (int64, decimal128 coefficient, hex-exact float64, `TOP_K_TRADES` cell, status, reasons, counts, witnesses) unchanged; never sorts, deduplicates, nets, imputes, converts scale or currency, derives a seed, chooses a window or computes a sign or a rank.
- **EF4 worker.** Routes selected outputs with their row closure, keeps per-identity tape order and the sign carry, runs independent partitions and merges only declared compatible partials, executes one config per complete result, binds inputs and the config digest and persists the library result unchanged. Direct, adapter, worker and stored results must be identical, including refusal class; a stored `decimal128` coefficient and a stored int64 are never converted through float.

## Fixtures

The JSON `coverage_map` indexes the fixtures by tag, `reasons_reached` by reason, `prefix_equivalences` lists identical-result pairs and `parity_notes` lists the replay, prefix, merge and size-versus-notional relations. Reasons reached by at least one fixture: `absent_input` (TK12a, TK12c, W08a, W10a...), `future_knowledge` (PM05, TK10a, TK10d, W08c...), `governed_gap` (TK11, W10f, W10g), `insufficient_history` (W05d), `unknown_availability` (TK10b, W08b, W10d, W10g...), `zero_denominator` (W11a, W11b, W11c, W11d).

Required readback: a stored int64 or decimal128 is never converted through float, a stored float64 equals the float64 of the exact rational, and a stored top-K cell equals the library cell row for row.

## Author decisions: conventions (pending independent and owner review)

| Id | Convention (reason and rejected alternatives; the same text is in the JSON) |
| --- | --- |
| DP-T1 | Producer split: Two producers with separate identities, versions and policy labels: `ef4.tape_window_sign` (EQ-158: rolling window totals and tick-rule signed volume) and `ef4.trade_top_k_notional` (EQ-162: notional-ranked largest prints). Reason: EQ-162 depends only on EQ-136, is order independent and merges; EQ-158 is an ordered chain with carry and no merge. Different state, readiness and resource profiles must not be coupled. Alternatives rejected: one tape producer; fold the window totals into the existing session trade family. |
| DP-T2 | Evaluation point: One evaluation per result, at the config cutoff C. A window length W is a config parameter, so several windows are several configs and several results; rolling means successive cutoffs, each a separate result. Reason: The library has one cutoff and one result per config; vector or per-trade series outputs would need a new result shape and a new codec. Alternatives rejected: vector output over several window lengths; a value at every trade (series). |
| DP-T3 | Window endpoints: Time window `[C - W, C)`: start inclusive, end exclusive, W an int64 >= 1 with no default. A print at exactly `C - W` is inside, a print at `C - W - 1` is expired, a print at C is outside the session scope. If `C - W < open` every output is `insufficient_history` (no clipping to the open, no spill into the prior session). Reason: Same half-open convention as the accepted `[open, C)` scope. Clipping would silently change what W means; spilling would break the reset epoch. Alternatives rejected: closed end; clip to open; allow a window spanning the prior session. |
| DP-T4 | Order and same-timestamp ties: The total order is `(event_ns, order_key)` exactly as supplied (shared validator: equal key is DUPLICATE, decreasing is INVALID_ORDER). No sorting. Prints sharing a nanosecond are processed one at a time in `order_key` order; they are never netted per timestamp. Reason: `order_key` is the only certified sequence for equal timestamps; netting or re-sorting would discard it and change the carry. Alternatives rejected: net all prints at one timestamp; sort by price; process in arrival order. |
| DP-T5 | Sign rule and unchanged price: Tick rule against the previous eligible print p_prev: sign +1 if p > p_prev, -1 if p < p_prev, and when p == p_prev the sign of the previous print carries unchanged (the zero-uptick / zero-downtick convention). The first print of the chain compares with the seed price when a seed is supplied. Reason: Deterministic, quote free, needs only the tape, and a carry removes the ambiguity at unchanged prices. Alternatives rejected: unchanged price is always neutral (no carry); quote-based classification. |
| DP-T6 | Epoch and first print: Reset epoch: the chain starts at the session open. Without a seed the first eligible print has sign 0 and every following unchanged print stays 0 until the first price change. No sign is invented. Reason: A sign without a reference is unknowable; a proxy must not pretend otherwise. Alternatives rejected: assume up; discard the first print; carry the prior session implicitly. |
| DP-T7 | Seed and seed gaps: `seed_policy` is `none` or `supplied`, no default. Supplied means one `ef4.tick.seed` fact: the last eligible print before the open (price coefficient and carried sign `+`, `-` or `0`). A price change from the seed overrides the seed sign; a `0` seed sign behaves like no seed for the carry. Only tick-class outputs consume the seed. Seed gaps: role absent is `absent_input`, `known_at` null is `unknown_availability`, `known_at > K` is `future_knowledge`, each only on tick-class outputs while count, volume and notional stay available. A seed supplied while the policy is `none` is `INVALID_CONFIG`, never silently ignored. Reason: The prior-session boundary needs an explicit fact; ignoring a supplied seed would let two configs differ unnoticed. Alternatives rejected: implicit carry from the prior session; seed price only; a default seed. |
| DP-T8 | Ineligible prints: An ineligible print is not counted, not signed and never the reference price of the next print. Knowledge still applies to every delivered row, eligible or not, as in the existing session trade admission. Reason: Eligibility is normalized by the caller; an excluded print must not move the reference. Knowledge compatibility with the accepted `session.trade.*` admission avoids two behaviours for one tape. Alternatives rejected: knowledge only for eligible rows (the EF1 candidate rule). |
| DP-T9 | Expiry: Expiry removes a print from the window totals only. The sign chain is a property of the whole epoch tape: prints before `C - W` still set the reference and the carry for the first in-window print. Reason: A sign depends on the sequence, not on window membership (W05: the first in-window print inherits its sign from an expired print). Alternatives rejected: restart the chain at the window start. |
| DP-T10 | Outputs and proxy language: Nine outputs: `tape.window.count|volume|notional` and `tape.tick.up_volume|down_volume|neutral_volume|net_volume|net_notional|imbalance`. `net_volume = up - down`; `net_notional = sum(sign * price * size)` (neutral contributes 0); `imbalance = net_volume / window volume`, so neutral volume dilutes it, and it is `not_applicable/zero_denominator` when the window volume is 0. These are tick-rule proxies: the words buy, sell, aggressor, dealer or inventory never appear in an id, unit or description, the `condition` text is not consumed and no aggressor flag is read. Reason: The tick rule infers a price direction, not who initiated the trade; naming it otherwise would misrepresent it. Alternatives rejected: name the sums buy/sell volume; denominator up + down only. |
| DP-T11 | Corrections and replay: A correction is a new tape revision: the cancelled print is re-delivered as ineligible and the replacement is a new row (new event_id, same or later `(event_ns, order_key)`). The library never patches a result: the corrected tape is recomputed from the seed over the whole epoch, because a changed price flips every later carried sign (W09b). A replacement known after K is `future_knowledge` in `known_at` mode. Earlier results stay immutable. Batch and replay of the same revision are identical. Reason: Accepted foundation: late corrections require a new supplied revision and recalculation; earlier results are immutable. Alternatives rejected: incremental patching of signs; in-place revision of a stored result. |
| DP-T12 | Static per-output closure and counts: Readiness is static per output (not value dependent). count needs the in-window rows; volume adds the size column; notional adds the price column; the six sign-based outputs need every row from the open to C, both columns and the seed when policy is `supplied`; imbalance has the sign-based closure. Counts: `expected` = declared coverage count (+1 seed slot for sign-based outputs when supplied), `observed` = delivered rows minus rows not ready inside the output's closure (+1 when the seed is ready); a missing required column gives observed 0; no batch gives 0 and 0. Coverage with `complete` false or an expected count different from the delivered count is `governed_gap` for every output. A `known_at_ns` column that is not delivered makes every delivered row `unknown_availability` (W10h). The closure is static also for undelivered price or size columns: an undelivered column is `absent_input` for the outputs that need it even when no eligible row exists (W10j); the top-K differs by inheriting the accepted rule that a column is needed only when an eligible row exists (TK12b). Reason: Independent readiness with a static, reviewable closure; an unrelated missing operand never blocks a ready output (W08a, W10a, W10b, W10d). Alternatives rejected: value-dependent closure (an empty window would ignore the prefix). |
| DP-T13 | Auctions: Opening and closing auction inclusion in the session config must be false for this producer, otherwise `INVALID_CONFIG`. Reason: Auction prints are not continuous-trading ticks; a tick sign for them has no meaning. Alternatives rejected: include auctions as neutral prints. |
| DP-T14 | Precision and overflow: Count, volume and the three volume splits are checked int64; notional and net notional are exact integer coefficients in currency/10^price_scale published as decimal128; only `imbalance` is a float64, one correctly rounded value of the exact rational. Because every price is below 2^63 and a summed volume above 2^63 - 1 is refused first, a notional sum is below 2^126 (8.507e37) < 10^38: the decimal128 bound cannot overflow once the volume bound holds. `OVERFLOW` is a typed failure raised only by a selected output whose own sum exceeds int64 (RF39, RF40); prefix prints are never summed (W13c); a selection that does not need the sum does not fail (W13d); an output that is already unavailable (any reason, or `insufficient_history`) never forms its sum and so cannot raise `OVERFLOW` (W13e). Reason: Accepted rule: exact integer arithmetic, typed failure for unrepresentable sums, no wrap, one final rounding. Alternatives rejected: saturate; return null; wide accumulators. |
| DP-T15 | Evidence: Available outputs list the seed witness `seed:<reference_id>` first (sign-based outputs when the policy is `supplied`), then the in-window eligible prints `trade:<event_id>` in canonical order, cut to `evidence_limit` (0..10000); the seed witness counts toward the limit and is cut last (W22: limit 2 gives the seed and one print; W21, W22b). Prefix prints are consumed but not listed; the cut is visible because `tape.window.count` exceeds the witness count. Unavailable outputs emit none. Reason: Bounded evidence with a deterministic order; the prefix can be large and is bound through the input binding and coverage instead. Alternatives rejected: list the prefix; fail when over the limit. |
| DP-T16 | Capabilities: Batch and full replay only. Update, restore and merge are `UNSUPPORTED_CAPABILITY` for `ef4.tape_window_sign` in v1. The ordered-state parity required by the issue is expressed as a prefix property any later state API must meet (W16 against W05: signs of the prefix prints do not change when the cutoff advances) and as replay parity (W09b). Reason: An ordered chain with carry and expiry needs its own state schema and certificates; merging disjoint partitions needs boundary stitching. Both are separate amendments. Alternatives rejected: ship an update API now. |
| DP-K1 | Notional definition and units: `notional = price_coefficient * size`, an exact Python/int64 product in currency/10^price_scale (the unit string of `session.trade.notional`). It is never a float, is bounded by (2^63-1)^2 = 8.507e37 < 10^38 and so always fits decimal128 (TK09). No bar-derived or adjusted proxy. Reason: Ranking in exact integers removes float collapse above 2^53 (TK08). Alternatives rejected: float notional; Decimal120; notional from close * volume. |
| DP-K2 | Ranking key and stable ties: Rank key `(-notional, event_ns, order_key, event_id)`. Equal notional is broken by earlier time, then `order_key`, then `event_id` compared by Unicode code point (not locale), never by size or price. Inside one canonical batch `(event_ns, order_key)` is already unique, so `event_id` only matters between partitions that collide on it (PM04). Reason: Row-intrinsic, partition independent and total, so every partitioning merges to the same answer. Alternatives rejected: prefer larger size on equal notional; prefer lower price. |
| DP-K3 | K and bounds: `top_k` is an explicit int 1..10000 with no default; `evidence_limit` is an explicit int `top_k..10000`; the result holds `min(K, n)` rows (the existing bounds and checks). Reason: Reuses the accepted bounds so that both rankings are bounded identically. Alternatives rejected: a default K; K above 10000. |
| DP-K4 | Name and compatibility: New feature id `tape.top_k_notional` in the separate ef4 catalog, value type the existing `TOP_K_TRADES` cell unchanged (rows keep price and size; the notional is derived exactly by the consumer, no new cell field, no new ValueType, Arrow struct unchanged). The size-ranked `session.trade.top_k` is untouched, byte for byte; the two rankings are not equivalent and no equivalence is claimed (TK01 lists both). A consumer distinguishes them by feature id and config digest, not by the cell. Reason: A separate name keeps the accepted output and its registry digest immutable. Alternatives rejected: add a mode parameter to `session.trade.top_k`; add a notional field to the row. |
| DP-K5 | Eligibility and admission: Identical to the accepted `session.trade.top_k`: eligible prints, the same scope, auction choices (a closing-auction print at C=close is admissible when the session includes it, boundary label `closing_auction`, TK15), coverage, knowledge on every delivered row, positive eligible price and size. A fully covered empty or all-ineligible population is an available empty table (TK04, TK05). Reason: The notional ranking must differ from the size ranking only in the key. Alternatives rejected: exclude auctions. |
| DP-K6 | Partition merge: Merge takes available partials built with the same policy_version, K, evidence_limit, price unit, adjustment, eligibility policy, entity, market cutoff and knowledge cutoff, concatenates their rows, sorts by the rank key and keeps the first K. The result equals the single pass over the union when the union is a valid canonical batch (PM01, PM02, PM03), is independent of partition order and associative (PM04b, PM06). Counts are summed; an unavailable partial makes the merged result unavailable with the union of reasons (PM05). The same `event_id` retained in two partials is `DUPLICATE`; disjointness of non-retained rows is certified by the caller (summaries cannot prove it). Mismatches use INVALID_CONFIG, INVALID_UNIT, UNSUPPORTED_ADJUSTMENT, INCONSISTENT_IDENTITY or INCOMPATIBLE_VERSION (RF59 to RF69). Order when several faults coexist (each fixture has one): empty partition list (INVALID_CONFIG), policy_version (INCOMPATIBLE_VERSION), price unit (INVALID_UNIT), adjustment (UNSUPPORTED_ADJUSTMENT), eligibility policy (INVALID_CONFIG), K and evidence_limit (INVALID_CONFIG), entity, market cutoff and knowledge cutoff (INCONSISTENT_IDENTITY), then partial row order (INVALID_ORDER), then retained duplicates (DUPLICATE). Reason: top-K(union of per-partition top-K) equals the global top-K for a total row-intrinsic key. Alternatives rejected: merge unequal K by the smaller K; trust unchecked duplicates. |
| DP-K7 | Capabilities: Batch, conditional merge (above) and full replay. Update and restore are `UNSUPPORTED_CAPABILITY` in v1. Corrections need replay because a retained row that is cancelled is replaced by a row that the K-row state never kept (TK13b). Reason: A K-row state cannot repair itself after a cancel; update and restore need the certificate machinery of the incremental API and are a separate amendment. Alternatives rejected: claim update and restore parity with the size-ranked output now. |
| DP-Q1 | Reason precedence and reachable reasons: The accepted precedence list is reused unchanged. Reachable here: `absent_input`, `unknown_availability`, `future_knowledge`, `governed_gap`, `insufficient_history`, `zero_denominator`. Unreachable by design: `null_field` (a null eligible price or size is a refusal, an ineligible row is not an operand), `ineligible`, `future_market`, `partial_universe`, `no_eligible_observations`, `empty_universe`. All applicable reasons are kept in lexical order, the status follows the first applicable reason in the precedence, a value is null exactly when the status is not available, and `available` implies `observed == expected`. Reason: One status vocabulary across EF2, EF3 and EF4. Alternatives rejected: new reasons. |
| DP-R1 | Numeric acceptance: The EF3 per-output classes: `exact_float64`, `exact_plus_zero`, `tolerance` (R17 contract) and `exact_integer` (all int64 and decimal128 outputs). Reason: Same policy, no documented exceptions. Alternatives rejected: per-fixture ad hoc tolerances. |
| DP-P1 | No hardcoded identities: Entity, instrument, session, role binding, seed reference and any grid or population id come from the typed `EntityKey`, `ConfigSpec`, input bindings and fact rows, never from a kernel constant. Fixtures carry only the placeholders `$ENTITY`, `$SESSION`, `$SEED_REF`, `$OTHER_ENTITY`, `$OTHER_SESSION`; the harness binds two unrelated sets and requires identical results. Role slot names (`trades`, `seed`) are the contract's closed vocabulary; the seed `reference_id` is the caller's `x1:B(seed_set_id)`. Reason: Parameterisation is part of the contract so that adapters, workers and sinks cannot diverge. Alternatives rejected: default identities in fixtures or kernels. |
| DP-M1 | Knowledge modes: In `known_at` mode a delivered row (or seed) with null `known_at` is `unknown_availability` and one with `known_at > K` is `future_knowledge` (`known_at == K` is available). In `reconstruction` mode (a separate config identity) the accepted `AvailabilitySpec.knowledge_reason` returns None, so no knowledge reason is raised and every delivered row is an operand whatever its `known_at` (W17, TK10e); the original `known_at` stays in the input binding. The EF1/EF3 wording that knowledge is enforced in both modes is deliberately not carried over to EF4. Reason: Follow the accepted availability spec instead of restating a different rule. Alternatives rejected: enforce knowledge in reconstruction mode too. |
| DP-H1 | Hosting: Both producers live in `packages/features` (EF4 module, config namespace `ef4.*`) with a separate catalog; `describe_intraday()`, the core session registry and their digests are unchanged; no package version bump. Reason: Same precedent as EF3; the accepted session registry digest stays immutable. Alternatives rejected: register in the core session registry. |

| Id | Ruling |
