# EF4 quote dynamics and VWAP path implementation

[EQ-159 #493](https://github.com/atulsrivas1/equity-features/issues/493) and [EQ-160 #494](https://github.com/atulsrivas1/equity-features/issues/494) library layer: the pure `ef4.quote_dynamics` (9 `quote.*` outputs) and `ef4.vwap_path` (7 `vwap.*` outputs) producers in `packages/features` (module `equity_features.ef4`, a new sibling of `equity_features.ef3`). The frozen [contract](QUOTE_VWAP_CONTRACT_PROPOSAL.md) (versions `ef4-quote-dynamics-v1` / `ef4-vwap-path-v1`, policy labels `ef4-quote1` / `ef4-vwap1`, merged in #703) is implemented as written; this is a library source result only. No I/O mapping, worker, header-ledger amendment, installed or release claim follows from it.

## Structure

`packages/features/src/equity_features/ef4/`: `_common` (closed reference-fact admission, the interval bounds fact, the declared-coverage reading, knowledge reasons, quality, evidence and result assembly), `_quote` (config, observation classification, the 9 outputs), `_vwap` (config, trade and bar series, the cumulative path and the 7 outputs), `_definitions` (own discovery, `ef4_definitions`) and `_dispatch` (`compute_ef4`, routed by config identity). It reuses the EF3 helpers `fail`, `label` and `_robust_common` (`check_entity`, `check_reference_id`, `columns_of`, `first_status`, `ordered`) by import and adds no edit to any EF3, EF2, EF1 or R17 file. The discovery is its own catalog: `describe_intraday` and `intraday_catalog_digest()` are unchanged (digest `e7dcd5fb...ab02d86` on the base commit and on this branch).

## Public surface

For each producer: `build_quote_dynamics_config` / `build_vwap_path_config` (explicit keyword parameters, none defaulted, including `evidence_limit`; the target `SessionSpec`, availability, adjustment and a mandatory `PriceUnit`), `decode_*_config` (closed envelope, byte-identical rebuild) and `compute_quote_dynamics(batches, config, *, entity, features)` / `compute_vwap_path(...)`. The role slots are fixed and nullable except `bounds`: quote `(bounds, quotes)`, VWAP `(bounds, grid, trades, bars, proof)`. `compute_ef4` routes by config identity, `ef4_definitions(config)` describes the executable output set of one config and `require_ef4_capability` refuses update, restore and merge. No entity, instrument, session, role, snapshot, grid or series identifier is fixed anywhere: they are call parameters (`entity`, the batches, `grid_version`, `series_policy_id`).

## Mathematics and numeric policy

Observations, spreads, midpoints, microprices, cumulative notional and volume, extrema, comparisons, ties and the OLS sums all run on exact integers and `Fraction`s; the price coefficient is divided by `10^scale` only when a value is published, and each published float64 is one correctly rounded `int / int` (an exact zero is `+0.0`; a value outside binary64 is `OVERFLOW`). The OLS slope is `10^9 (n Sxw - Sx Sw) / (n Sxx - Sx^2) / 10^scale` on the raw nanosecond axis with exact sums, so the epoch-scale and near-cancellation fixtures (V39, V40) need no centering. Counts are int64.

## Admission, refusal order, readiness, counts and evidence

The call is refused by the first applicable tier of the contract: T1 config (policy label, then selected feature, then the closed parameters), the shared batch constructors, T3 the shared `validate_batch` per delivered batch with the market cutoff (references first: bounds, grid, proof, then quotes, trades, bars), then T4 the library checks (fact kind and grammar, unit scale, basis, namespace, sampling, identity, interval membership, grid, alignment, proof, notional) with existing error codes only. Assessment follows only when nothing is refused: knowledge uses the original `known_at` (null is `unknown_availability`, after K is `future_knowledge`, K itself is known) in every availability mode; every applicable reason is reported in lexical order and the status follows the first applicable reason of the contract precedence; `expected` and `observed` follow the contract counts (an unready bounds, anchor, proof or grid-edge fact gives observed 0; `insufficient_history` is expected 2, observed 1). Each output has its own readiness (`quote.sampled.*` and the change counts do not read sizes; `vwap.path.point_count` reads volumes only). Evidence rows are `quote:<event_id>`, `trade:<event_id>` and `bar:<start_ns>:<end_ns>` (boundary `completed_interval` for bars) in the contract order; the bounds, grid and proof facts are bound to the result but consume no witness budget.

## Notes, gaps and contract nits (recorded, nothing redefined)

1. **Evidence limit is result-wide**, as in EF3: the shared `FeatureResult` bounds the total evidence rows by `evidence_limit`; a single-output selection reproduces each fixture witness list and a joint selection truncates in lexical output order. Witness boundary is `ordinary` for quotes and trades (the shared validator admits `completed_interval` only for BAR and DAILY).
2. **Coverage reading.** The contract says the declared `IntervalCoverage` travels with the batch. The library reads, for the quote and trade batches, an `IntervalCoverage` entry exactly equal to `[S, E)` (at most one; its observed count must equal the delivered rows), and otherwise the aggregate `Coverage`: complete is complete, incomplete with a known `expected` is incomplete, and incomplete with `expected` null (the usual "no declaration") is undeclared. Zero rows with no declaration or an undelivered role are `absent_input`; undeclared coverage with rows is read as complete (no fixture; the fixture harness does the same). For bars, a per-slot entry must equal a grid slot: no row with an entry is `governed_gap`, no row without one is `absent_input`, and a delivered row whose entry is incomplete is `governed_gap` (not in a fixture).
3. **Unpinned absences.** A bar or prepared source with the grid or the bars batch undelivered is `absent_input` with expected 0 and observed 0 (as the trade source without trades); a `None` or empty bounds role is a refusal (`INCONSISTENT_IDENTITY`, RQ24). When the quotes or trades are absent the other readiness reasons (an unready bounds fact, `future_market`) are not combined with `absent_input`, as in the contract harness.
4. **Strictness beyond the text** (existing codes, no fixture affected): a role the series source does not read (grid or proof with the trade source, trades or proof with a bar source, trades with the prepared source) is `INCONSISTENT_IDENTITY`; a proof fact whose bounds differ from `[S, E)`; reference ids must follow the closed `x1:B(...)` grammar; reference facts carry null price and factor columns, `ef4.window.edge` a null end and the bounds and proof facts an end; fact instrument and session must equal the entity and config session; the batch namespace must equal the target session namespace; a quote or trade batch with an interval entry other than `[S, E)`; an edge's `reference_id` index is not compared with its position.
5. **Builders.** `evidence_limit` has no default (the contract: no defaults); the other keyword defaults of the builders are `None` only so that a missing value raises `INVALID_CONFIG`. The config envelope does not refuse a market cutoff before the session open (EF3's does); the contract states no such refusal.
6. **Null fields on the trade source.** The shared validator refuses an eligible trade with a null price or size, so `null_field` is unreachable there; the library still maps a null defensively. An ineligible trade is never read, including its price, size and knowledge.
7. **No row cap.** The contract states no bound on rows or slots; cost is linear in rows with exact rational sums (see the cost note).
8. **Boundary and typing.** `tools/check_boundary.py` fails on the base commit at `ef1/_reference_close.py` (`import base64`); the `violations` policy applied to every file of `equity_features.ef4` reports nothing. mypy was not installed in the author environment; the code is annotated for strict mode but a mypy run is not claimed.
9. The header-ledger amendment, the shared `CONTRACT.json`, the three reference fact kinds and the new `pairs` / `points` unit strings are not amended here; the contract defers them to the sibling amendment.

## Author source validation

Manual scripts (kept outside the repository; no unit tests were added, by owner policy) expanded the compact fixture notation of the frozen contract into canonical batches with the unmodified fixture-expansion harness (`build_model`, `apply_ops`) and compared the library with the contract values per each output's acceptance rule (exact integer, bit-exact float64 hex, bit-exact `+0.0`, or the 8 ulp / 1e-12 tolerance), the status, reasons, expected and observed counts, and every witness list (single-output runs under the fixture evidence limit). All 69 result fixtures matched (30 quote and 39 VWAP, 507 selected outputs), and all 80 refusal recipes (36 quote and 44 VWAP) raise the stated error code (10 of them at batch construction or capability selection, before the library call, as the contract tier model says). The run was repeated with three id sets (default ids; a second set that also uses interval-coverage entries, priced reference columns and coherent OHLC columns; and seeded random ids) with identical results. A differential run of 1000 seeded random fixtures per id set (400 quote, 600 VWAP) against the independent stdlib recompute harness (about 7000 output cells per set) found no mismatch.

## Cost

Author-observed on one machine, not a performance claim: 4096 trades with all seven outputs about 0.1 s per call and 4096 quotes with all nine outputs about 0.06 s (the exact OLS sums dominate the trade source); 1024 rows about 0.015 s. Batch only; no incremental state.

See the [quote dynamics](../api/EF4_QUOTE_DYNAMICS.md) and [VWAP path](../api/EF4_VWAP_PATH.md) APIs. No acquisition, source rights, installed, cross-layer, performance or release claim follows from this source result.
