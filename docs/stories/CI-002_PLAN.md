## Effective workflow and dependency contract

One `.github/workflows/qualification.yml` runs on every push and pull_request, without path filters. `scope` checks out the exact GitHub SHA with full history and runs the accepted classifier against the actual event file/context. Its only job output is `record`, one compact JSON object with the existing closed ci-scope.v1 schema. Invalid input retains the classifier's nonzero exit; an empty, malformed or invalid record cannot qualify. The scope artifact contains the original exact UTF8 classification JSON.

`docs` calls the same-commit local documentation workflow unconditionally and keeps every existing check. Sixteen literal package roots call the same-commit reusable leaf paths listed in CI-002_CONTRACT.json. Each requires scope success and a valid FULL record. No caller-selected workflow or shell interpolation of event/needs data is permitted. Existing seventeen leaves replace push/pull_request with workflow_call. Evaluation also retains its original workflow_dispatch, study_id input and exact qualify/study predicates; this release does not select or execute an evaluation study.

Root permissions are contents:read/actions:read, the ceiling needed by existing quickstart qualification; each existing leaf keeps its narrower permissions. No branch-protection/account change, new dependency, package API/math/version change, concurrency cancellation shortcut or removed qualification operation.

The terminal job is the unique required `check`, with `always()` and the exact eighteen logical dependencies in the JSON contract. `ci_gate.py` validates the entire needs object: exact keys; each value has only result/outputs; scope.outputs has only record; other outputs are empty. Scope and docs must succeed. The scope record must equal a fresh classification of the actual event and committed checkout, with strict types (bool is not int), closed keys and no duplicate JSON keys. FULL requires all sixteen successes. DOCS requires all sixteen expected skipped results, which remain NOT QUALIFIED package work. Missing/extra/unknown/cancelled/failed/unexpectedly skipped or unexpectedly executed dependencies fail the gate. No continue-on-error or synthetic PASS fallback.

Pass `toJSON(needs)` as environment data. `ci_provenance.py` recomputes source classification, invokes the gate and emits a policy sidecar only after successful validation. Any exception produces a fixed rejected error record where possible and a nonzero exit. Upload failure/missing files also fail the job. A successful gate procedure is not its own final workflow acceptance.
