# EQ123 pre-implementation contract freeze

Canonical [issue280](https://github.com/atulsrivas1/equity-features/issues/280), E19 / R4.1, 5 provisional complexity points. EQ121 is verified Done; sequential EQ122 acceptance is [recorded](https://github.com/atulsrivas1/equity-features/issues/279#issuecomment-6029211426). One active story. [Architecture](../IO_WORKER_ARCHITECTURE.md) and [test strategy](../R4_1_TEST_STRATEGY.md) govern the work.

Deliver a normative companion I/O specification and independently hand-worked protocol/serialization vectors before runtime implementation. Existing canonical source acquisition types remain in equity-feature-contracts0.0.4a4. Companion source APIs reuse them; source and sink interfaces remain separate. EQ124 implements factories and EQ125 implements typed publication lifecycle/serialization/conformance. This design story does not claim a running sink or introduce a second canonical result schema.

Freeze exact version admission, destination/generation/job/partition and calculation/input/config identities, supersession, logical content SHA256 versus storage-byte hashes, complete values/quality/metadata/evidence membership and bounded sequential chunking. Specify closed safe scalar/record encoding preserving float64 signed zero, int64 UTCns, decimal128 integers, nulls and structured values. No executable deserialization or filesystem-dependent logical digest. Canonical constructors remain the validation authority.

Specify begin/write/commit/abort/lookup state and evidence for same-content replay, different-content conflict, partial/crash/lost-response behavior, pre/postcommit cancellation, reader visibility and bounded resource limits. Capability matrix distinguishes requirements from backend-qualified guarantees. Stable errors separate incompatible versions/configuration, conflict, corruption, retryable transport, uncertain commitment, cancellation and unsupported capabilities.

Independent fixtures: manually expected traces for empty versus missing/unavailable scalar results, signed zero/int64 boundaries, one changed evidence field, same key/content replay, changed content under same key, partial failure with no receipt, lost commit response then lookup, cancellation around commit and incompatible schema rejected before writes. Documentation reviewer checks these outcomes against the normative rules; runtime EQ125 must execute them from installed artifacts. Review dependency/schema ownership with unchanged package/source/archive evidence; no irrelevant numerical changes or performance claim.

Release gates: separate final-head semantic review, scope/link/UTF8/whitespace and existing applicable native CI, current successful-main source/artifact readback and unchanged package equality, canonical lifecycle/evidence reconciliation. Normative specification, capability/error tables, no-impact mathematical decision, cross-repository links and continuity are part of this story. No R5 workers, provider implementations, source-store mutation, registry publication or stable tags.
