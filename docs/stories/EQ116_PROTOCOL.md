# EQ116 closed local export protocol

This pre-code specification supplements the [implementation plan](EQ116_IMPLEMENTATION_PLAN.md) and [full independent oracles](EQ116_ORACLES.json). It is an outer example protocol, not a new package or remote transport. The review found that status-only strict diagnostic expectations and prose-only export shapes were insufficient; the full report projections and shapes below resolve that design gap subject to renewed separate review. No product execution is claimed.

## Encoding and owned file layout

JSON is ASCII, sorted keys, no insignificant whitespace, no nonfinite numbers, no duplicate keys, no trailing data and no extra keys at any object depth. One LF terminates each outer JSON file; digests include that LF. Public package payloads retain their original canonical encoding, without an added LF. JSON integers are exact integers, never booleans or floating approximations. All digest values are lowercase 64-hex SHA256; lengths/counts are nonnegative exact integers. Every ID/enum/schema must be one of the literal selections below. Wrong type, additional/missing key, unexpected file, unknown version or failed binding refuses the entire read; no fallback or partial success. A trusted local root may contain only directories P01 through P08, each containing these eight regular files:

| File | Contents and logical cap |
| --- | --- |
| `bundle.zip` | Original public bundles format, stored ZIP, at most1MiB/16members/256KiB uncompressed |
| `plain-log.json` | Eight shared-fact records, or the deliberate seven-record P06 prefix, at most32KiB |
| `events.json` | Array of original public canonical event objects, at most128KiB total/16KiB per event |
| `ledger.sqlite` | Actual owned public ledger store; SQLite physical bytes explicitly outside logical payload caps |
| `terminals.json` | Both independently prepared original eight-record/event terminals, at most16KiB |
| `reports.json` | Full strict diagnostic, original advisory diagnostic and explanation payloads, at most64KiB combined; strict16KiB/explanation32KiB/advisory16KiB |
| `observations.json` | Shared producer/assessment observations before export mutation, at most16KiB |
| `completion.json` | Closed manifest for seven files above, at most16KiB |

ZIP members are contained bytes, not additional outer files. No per-arm copies or hidden payload files are written; both readers receive identical shared artifacts and independently written arm records. The file-count bound includes SQLite, while its physical size and transient journals/caches are not counted as logical payload bytes. The sum of all other seven outer file lengths is at most1MiB per case/eightMiB across eight cases. Completion requires the whole eight-case directory/file map; no ninth root index is added. Completion files are last, after payload writes, ledger close and renames return; failure leaves an incomplete root. There is no power-loss atomicity, physical storage/node limit or no-follow containment claim.

## Shared facts and plain-log records

Each plain-log record has exactly `schema`, `case_id`, `sequence`, `kind`, `facts`. Schema is `eq116.plain.v1`; case_id is P01–P08; sequence is1–8, contiguous and ordered. The eight kinds and exact fact keys are:

| Sequence/kind | Exact fact keys and values |
| --- | --- |
| 1/request | `request_key`:case_id, `objective`:`inspect supplied trade count`, `narrative`:case oracle string, `context`:complete demo/A/S availability200/210/210 |
| 2/model | `provider`,`model`,`version`,`identity_state`:synthetic/fixture-model/v1/declared, or all null and not_supplied for P08 |
| 3/calculation_call | `request_sequence`:1, `tool`:`compute_trades`, `version`:`0.0.4a4`, `configuration`:complete configuration fingerprint, `input`:complete same-case batch fingerprint |
| 4/calculation_result | `call_sequence`:3, `outcome`:`succeeded`, `output`:complete result fingerprint, `payload`:complete public canonical result bytes as ASCII text |
| 5/diagnostic_call | `request_sequence`:1, `tool`:`evaluate_diagnostics`, `version`:`0.1.0a1`, `input`:same batch fingerprint, `policy`:literal strict policy |
| 6/diagnostic_result | `call_sequence`:5, `outcome`:`succeeded`, `report`:full strict report projection |
| 7/feature_read | `result_sequence`:4, `configuration`,`input`,`output`:same full fingerprints, `receipt`:original canonical receipt ASCII text, `feature_ids`:[session.trade.count], `context`:same availability |
| 8/decision | `request_sequence`:1, `feature_read_sequences`:[7], `action`:case DEFER/REJECT, `reason_code`:unchanged assessment reason |

Fingerprint objects have exactly domain/digest/byte_length/schema_version/canonicalization/algorithm, using public fingerprint values and exact same-case raw canonical bytes. Plain-record context has exactly namespace/entity/availability as in strict-report oracle. Public event DecisionContext instead has exactly namespace/session_id/availability: demo/S and the identical full availability. Compare namespace, event session_id against diagnostic entity.session_id, and every availability field; A remains explicitly bound by diagnostic entity, original result entities and receipt/explanation. Do not pass EntityKey to the event context or erase A from diagnostic/result checks. Plain records are independently constructed from shared facts, never by decoding or projecting verified events. Known fixed call names/versions and original references are checked, not trusted merely because supplied. Full result, receipt, diagnostics, explanation and narrative are equally available to both arms via shared files. A complete baseline terminal digest plus expected count detects a changed or missing suffix without requiring event-chain machinery.

## Evidence events and independently retained terminals

Events use unchanged public EventRecord codec/schema. Chain ID is `pilot:P01` through `pilot:P08`; event IDs are `P01:e1` through `P01:e8` (case substituted), actor is software `eq116-pilot`, occurred/recorded time declarations have all three fields null. Sequence/kind corresponds to the table: request/model/tool_call/tool_result/tool_call/tool_result/feature_read/decision. Request key/objective, model declaration, public call argument fingerprints, result/receipt payload identities, full context and action/reason match shared facts exactly. Call argument sets are retained_complete, with configuration/input digest strings for calculation and input digest/policy_id for diagnostics; lexical argument-name order is fixed. Result4 payload is TOOL_RESULT canonical result; result6 payload is DIAGNOSTIC_REPORT strict projection bytes; feature-read receipt is EXECUTION_RECEIPT. All are retained_complete with exact raw digest/full/retained lengths. FeatureRead inputs contain exactly trades/trades and the same batch fingerprint. All references bind actual original earlier event IDs, kind, sequence and digest; no ref reconstruction from a truncated store.

`terminals.json` has exactly schema=`eq116.terminals.v1`, case_id, expected_count=8, ledger and ordinary_log. Ledger has exactly chain_id/sequence/head_hash from the eight public event bytes prepared before SQLite append. Ordinary_log has exactly record_count=8/byte_length/digest of the original complete plain JSON array including LF. Both are retained before the P06 deliberate prefix selection, separately from their stores. They are author-controlled comparison anchors, not third-party authentication. The independently frozen semantic expectations plus public event/ledger independent verification constrain event bytes; no production writer is used to generate mathematical expected results. Repeated writer-generated hashes alone are insufficient semantic validation.

P06 appends/writes only the first seven events/records and retains both original eight terminals. Public verification must report internally consistent prefix with not_covered ledger anchor; the baseline terminal comparison also fails coverage. No nonexistent decision8 is reported as observed in the retained prefix. The pre-export producer observation may record the original decision separately and must label that scope.

## Reports, observations and completion

`reports.json` has exactly schema=`eq116.reports.v1`, case_id, strict, advisory, explanation. Strict is the complete clean/future report literal in ORACLES, including all three check IDs/subject IDs/full same-case batch fingerprints, findings, counts, not_requested, policy/context and false authentication flags. This is an explicit field projection of the actual public report. It is not MCP diagnostic wire; no synthetic association field is added. Advisory/explanation are the unchanged canonical public/example report bytes as ASCII strings, generated from the actual checked producer. Advisory remains not_applied and never substitutes for the strict report.

`observations.json` has exactly schema=`eq116.producer.v1`, case_id, narrative, model_state, narrative_status, decision, reason_code, input_retained, initial_calculator_calls=1, initial_diagnostic_calls=1, strict_admission, source_authenticated=false, execution_verified=false. Values match the case oracle and unchanged assessment; input_retained is false onlyP05. It describes pre-mutation production, including P07 original execution, and is never evidence of successful post-corruption parsing. Diagnostics see all three original rows before P05 omission. Replay reader observations are returned on stdout, not written into completed exports.

Each stdout observation has exactly schema=`eq116.reader.v1`, case_id, arm, form, load, consistency, anchor, retention, narrative_status, decision, model_state, strict_admission, replay_status, calculator_calls, source_authenticated=false, execution_verified=false. Arm is ordinary_log/evidence_ledger; form is wheel-light/wheel-compute/sdist-light/sdist-compute. Load is verified/integrity_mismatch. For successful load: consistency=verified, ledger anchor is matched_terminal/not_covered and plain anchor uses the same coverage words; retention and narrative/decision/model/strict fields match actual checked content. For P07 integrity refusal all those seven post-load fields are null, replay_status=refused_before_calculator and calculator_calls=0. A refused read returns a typed observation only for this deliberate case; any other refusal fails qualification. Separate independent expectations, not the completed observation file, determine expected reader outcomes.

`completion.json` has exactly schema=`eq116.complete.v1`, case_id, files. Files is an object with exactly the other seven literal filenames, each value exactly bytes/digest. The whole logical bound is checked before completion. Readers verify filename map/length/digest before deserializing. P07's intentional bundle corruption is reflected in the outer completion digest, so the expected refusal specifically reaches the stale internal bundle manifest rather than stopping at an unrelated outer mismatch. P05's public manifest remains valid with a reference-only input. No reader repairs either condition, substitutes absent content, retries a mutation or overwrites a completed export.
