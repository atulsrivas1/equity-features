# EQ106 exact proposed event contract

This is proposed data/schema design, not implemented API or Ready approval. It will accompany the EQ106 story after governance publication. Package `equity-feature-agent-evidence`, import `equity_feature_agent_evidence`, experimental0.1.0a1, Python3.12, Apache-2.0. Exact dependencies: contracts0.0.4a4 and evidence0.1.0a2. Existing pure packages have no outward import to it. Ledger persistence/global indexes/chain storage belong to EQ107; no database, clock/environment, files, network, model, credential, source/sink or scheduling operation here.

## Scalars, bounds and errors

All records frozen; exact own/accepted record types, exact builtin scalars/enums, concrete list/tuple sequence inputs checked before copying to tuples. Subclasses, bool-as-int and generic Mapping/iterators are unsupported. Chain IDs and event IDs use exactly one colon: namespace matches `[A-Za-z][A-Za-z0-9_.-]{0,62}`, name matches `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`, total<=128ASCIIbytes. Additional colons/whitespace are forbidden. This grammar does not apply to request_key, actor labels, source input IDs or ordinary labels. Ordinary labels are nonempty/non-whitespace strings <=256codepoints and1024UTF8bytes, preserving exact Unicode without normalization, no U+0000–001F/U+007F–009F or surrogates. Argument names are `[a-z][a-z0-9_]{0,63}`. Argument text may be empty/whitespace but obeys the same size/control/surrogate bounds.

Timestamp fields are exact signedint64. Sequence is positive<=INT64_MAX; counts/byte lengths/uncertainty are exact0..INT64_MAX. Max16argument entries,16references/read targets,16input fingerprints,32feature IDs,64retained context events. Maxevent16384encodedASCIIbytes,12opencontainers,4096lexicalnodes; each key token counts. Construction has bounded fixed shapes/collections/strings before projecting; encode enforces aggregate nodes/depth/bytes. Decode checks bytes<=16384 and ASCII, iterative lexical limits and <=20character integer tokens before JSON parsing. These are application limits, not physical quotas or deadlines.

Closed AgentEvidenceError codes: invalid_schema, unsupported_version, duplicate, limit_exceeded, invalid_reference, inconsistent_reference, inconsistent_content. Fixed messages only, no payload echo or original exception context. JSON/domain/shape/type failure is invalid_schema; complete root with unsupported schema/canonicalization is unsupported_version. Extra/duplicate keys, floats/nonfinite constants, malformed tokens, BOM/trailing newline/whitespace/noncanonical representation refuse. Unsupported subject tags are invalid_schema. Invalid accepted nested evidence/contracts normalize to fixed agent errors outside exception handling so __context__ remainsNone.

## Public value records

ActorDeclaration(actor_id:label|None, kind:ActorKind): human/software/system/unknown. Unknown kind requiresNone ID; other kinds may lack supplied identity. This never authenticates an actor.

TimeDeclaration(at_ns:int64|None, clock_source:label|None, uncertainty_ns:nonnegative|None). Source/uncertainty require time. Occurred and recorded declarations are separate; neither reads a clock or imposes ordering. Their wire keys are at_ns,clock_source,uncertainty_ns.

DecisionContext(namespace:label,session_id:label,availability:exactcontracts.AvailabilitySpec). Wire context keys availability,namespace,session_id; availability uses exact market_cutoff_ns,knowledge_cutoff_ns,evaluation_ns,mode,reconstruction_reason attributes from accepted contracts. Mode is the accepted exact string known_at/reconstruction, not a new enum. Current execution/recording and historical C/K/E are distinct. Existing AvailabilitySpec invariants apply, no reconstructed source truth.

EventReference(chain_id,sequence,event_id,kind:EventKind,digest:lowercase64hex). Kind is one of the ten subjects below. References must name this chain and a strictly earlier sequence once placed in EventRecord; event ID must differ from current ID. Header fields bind declared prior identity. Known retained event verification is separate.

Argument(name,value): exactNone/bool/int64/str only. Wire value is tagged object {kind:null|bool|int|text,value:<scalar>}, never an untyped arbitrary object. No float/decimal/nested executable payload. ArgumentSet(state, total_count, entries): state retained_complete/truncated/redacted/not_supplied/unknown. Complete total=len(entries); truncated known total>len(entries); redacted entriesempty and totalNone ornonnegative; not_supplied/unknown entriesempty and totalNone. Names unique. This records supplied public scalar arguments; unsupported complex/private arguments must be explicitly redacted/referenced externally rather than lossily coerced. Labels cannot automatically detect every secret a caller mislabels.

PayloadReference(kind:PayloadKind,digest:hex|None,retained_bytes:int,full_bytes:int|None,state:DisclosureState). Kinds tool_result,diagnostic_report,explanation,artifact,execution_receipt. Scheme is fixed sha256 of the exact retained bytes, with kind/state included in the event hash; this is not a R9 ContentFingerprint or a native service attestation. Complete requires digest and full=retained. Truncated requires digest and known full>retained. Redacted requires no digest,retained0,fullNone ornonnegative. Not_supplied/unknown require no digest,retained0,fullNone. Empty complete payload is allowed, with actual SHA256 of empty bytes when independently verified. Constructor claims are declarative. Included public verify_payload(reference:PayloadReference, content:bytes|None)->PayloadCheck has the exact semantics below: matched retained bytes or typed unavailable, never an untyped bool/string. It does not authenticate provenance/rights or verify omitted full bytes.

Content references inside a FeatureReadSubject reuse exact public ContentFingerprint/InputFingerprint records; configuration/output/input domains must be configuration/feature_result/canonical_batch respectively. No new R9 domain, metadata digest substitution or private codec import. Direct references remain supplied assertions until actual content is independently checked.

## Public operations and meanings

encode_event(exactEventRecord)->bytes and decode_event(exactbytes)->EventRecord use ASCII JSON ensure_ascii=True,sort_keys=True,separators comma/colon,allow_nan=False, no trailing bytes/newline. Decode requires byte-for-byte canonical encoding after typed reconstruction. No generic reflection/metadata encoder. event_digest(event)->str is SHA256 of these exactbytes; no digest inside its own preimage. event_reference(event)->EventReference computes that canonical identity.

check_references(event,retained_events:concrete<=64exactEventRecords)->ReferenceCheck. Known records must be in this chain and precede current sequence; duplicate known IDs/sequences refuse. Hash each bounded retained context event once, then compare requested references' full chain/sequence/eventID/kind/digest. A present conflicting identity is inconsistent_reference; an absent target is unresolved, never passed. ReferenceCheck exposes verified and unresolved tuples and fully_resolved bool derived from them. The result verifies only supplied identity consistency, not chain completeness, original history, corrections authorization or external authenticity. It does not silently resolve references through I/O. Full persisted chain/global uniqueness/anchors/continuations remain EQ107.

No hidden global cache or mutable retained list; work is bounded by fixed admitted event/context sizes. check_references does not copy or traverse an unbounded history. Direct supplied records, references, approval/model declarations and complete disclosure are not evidence of actual source consumption or operational completion.

## Resolved exact API and ownership contract

All public constructors below take the listed positional/keyword parameters in that order; every field is required, including explicit None. No field introspection or dynamic defaults. Enums are exact own Enum records; wire strings are their exact values. Existing accepted AvailabilitySpec uses exact strings, not a new enum. Proposal preparation and public examples explicitly construct not_supplied/redacted/unknown records; nothing captures arguments, secrets or model inputs automatically.

ActorDeclaration(actor_id:str|None,kind:ActorKind); TimeDeclaration(at_ns:int|None,clock_source:str|None,uncertainty_ns:int|None); DecisionContext(namespace:str,session_id:str,availability:AvailabilitySpec); EventReference(chain_id:str,sequence:int,event_id:str,kind:EventKind,digest:str); Argument(name:str,value:None|bool|int|str); ArgumentSet(state:DisclosureState,total_count:int|None,entries:list[Argument]|tuple[Argument,...]); PayloadReference(kind:PayloadKind,digest:str|None,retained_bytes:int,full_bytes:int|None,state:DisclosureState).

RequestSubject(request_key:str,objective:str,context:DecisionContext|None); ModelSubject(provider:str|None,model:str|None,version:str|None,identity_state:ModelIdentityState); ToolCallSubject(request:EventReference,tool_name:str,tool_version:str|None,arguments:ArgumentSet); ToolResultSubject(call:EventReference,outcome:ToolOutcome,payload:PayloadReference); FeatureReadSubject(result:EventReference,receipt:PayloadReference,configuration:ContentFingerprint|None,inputs:list[InputFingerprint]|tuple[InputFingerprint,...],output:ContentFingerprint|None,feature_ids:list[str]|tuple[str,...],context:DecisionContext|None); DecisionSubject(request:EventReference,feature_reads:list[EventReference]|tuple[EventReference,...],action:DecisionAction,reason_code:str); HumanReviewSubject(decision:EventReference,verdict:ReviewVerdict,review_key:str); CancellationSubject(target:EventReference,reason:CancellationReason); ErrorSubject(target:EventReference|None,code:EventErrorCode); CorrectionSubject(target:EventReference,operation:CorrectionOperation,replacement:EventReference|None,reason_code:str).

EventRecord(chain_id:str,sequence:int,event_id:str,actor:ActorDeclaration,occurred:TimeDeclaration,recorded:TimeDeclaration,previous_hash:str,subject:Subject). Subject is the closed union of the ten exact subject classes. Exact EventKind/ActorKind/DisclosureState/ModelIdentityState/PayloadKind/ToolOutcome/DecisionAction/ReviewVerdict/CancellationReason/EventErrorCode/CorrectionOperation wire strings are precisely the lower-case tags listed in the tables; no aliases/case folding. The ten EventKind values are request,model_declaration,tool_call,tool_result,feature_read,decision,human_review,cancellation,error,correction. Declaration IDs such as request_key=r1 are ordinary labels, not namespaced event IDs.

PayloadCheck(status:PayloadCheckStatus,disclosure:DisclosureState,retained_bytes:int) is a frozen result. Status values matched_retained/unavailable. Derived retained_matched is status==matched_retained. Unavailable requires retained_bytes0; matched_retained requires complete or truncated disclosure. There is no authenticity/complete-history/operational verified flag. verify_payload first validates exact reference/content types and bytes<=65536. If contentNone or reference state redacted/not_supplied/unknown, return PayloadCheck(unavailable,reference.state,0) without hashing/retaining supplied content. Otherwise compare actual bytes length and SHA256 with the declared retained length/digest: mismatch raises inconsistent_content; match returns matched_retained/disclosure/actual length. Truncated matched bytes do not verify omitted bytes. A complete empty payload is matched only against its real empty-byte hash. The function returns no content and never fetches it.

ReferenceCheck(verified:list[EventReference]|tuple[EventReference,...],unresolved:list[EventReference]|tuple[EventReference,...]) is frozen, copies concrete sequences and preserves each tuple's reference order. fully_resolved is derived from unresolved being empty. No requested references returns both empty and fully_resolvedTrue, meaning only that there were no references to resolve, not chain validity. The flattening order is request/model=none; tool_call=request; tool_result=call; feature_read=result; decision=request then feature_reads in supplied order; human_review=decision; cancellation=target; error=target ifpresent; correction=target then replacement ifpresent. Payload/content fingerprints are not EventReferences. Aggregate subject EventReferences<=16, even if a per-field maximum alone would allow a larger combination; IDs cannot repeat within this flattened list. Amendment target/replacement must have different event IDs, not merely different digest text.

check_references builds bounded maps by BOTH event ID and sequence after validating every retained context record's structure/canonical limits, same chain and earlier sequence. Context IDs and sequences are individually unique; duplicates refuse duplicate. For each requested ref: neither ID nor sequence found means unresolved. Exactly one found, ID/sequence resolving to different records, or kind/digest mismatch means inconsistent_reference. Both lookups resolving to the same exact matching computed event identity means verified. Conflicts are never relabeled missing; a later conflict still refuses a context even if an earlier ref was unresolved. Verified/unresolved subsets retain the flattening order. Retained context records need not form a complete linked prefix: their own predecessor fields are structurally checked, but this API does not assert global linkage, original history or correction authority. At most64events and <=1048576aggregate canonical bytes of context are admitted; each event separately<=16384.

Every own nested record and accepted AvailabilitySpec/ContentFingerprint/InputFingerprint is detached/reconstructed on retention from independently checked exact scalar fields. Reconstruct nested InputFingerprint.content and DecisionContext.availability too; borrowing a frozen wrapper is insufficient. No arbitrary object __post_init__, property dispatch, generic Mapping/reflection or original mutable object is retained. Parent construction checks concrete lengths before copying; string length before UTF8 allocation; exact member classes, nested scalar ranges/labels/domain/schema/canonicalization and duplicate IDs before retaining copies. Reconstruct accepted records through their public constructors only after own scalar preflight and normalize accepted failures to fixed own codes without payload context. Caller mutation through object.__setattr__ on an original nested record cannot change a retained event.

EventRecord construction rejects aggregate canonical-byte/node/depth overflow, not only encode. Structural checks and fixed scalar/collection bounds precede projection/copying; then explicit closed-shape projection enforces aggregate counts/bytes. The conjunction is authoritative: individually legal fields can exceed the event aggregate and refuse limit_exceeded. encode_event/event_digest/event_reference/check_references revalidate/detach exact supplied records and enforce the same aggregate admission; post-construction caller tampering is not silently encoded. This is bounded application processing, not allocation-free or physical enforcement. Some lexical maxima are unreachable by a valid first-version closed shape; test refusal boundaries with malformed inputs without claiming a fictional at-bound valid record. Escaped ASCII wire-byte size, Unicode codepoints and UTF8 label-byte size have separate tests.

Error precedence for decode: exactbytes/type → maximum byte length → ASCII → lexical integer-token/node/open-container caps → JSON syntax/duplicate keys/no floats/constants → exact root key set/domain → supported schema/canonicalization → nested subject tag/key sets → typed constructors in parameter order → byte-for-byte canonical representation. A negative sign counts toward the20character integer-token cap; tokens within that cap but outside int64 fail scalar validation. Count one node for each object/array opening, every string token INCLUDING object keys, integer and true/false/null token; not closing delimiters/commas/colons/whitespace. Container depth counts simultaneously open containers including root1. Quoted escaped text does not alter structural counts. Oversized raw ASCII data fails limit_exceeded before syntax parsing. Malformed/duplicate/extra-root shape wins over unsupported version when shape is already invalid.

Constructor fields validate in the exact signature order. For each scalar: exacttype, length/range, then grammar/enum. For a collection: concrete type, length, member validation in order, then uniqueness. EventRecord validates/detaches its fields in signature order, then flattened reference aggregate/uniqueness/samechain-prior/no-self and final aggregate encoding limits. check_references validates all supplied context before resolving requested refs. Fixed error codes normalize nested unsupported ContentFingerprint schema/canonicalization to unsupported_version, other invalid accepted contracts to invalid_schema. No data-dependent diagnostic text.

Before actual Ready, retain a hand-authored complete twelve-event table: allten subject kinds, an additional replacement decision and amendment, exact full wire keys/bytes/hash/link; all disclosure/argument scalar cases; header/time/missing/context/ref-conflict/alias controls. The two original minimal literal wire goldens remain immutable. Qualification design will use fresh declaration-only and producer/evidence wheel-sdist forms on Windows/Linux, actual public producer/receipt/full-content parity only in the producer forms, and source/RECORD/license/dependency/typing/owned-cleanup audits. No native backend or service operation is added by this pure contracts story.

## Exact sequence input and immutable field typing

Constructors accept only exact builtin list or tuple, as the union input annotations above state. ArgumentSet.entries is stored/annotated tuple[Argument,...]; FeatureReadSubject.inputs tuple[InputFingerprint,...] and feature_ids tuple[str,...]; DecisionSubject.feature_reads tuple[EventReference,...]; ReferenceCheck.verified and .unresolved tuple[EventReference,...]. These classes use explicit constructor input annotations and frozen tuple field annotations; custom init validates length and members before detaching and storing tuples. No Sequence protocol, iterator, generator or subtype is admitted. check_references(event:EventRecord,retained_events:list[EventRecord]|tuple[EventRecord,...])->ReferenceCheck has the identical exact-list/tuple rule. Other operations: encode_event(event:EventRecord)->bytes; decode_event(data:bytes)->EventRecord; event_digest(event:EventRecord)->str; event_reference(event:EventRecord)->EventReference; verify_payload(reference:PayloadReference,content:bytes|None)->PayloadCheck. Read-only derived properties EventRecord.kind:EventKind, PayloadCheck.retained_matched:bool and ReferenceCheck.fully_resolved:bool have no setters. No public mutable sequence is returned.
