# EQ089 strategy and label contract proposal

Local unreviewed design preparation, October14,2026. [EQ089 #101](https://github.com/atulsrivas1/equity-features/issues/101), E12#100, R8 milestone9; provisional eight complexity points. No implementation, Ready transition, independent review or acceptance. This proposes concrete initial families within the existing scanner/ranking/forward-label scope; publish and review before implementation. Current Atul Project access remains unavailable.

## Ownership and imports

Propose two optional distributions in the canonical repository: equity-feature-strategies under packages/strategies and equity-feature-labels under packages/labels. Each depends inward on the accepted equity-feature-contracts version and supports the accepted Python3.12 interface; neither is a dependency of core contracts/features, adapters or workers. Strategies consume supplied FeatureResult objects; they do not import/recompute numerical feature algorithms. Labels consume supplied immutable price observations and basis evidence. Neither imports the other. No fetching, files/databases, wall clock, credentials, jobs, output publication, orders or portfolio state. Version numbers and CI/build integration are frozen in the implementation readiness packets, not invented as delivered artifacts here.

## Strategy inputs and identities

An immutable request supplies a finite declared universe of unique (namespace, instrument_id, session_id) keys, causal AvailabilitySpec in known_at mode, a tuple of typed accepted FeatureResult objects and an immutable rule configuration. Reject reconstruction mode for signal production. Require result namespace/session and market/knowledge/evaluation cutoffs to match the request exactly; consumers cannot retrospectively tighten the cutoff of an already calculated value. Bind result metadata identity digests, feature schema/algorithm/unit/dtype, source input revisions and configuration digest into output provenance. Strategy input accepts only the core result type with explicitly selected built-in scalar numeric columns; labels and unknown/future-label feature namespaces are rejected.

Freeze selected feature identity, algorithm/schema version, expected unit and dtype in each rule. Initial supported scalars are finite Float64 and int64; bool, strings, decimal128 and structured values are excluded until separately specified. No implicit unit conversion, Float64 coercion of int64, recomputation, normalization or missing-to-zero. Duplicate universe keys, conflicting duplicate feature/entity cells, incompatible metadata, invalid versions, nonfinite thresholds and malformed config are typed errors. Identical duplicate bindings are also rejected rather than resolved by arrival order.

## Scanner, ranking and watchlist mathematics

The first family is an AND scanner over supplied scalar features, followed by a single selected scalar ranking. Predicate operators are <, <=, ==, >= and > in the feature's declared unit/type. All required predicates must be available and true. False predicates exclude the entity; absent/null/unavailable required feature yields an explicit unavailable entity reason, distinct from false. Validate all required predicate and ranking feature cells for every entity before deciding selection. Precedence is unavailable if any required cell is absent/null/unavailable, otherwise nonmatching if any predicate is false, otherwise matching. Thus a false predicate plus a missing different predicate/ranking cell remains unavailable; it is never silently short-circuited into a complete false result. Ranking feature is required for this full eligibility assessment even when a predicate is false. Comparisons use exact int64 or finite Float64 representation with no epsilon tie or arithmetic score transform. Identity of ordered predicates is part of config; stable ordering does not hide different config identities.

For ranking, sort admitted matching entities by the selected scalar ascending or descending. Exact equal represented values tie; break ties by (namespace, instrument_id, session_id) lexicographic Unicode codepoint order, with no locale/case folding. Assign unique ordinal ranks 1..M after tie breaking. Watchlist is the first min(k,M) ranked rows, with integer k>=0 (bool rejected). k=0 is a valid empty watchlist, not an unavailable result; negative k is invalid. No percentile, weighted score, normalized alpha, trading instruction or profitability claim.

Emit immutable rows for every declared entity in canonical entity order, including matching/nonmatching/unavailable status, predicate dispositions, selected value when available and rank when admitted. Emit ranked and selected entity tuples separately in rank order. Universe coverage is eligible_count/declared_count, eligible requiring all predicate/ranking inputs. Empty universe has coverage=None and an explicit empty-universe reason. All-missing nonempty universe has coverage=0 and no ranked entities. Partial results stay explicitly incomplete even if an admitted subset is ranked; selection does not claim a complete universe. Do not add a silent partial-coverage threshold.

Same supplied data and config produce identical complete rows/order/provenance. Source revisions or config changes produce new output identities. All outputs include schema/rule/package versions and request/result/config identities. Do not claim the identity is an authenticity or sandbox proof.

## Forward price-return label family

Initial labels are simple forward price returns, kept in a distinct label result schema and namespace. Supply anchor timestamp t0, positive UTC elapsed horizon h in int64 nanoseconds and a finite immutable path keyed by unique timestamps. Define endpoint t1=t0+h with checked int64 overflow. Require exact observations at t0 and t1; no interpolation, nearest observation, exchange-calendar discovery or hidden next-session substitution. If users need session horizons, they must await a separately specified governed-session family.

Formula: R=(P(t1)-P(t0))/P(t0), unit fraction. Require finite positive supplied prices; zero/negative/nonfinite prices are typed invalid input. For admitted endpoints evaluate q=P(t1)/P(t0), then R=q-1 using Float64. If q or R is nonfinite, reject with a typed numerical-bounds error; if the positive mathematical ratio underflows to q=0, reject with a typed precision-bounds error. Do not clip, substitute infinity/zero, or relabel these failures pending. Finite nonzero subnormal q is supported with normal Float64 rounding, including an R rounded to -1; no exact-rational output promise. Independent rational fixture comparisons use absolute/relative tolerance 1e-12 on finite supported outputs; this is a verification tolerance, not a threshold-equality epsilon or a guarantee of relative accuracy for tiny near-zero returns. Zero return is a valid mature value. Validate input prices structurally first, but compute q/R only after endpoint/basis admission so pending outputs expose no future numeric result. Interior observations are not used in the formula. Bind instrument namespace, source/path/config revisions and explicit basis identity to both endpoints.

Support caller-supplied raw or split-adjusted price basis, with a nonempty adjustment revision/evidence identity and identical basis on both endpoints. Reject mismatch and ambiguous basis. Raw returns are explicitly raw price movement, including split discontinuities; split-adjusted returns use supplied comparable adjusted prices. No adjustment inference, corporate-action lookup, dividend addition or total-return label. A cash-dividend event does not silently change this price-return definition. A caller-supplied basis witness is trusted evidence, not independent verification of provider rights or economic correctness.

Each observation carries event_ns and known_at_ns. Label evaluation supplies explicit market cutoff C, knowledge cutoff K and evaluation E with C<=E and K<=E. Anchor must be observable at signal time supplied separately and not selected from future prices. Preserve the immutable originating signal/request identity; label maturation cannot rewrite it. Endpoints must satisfy event<=C and known_at<=K. Endpoint values are not used or exposed before admission. label_known_at=max(endpoint known-at times, supplied basis-evidence known-at); maturity requires all consumed basis evidence admitted too.

After structural validation, state precedence is: pending if t1>C; otherwise incomplete if either exact endpoint is absent; otherwise pending if either endpoint or required basis evidence has unknown known-at or known-at>K; otherwise mature after supported numeric evaluation. Missing endpoints after the horizon outrank unavailable basis knowledge, so an absent endpoint plus future/unknown basis evidence is incomplete; before the horizon that combination is pending. Invalid supplied data remains a typed error before this state evaluation. This precedence does not inspect undisclosed future prices. Invalid input is a typed error, not pending. Values are null except mature. A corrected source or basis revision creates a distinct new label identity and supersedes the old result only by caller choice; it cannot silently overwrite prior maturity. Re-evaluation of the same immutable admitted inputs is deterministic.

## Independent fixtures before Ready

Strategy hand-derived fixture: universe A,B,C,D,E, same session/namespace; predicate x>=2, rank y descending, k=2. A:(x=2,y=5), B:(3,5), C:(1,9), D:(missing,8), E:(4,4). Expected ranked A,B,E (tie A before B); selected A,B; C=false, D=unavailable; coverage=4/5. Permute input/entity order without changing canonical output or rank. Also cover equal-threshold exclusion/inclusion, empty/single/all-missing, absent ranking input, duplicate/conflicting identities, k=0/k>M/negative/bool, exact int64 beyond binary64 precision, incompatible unit/version/cutoff, invalid nonfinite values and labels rejected as signal input.

Label hand-derived fixtures: 100->110 gives 1/10; 100->90 gives -1/10; 100->100 gives 0. Missing exact horizon is incomplete after horizon and pending before it. Known-at later than K stays pending at the exact endpoint time; equality is admitted. Unknown basis knowledge stays pending. Raw 100->50 gives -1/2; a caller-certified consistently split-adjusted 50->50 gives 0, with distinct basis/result identities. Dividend price fall 100->99 gives -1/100 price return; no cash addition. Zero/negative/NaN/inf, duplicate endpoints, overflow and basis mismatch are errors. Revisions must change identity. Add bounded numeric fixtures with minimum-positive-subnormal versus maximum-finite prices: max/min rejects ratio overflow; min/max rejects underflow-to-zero. Equal max/max returns zero; a supported finite subnormal ratio follows documented rounding. Add explicit mixed-condition fixtures for absent endpoint plus future/unknown basis (pending before horizon, incomplete at/after horizon) and false scanner predicate plus a missing different required cell (unavailable).

Causality fixtures keep the observed feature prefix/config/cutoffs identical while replacing future prices, future basis facts and labels: strategy outputs must remain exactly identical. Pending labels must expose no endpoint return. Mature-label joins in a later synthetic backtest example filter by label_known_at and maturity; the demonstration does not establish profitability or execution realism.
