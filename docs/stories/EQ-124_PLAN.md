# EQ124 explicit composition pre-code plan

Canonical [issue281](https://github.com/atulsrivas1/equity-features/issues/281), E19 / R4.1, 5 provisional complexity points. EQ123 verified Closed/ProjectDone after [actual design acceptance](https://github.com/atulsrivas1/equity-features/issues/280#issuecomment-6029469345); no other story active. [Frozen design](../IO_PUBLICATION_V1.md), [architecture](../IO_WORKER_ARCHITECTURE.md) and [test strategy](../R4_1_TEST_STRATEGY.md) govern scope.

Implement explicit per-run SourceRegistry/SinkRegistry and direct-instance admission. Caller registers already imported local factory instances under validated ASCII IDs; source/sink ID namespaces are separate. No automatic discovery/import/module strings, mutable global registry or worker commands. CredentialProvider is passed separately to create; public configuration is an immutable scalar mapping, with secret-bearing reserved keys and unsupported objects rejected. Local extensions remain trusted caller code; remote systems need server-selected allowlists and cannot accept uploaded executables.

Signatures: ComponentFactory[T].protocol_version='1'; validate_config(PublicConfig)->PublicConfig; create(PublicConfig,CredentialProvider)->T. Registry.register(id,factory); resolve(id,config,credentials,requirements)->component. SDK validates/freeze-copies configuration before and after the caller validator, suppresses raw extension exception messages/context, checks exact factory versions, and admits capabilities before acquisition/publication. Direct injection uses the same admission path as factory resolution. Constructors/validators are trusted local code, not sandboxed; this SDK itself never acquires or writes during admission.

Canonical source protocols/capability/request admission remain unchanged. New companion types include CredentialProvider, immutable scalar config/factory/error interfaces, a structural SinkCapabilitiesView/SinkCandidate and typed SinkRequirements matching the frozen capability fields. This enables startup admission without implementing begin/write/commit runtime objects: full operational sink types/codec/conformance remainEQ125. Source historical/live selection stays explicit; factories never invent live support. Sink admission verifies all exact protocol/codec/key/digest/canonical versions, required visibility/writer mode/lookup-abort-read booleans and requested bounds.

Version effects: io-contracts0.1.0a1 and io-sdk0.1.0a1, SDK depends exactly on contracts.a1; canonical purepair.a4 and DuckDB.a8 stay unchanged. Existing worker.a0 remains a skeleton using its accepted SDK.a0 pair; current composed worker dependency alignment is explicitly qualified by EQ129, not silently changed here. No compatibility claim for arbitrary mixed prerelease pairs. No I/O/backend dependencies enter pure core.

Independent validation: separately install a small synthetic consumer distribution implementing factories using public APIs; compare direct/factory object behavior, request capabilities and no acquisition/write counters during rejection. Cases: duplicate/unknown IDs, same ID across directions and isolated registries, invalid config/versions/capability/limits, source schema rejection, credential-sensitive constructor/validator/capability failures with redacted diagnostics, import-side-effect probe, strict external positive/negative typing and core-without-I/O invariance. Consumer fixture is factory qualification, not EQ128 full extension/backend conformance or production storage.

Update repeat/fresh-form foundation builder/probe for declared versions/public exports and installed external factory fixture; preserve committed Git archive provenance and capture/reject changed source heads. Current native Windows/Linux CI, relevant tests, separate final-head review, actual main package/archive/report/download/hash/source/owner/retention readback and same-story API/config/compatibility/decision/continuity docs remain release gates. No mathematical definition/source/rights changes, private generation, provider/service/stable registry or R5 execution. Publish this concrete plan before package code.
