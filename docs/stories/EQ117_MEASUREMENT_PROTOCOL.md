# EQ117 measurement protocol proposal

Read [plan](EQ117_PLAN.md) and [numeric proposal](EQ117_EVALUATION_PROPOSAL.json). No study has run. Exact operation/schema/source implementation is pending review after owner threshold acceptance; this document is not an execution grant.

## Tasks and fair evidence

Each case asks the same four questions in both arms: identify supported findings and unsupported claims; check retained completeness against the separately supplied original terminal; reproduce retained calculation once if supported; report gaps/refusals without treating them as success. Expected outcomes derive from the independently frozen [EQ116 oracles](EQ116_ORACLES.json), not a new calculator-derived golden.

Score every complete supported output field against full literal expected data (including quality/context, complete native result and all relevant statuses), not only a digest or PASS token. The summary table supplements those literals. P01/P08 unknown authenticity is a limitation, not a false alarm; P01 must not be labeled anomalous.

Both arms get identical synthetic inputs/configuration/results/receipts/reports/narrative facts and retained bundle, equivalent task instructions and original terminal information. The exact solver file/field allowlist and forbidden inputs are frozen in solver_visibility in the JSON. No observations.json/completion.json/scorer/oracle/fixture/opposite-arm access is permitted. task.json contains only schema, opaque trial_id and original narrative. declared-reports.json exposes strict/advisory/explanation as untrusted original producer declarations, identically to both arms; ledger payload references may use these same bytes. terminal.json contains only that arm original expected terminal from the same controlled trust authority. The public arm-specific trace is unchanged, including logged decisions, but a declared decision/report is never scored as an independently derived diagnosis. Recompute supported comparisons from retained bundle/task facts, and strict diagnostics from retained input/configuration with the accepted API. Keep declared_strict_admission and recomputed_strict_admission separate. P05 retains declared admitted, while recomputed admission is UNKNOWN/retained_input_missing; do not restore omitted rows from the fixture. P07 returns null for all post-load declarations/recomputations. These literal expected distinctions are in the JSON, supplementing accepted EQ116 native-content oracles; no accepted package contract changes. Retention/corruption/prefix interventions affect both equally. The structured log has its full canonical JSON/count/bytes/digest anchor; it can detect truncation too. No private terminal or hidden input is available only to the ledger. Shared qualification completion/manifests must not reveal the diagnosis in one arm; arm-native stores and equivalent common files get the same visibility policy.

The accepted EQ116 `read_case` imports fixture/oracle data, branches on case IDs and checks expected answers. It is a qualification checker, not a blind task solver, and must NOT be timed or counted as evidence of debugging benefit. New generic observation adapters must derive findings from supplied retained evidence using public APIs, without case-ID branches, expected outputs, fixture reconstruction or the opposite arm's store. Only the independent post-trial scorer sees the case-to-oracle mapping. Generic parsing, event/terminal verification, payload checks and replay remain distinguishable. If this separation cannot be implemented without missing evidence, mark the assessment unavailable/DEFER; never reuse an oracle-aware PASS as a diagnosis.

## Fixed schedule and process state

Eight cases, two arms, ten paired repetitions, two OSs: 320 observations, with 240 eligible replay entries and 80 missing/corrupt zero-call observations. One observation is a full case/arm result, not an independent participant or statistical sample. Fixed odd/even case orders and counterbalanced arm order are in the JSON. Arm order uses stable case index P01=1 through P08=8, never the position in a reversed order. Each case has five ordinary-first and five evidence-first repetitions per OS; within each five-repeat process state the split is2/3, reversed in the other state. No random seed search, adaptive stopping, discarded failures or optional extra repeats.

Repetitions1–5 use a newly launched isolated interpreter per case/arm; label PROCESS_COLD, never disk/cache cold. Repetitions6–10 use one warmed isolated interpreter per arm per OS, importing once and processing its fixed schedule sequentially; label PROCESS_WARM, never claims about CPU/cache residency. Each trial gets fresh owned writable stores with identical immutable fixture bytes. No intertrial ledger/root reuse. No warmup outcomes are omitted. OS jobs are sequential within themselves; record runner identity and concurrency conditions. Compare arms only within the same OS/case/process-state; do not pool Windows/Linux medians.

## Timing and operation accounting

Use monotonic `perf_counter_ns`, with explicit nonnegative integer start/end observations. Parent launch/import duration is separate. Common fixture calculation occurs once per paired trial outside both arm timers, is fully parity checked and separately reported. It may not be claimed as recording advantage. No package calculator consults the timer.

Record stage: serialize the same factual record, append/write it through that arm's actual public path, retain equivalent artifacts and actually close owned handles. Export stage: retrieve the actual stored records (ledger page verification for evidence, canonical JSON verification for ordinary log), serialize/export them and finish actual writes/closes. Read/verify/replay stage: read retained bytes, verify the arm-specific evidence and common bundle, diagnose generically, then invoke the same accepted replay registry at most once. Do not time accepted paired `record()` as if it measured two separate arms. Include all arm-specific work rather than move it to untimed setup. Report shared bundle construction separately with a combined-total column as well as stage values. Performance comparisons require full output parity first.

The raw operation trace records every occurrence of closed categories: file_read, file_write, file_close, json_decode, json_encode, hash_verify, event_decode, chain_verify, ledger_open, ledger_append, ledger_verify, ledger_export, ledger_close, bundle_read, payload_verify, assessment, replay_entry and calculator_call. Instrument actual operations including nested API work, with source-reviewed non-overlapping definitions; tracing must not double count the same category at wrapper and callee. Both adapters have identical tracing rules and access to public tools. Report the full vector, total, CLI invocations and counted API calls separately. Fixed script stages are not measured human debugging steps; null human fields remain null. Do not fabricate fewer steps by labeling a ledger convenience wrapper as a single operation.

Closed-file bytes sum st_size of every regular output file attributed to the arm after close, including SQLite files and terminal/export/common retained bundle; common files count once per arm identically. Report file count, common/arm-specific components and observed transient peak separately. A safely observable transient peak may be unavailable (null, explicit reason); never imply a sample proves physical peak. Deleted-open/sparse/allocated blocks, RSS, OS caches and physical containment remain unqualified. Threshold compares completed closed-file totals for every paired trial, not only a favorable median.

## Raw capture, summaries and failure

The JSON defines bounded context, 320 closed-schema trial records, stdout/stderr and aggregate logical log caps. Record exact source/proposal/input/installed/environment maps, each operation count, raw timing endpoints and derived durations, output hashes/sizes, errors, return codes and status. The normative raw_fields list includes signed process return_code and paired start/end fields for record, export, read_verify_replay, launch_import and common_fixture_compute. Each duration equals end-start in its own process/clock domain; parent and child clocks are never subtracted. No observed exit means null return_code with explicit unknown status, not success. Freeze concrete enums/string/trace bounds before execution. Record failed calls and prior successful stages; unavailable timings are null, never zero. No raw file limit or timeout is a physical resource or hard cleanup guarantee. Keep unknown outcomes and incomplete roots; stop mutation rather than replay an uncertain append. A safety/fixture/pin error invalidates the aggregate and marks remaining planned slots NOT_RUN. Ordinary task failure occupies its scheduled slot and may continue only after confirmed local cleanup; cleanup unknown stops the run. All trials/roots/logs are retained under new run identity, no overwrite or successful-rerun selection.

Publish the complete 320-slot table, planned/attempted/valid/failed/not-run denominators; counts of exact findings, false positives, replay matches/unavailable/refused and all calculator calls; each OS/case/process-state median, minimum, maximum, nearest-rank p25/p75 and individual paired differences. With five repeats per stratum, nearest-rank quantile is sorted value at ceil(p*n), 1-based. Median is middle sorted value for odd n, arithmetic mean of middle two for even n. Pair by OS/case/repetition; delta=evidence-baseline, reduction=(baseline-evidence)/baseline only when baseline>0, otherwise report absolute values and no percentage. The operation-improvement threshold uses the ratio of the two arm medians, (median_baseline - median_evidence)/median_baseline, over all five scheduled repeats within each OS/case/process-state. This differs from median paired ratios, which are descriptive only. A case passes only if every slot is valid and the ratio is at least0.20; zero baseline makes reduction undefined and cannot pass. At least6/8cases must pass in each OS/process state. Missing/failure invalidates that stratum's threshold; never drop it to compute a passing median. No significance/population/human benefit claim from scripted repetitions.

## Decision and qualification

Correctness failure is NO_GO for the changed evaluator until diagnosed; retain original failed result and review correction. Technical budgets exceeded yields DEFER for broader use, with exact failing strata. Passing technical budgets yields only a bounded automated feasibility result; human usefulness/demand and independent trust need remain UNKNOWN. No automatic witness selection. Owner accepts go/defer/no-go after seeing actual results; absent human evidence defaults DEFER for productization, not a fabricated successful study.

Before measurement: owner accepts final proposal identity; independent source/instrumentation review and inert timing/arithmetic/denominator/schema/refusal/fairness controls pass; immutable environments and source/raw maps frozen; fresh installed Windows/Linux harness qualified. Relevant numerical output parity, current CI/artifact and public/main review gates remain. All dry-run/qualification invocations must be disclosed separately; they are not scheduled study observations. If measurements were accidentally collected before threshold acceptance, quarantine them as exploratory/unqualified and do not use them to select thresholds. No such collection has occurred in this proposal.
