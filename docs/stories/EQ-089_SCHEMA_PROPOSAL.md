# EQ089 exact v1 schema and identity proposal

Local design preparation, October14,2026. Extends the [reviewed formula draft](EQ-089_CONTRACT_DRAFT.md) for [EQ089 #101](https://github.com/atulsrivas1/equity-features/issues/101). These are proposed contracts, not implemented public classes or accepted Ready status. Conflicting draft language is superseded only by the explicit decisions below; original review reports remain evidence. Current canonical source is da74650e03d67acc5de6f8881065518f68b1f24f. No GitHub mutation or runtime implementation.

## Distribution and compatibility decision

Propose equity-feature-strategies and equity-feature-labels, each experimental 0.1.0a1, Python >=3.12,<3.13, Apache-2.0, typed pure Python, independently optional. Each requires equity-feature-contracts==0.0.4a4 only, with no columnar extra or dependency on the other distribution. Core/features have no outward dependency. Setuptools==80.9.0 is the proposed isolated build tool. Release is through reviewed GitHub CI artifacts, not a stable registry. EQ090/EQ091 implementation packets must confirm these actual choices and freeze build/CI integration before implementation; versions in this proposal are not delivered versions.

Input and output schema strings are strategy-request:1, strategy-config:1, strategy-result:1, label-origin:1, label-request:1, label-config:1, label-result:1. Algorithm strings are scanner-and-rank:v1 and forward-price-return:v1. Unsupported versions reject with incompatible_version; no automatic migration. Core FeatureResult metadata/schema and FeatureColumn schema must be "1", math_policy_version "v1", and selected feature algorithms "v1". Reject reconstruction availability throughout signal and label admission.

## Shared primitive and ownership rules

All records are frozen typed values. Sequences accept concrete tuple/list only and snapshot to owned tuples; no lazy iterators, mappings with user callbacks or subclasses. Exact built-in types are required. UTCns values are int64, bool rejected; k and counts are integers 0..2^63-1; horizon_ns is 1..2^63-1 with checked endpoint addition. Identity strings are nonempty/non-whitespace valid Unicode without surrogate codepoints or control characters U+0000..U+001F/U+007F, with no trimming, case folding or Unicode normalization. Hashes are exactly 64 lowercase hex characters. No maximum dataset size, authentication or sandbox guarantee follows from these value contracts; caller orchestration owns resource budgets.

Entity is (namespace:str, instrument_id:str, session_id:str). Each request supports exactly one namespace and session_id; every universe key, result metadata and label origin/path must match. Mixed namespaces/sessions reject inconsistent_identity. Empty universe is legal with request namespace/session still supplied. The core EntityKey remains unchanged: namespace comes from request/result metadata. Outside-universe feature rows reject inconsistent_identity rather than being silently discarded. Duplicate universe keys or duplicate supplied feature/entity bindings reject duplicate, even if values match.

## Exact supported feature set

No arbitrary custom or label namespaces. This closed table is taken from the accepted core catalog; adding another ID is a future versioned contract decision.

| Feature ID | schema / algorithm | dtype | unit |
| --- | --- | --- | --- |
| session.trade.count | 1 / v1 | int64 | trades |
| session.trade.volume | 1 / v1 | int64 | shares |
| session.price.open_close_return | 1 / v1 | float64 | fraction |
| history.return | 1 / v1 | float64 | fraction |
| baseline.relative_volume | 1 / v1 | float64 | fraction |

Every supplied result column must belong to this table, even when not selected by a rule. No implicit projection of unsupported columns inside the strategy package. Callers can construct separately validated supplied results before invoking it. FeatureId supports exact table values; FeatureRequirement fields are feature_id, schema_version, algorithm_version, dtype, unit, expected_result_config_digest:str and expected_input_semantic_digest:str. The first five fields exactly match the table; both expected digests are mandatory 64-character lowercase SHA256 values. All required cells for a requirement, across every admitted entity/result, must have metadata.config_digest exactly equal to expected_result_config_digest and their complete input-semantic projection digest exactly equal to expected_input_semantic_digest. Mismatch rejects inconsistent_identity before scanning; recording different provenance is not compatibility. This deliberately supports one common configuration per feature/request, not per-entity horizon aliases. The caller obtains the exact accepted ConfigSpec.digest for the requested session/window/period/availability/adjustment/policy; the strategy package compares the binding and does not recompute feature formulas or infer semantic equivalence from units. ConfigSpec.identity/algorithm and each selected feature algorithm remain separately bound. Predicate fields are requirement:FeatureRequirement, operator:str from lt/le/eq/ge/gt and threshold:int|float exactly matching dtype. Int thresholds are int64, Float64 thresholds finite; no numeric coercion or epsilon. Ranking uses requirement:FeatureRequirement and direction from ascending/descending. Empty predicates are permitted and mean an unconditional scanner requiring the ranking feature. Repeated predicate definitions are legal ordered rules, not duplicate data; order is part of config identity.

StrategyConfig fields: schema_version="strategy-config:1", algorithm_version="scanner-and-rank:v1", predicates:tuple[Predicate,...], ranking:Ranking, top_k:int. StrategyRequest fields: schema_version="strategy-request:1", namespace:str, session_id:str, availability:AvailabilitySpec, universe:tuple[Entity,...], feature_results:tuple[FeatureResult,...], config:StrategyConfig. Results must have availability exactly equal to request availability and satisfy core constructors and explicit selected-table constraints. Each input retains its full immutable content; do not replace content with metadata.identity_digest, which binds metadata only. Unknown or conflicting versions/unit/type/namespace/source identities are invalid input, not ordinary missing data.

### Calculation and input-semantic compatibility

A result input-semantic projection is the tuple of every ResultMetadata.inputs binding sorted by role, with a closed InputSemantic record containing role, kind, schema_version and fields from its BatchMetadata: namespace, source_id, mapping_version, price_unit, adjustment, sampling, quantity_unit, ordering, duplicate_policy, scope and interval_bounds. interval_bounds is the tuple of IntervalSemantic(name,start_ns,end_ns) sorted by name, excluding observed/expected coverage counts. Source snapshot_id/input_id and data coverage counts are excluded from this comparability projection but remain in full content identities. Include all bindings, not a heuristic guess of which role a feature used. Require the exact projection for each result that supplies a required cell, even if other required cells are unavailable. This strict equality can reject semantically equivalent inputs; v1 makes no automatic equivalence or per-entity normalization promise.

InputSemantic.price_unit is the exact optional core PriceUnit and adjustment the exact core AdjustmentSpec. This freezes currency/scale, raw/split/total-return basis identity, action snapshot/anchor/policy, source mapping and eligibility/auction/time scope in addition to ConfigSpec.digest. A missing required cell still has the ordinary unavailable disposition; an actually supplied cell under the wrong configuration/basis is invalid input, not missing. If two rules reference the same feature_id, they must declare identical FeatureRequirement fields; conflicting requirements reject invalid_config. Unselected supported columns bind to full content identities but do not authorize their use under a requirement they do not match. No input authenticity is inferred from a supplied matching digest; honest supplied facts are the existing trust boundary.

## Strategy outputs and reasons

PredicateDisposition fields: predicate_index:int, feature_id:str, state from pass/fail/unavailable, reason:Optional[str]. Unavailable reasons are absent_feature, absent_entity or the exact core unavailable Status.value (insufficient_history, missing_input, incomplete_coverage, not_applicable). Retain the full original QualityRow, including Reason tuples, through source provenance; a string disposition does not replace that evidence. Available-but-null or malformed quality/value combinations reject invalid_schema. Predicates with available values emit pass/fail and reason=None.

StrategyRow fields: entity:Entity, status from matching/nonmatching/unavailable, predicate_dispositions:tuple[PredicateDisposition,...] in predicate order, ranking_value:int|float|None, ranking_reason:Optional[str], rank:int|None. Ranking value is retained when independently available even if another predicate is unavailable or false; otherwise it is null and ranking_reason follows the same reason vocabulary. Rank is nonnull only for matching rows. If any required predicate/ranking cell is unavailable, row status unavailable; otherwise a false predicate gives nonmatching; otherwise matching. This explicitly assesses all cells before applying precedence.

StrategyResult fields: schema_version="strategy-result:1", algorithm_version="scanner-and-rank:v1", config_digest:str, request_digest:str, input_content_digests:tuple[str,...] sorted, rows:tuple[StrategyRow,...] sorted by Entity, ranked:tuple[Entity,...] in rank order, selected:tuple[Entity,...] in rank order, expected:int, eligible:int, matching:int, coverage_numerator:int, coverage_denominator:int, readiness from complete/incomplete/empty_universe, producer_version="0.1.0a1". expected is universe size; eligible counts rows with every required cell available; matching counts matching rows. Counts preserve exact rational coverage without Float64 division. For an empty universe both coverage counts are zero and no fraction is defined; readiness empty_universe. Otherwise complete iff eligible==expected, incomplete otherwise. The draft's coverage=None means undefined 0/0, not a separate hidden nullable field.

Sorting uses exact numeric value, reverse numeric direction only, then ascending Entity lexicographic codepoint order. No negation through Float64 for int64 sorting. Exact represented equality is a tie; distinct +0.0/-0.0 compare tied numerically while distinct bit spelling remains in content identity. Rank is unique ordinal 1..matching. selected is ranked[:top_k]. A complete request with no matches or top_k=0 is still complete, not an error or unavailable watchlist.

## Label origin, path and basis admission

LabelOrigin fields: schema_version="label-origin:1", entity:Entity, signal_request_digest:str, signal_result_digest:str, signal_availability:AvailabilitySpec, anchor_event_ns:int, anchor_price:float, anchor_known_at_ns:int, anchor_source_revision:str, anchor_basis:BasisWitness. Anchor price is finite positive, anchor_event_ns<=signal C, anchor_known_at_ns<=signal K, origin basis known_at_ns is nonnull and <=signal K, and basis effective_ns<=anchor_event_ns. All signal cutoffs are causal. Origin is an immutable supplied fact binding, not an authenticated proof that a signal actually ran. A future/unknown anchor or origin basis rejects inconsistent_identity instead of producing a retrospective signal.

BasisWitness fields: basis from raw/split, policy_version:str, action_snapshot:str, anchor_id:str, source_revision:str, effective_ns:int, known_at_ns:int|None. Raw requires policy_version="raw-v1", action_snapshot="none", anchor_id="none" and an explicit source_revision. Split requires nonempty identifiers other than "none" for policy/action snapshot/anchor/source revision. All strings obey shared rules. total_return and unspecified adjustment bases reject unsupported_adjustment. No action lookup or adjustment calculation occurs. The witness is a trusted caller assertion.

PriceObservation fields: event_ns:int, price:float, known_at_ns:int|None, source_revision:str, origin_anchor_digest:str, basis:BasisWitness. All observations in a LabelRequest have identical basis identity (basis,policy_version,action_snapshot,anchor_id,source_revision,effective_ns,known_at_ns), identical source_revision and origin_anchor_digest equal to the supplied origin digest. event_ns may exceed current label C, but prices must be structurally valid finite positive Float64. Duplicate timestamps reject duplicate; paths normalize to ascending event_ns. All supplied rows bind to one origin/entity; path digest includes every row, not just endpoints. This restriction avoids ambiguous correction selection.

LabelConfig fields: schema_version="label-config:1", algorithm_version="forward-price-return:v1", horizon_ns:int. LabelRequest fields: schema_version="label-request:1", origin:LabelOrigin, availability:AvailabilitySpec, observations:tuple[PriceObservation,...], config:LabelConfig. Label availability C,K,E must each be >= the corresponding signal cutoff, with C/K<=E. Checked t1=origin.anchor_event_ns+horizon_ns. The supplied label path may use a later split-adjustment revision and adjusted anchor price, provided its origin_anchor_digest binds the original anchor facts and its own known-at witnesses satisfy label maturity. This is an explicit trusted caller mapping, not proof that the adjusted price is correct. It must never replace origin.anchor_price, signal identity or original signal basis. A later basis cannot enter a signal input merely because it is permitted in a future label.

Basis effective_ns must be <=t1 for a mature label; if later, label remains pending with basis_not_effective. Endpoint and basis knowledge can arrive after signal E; that is normal future-label information, admitted only under the label C/K/E. The exact t0 path price used in the label may have a later known_at than the immutable signal anchor when it is an adjusted/revised supplied observation. This does not retroactively change anchor admission. Distinct adjusted anchors, source/basis revisions and paths create distinct label request/content identities, even if returns coincide.

## Label outputs, state precedence and joins

Structural validation and origin admission precede state determination. A malformed unrelated future row is still invalid input, never a silent missing value. State precedence is:

1. If t1>label C: pending/horizon_not_elapsed.
2. Otherwise if t0 or t1 is absent: incomplete/missing_anchor_endpoint or missing_horizon_endpoint; when both absent, missing_anchor_endpoint first in reasons.
3. Otherwise if any consumed endpoint or common basis known_at is None: pending/unknown_availability; if any exceeds K: pending/future_knowledge. Both reasons may be retained in this fixed order.
4. Otherwise if basis effective_ns>t1: pending/basis_not_effective.
5. Otherwise compute q=P(t1)/P(t0) then R=q-1 using Float64. Nonfinite q/R raises numerical_bounds; q=0 raises precision_bounds. Supported finite nonzero subnormals retain ordinary rounding. Mature has no pending/incomplete reason.

LabelResult fields: schema_version="label-result:1", algorithm_version="forward-price-return:v1", entity:Entity, origin_digest:str, config_digest:str, request_digest:str, path_content_digest:str, availability:AvailabilitySpec, horizon_endpoint_ns:int, status from pending/incomplete/mature, reasons:tuple[str,...], value:float|None, unit="fraction", label_known_at_ns:int|None, producer_version="0.1.0a1". value and label_known_at are nonnull only for mature. Mature label_known_at=max(t0 known_at,t1 known_at,basis known_at); it never substitutes E or wall time. Pending/incomplete output exposes no endpoint price, ratio, path contents or future known-at timestamp. Digests are opaque equality/revision bindings, not a promise of private-data secrecy. A corrected request produces another identity; the library cannot overwrite historical output.

A synthetic as-of backtest consumer may join a mature label only if label.horizon_endpoint_ns<=join C, label_known_at_ns<=join K and join C/K<=join E, the original signal cutoffs remain <=join cutoffs, origin/request identities match the selected records and the application explicitly selects the label revision. A future path revision or immature label never enters strategy-request:1, even if its numerical field could resemble a supported feature. If labels are used for retrospective research targets, their known-at remains explicit; no tradable signal claim.

## Canonical in-memory serialization and complete identities

Provide encode-to-bytes/digest helpers only; no decoder, file/network operation, object import by name or arbitrary serializer. Each proposed package independently implements this specified closed encoding, with no third distribution or outward I/O dependency. Canonical output is ASCII JSON with sort_keys=True, separators=(",",":"), ensure_ascii=True, allow_nan=False; no BOM/newline. All field names are strings. Null/bool/string map to JSON null/bool/string. int maps to {"int":"<base10>"}; Float64 maps to {"float64":"<float.hex()>"}, finite only. Exact approved StrEnum types map to {"enum":"<fixed class label>","value":"<enum value>"}; check enum before string. Tuple/list maps to JSON array after the field-specific normalization below. Exact approved frozen records map to {"record":"<fixed class label>","fields":{every declared field:encoded value}}. Unknown types/subclasses reject invalid_schema. No __dict__, pickle, repr, unknown dataclass or reflection-selected import path is accepted.

Approved proposed compatibility record labels also include InputSemantic and IntervalSemantic with exactly the fields listed above. Approved core record labels are results.EntityKey, results.FeatureColumn, results.QualityRow, results.InputBinding, results.ResultMetadata, results.EvidenceRow, results.FeatureResult, inputs.BatchMetadata, inputs.SourceBinding, inputs.Coverage, inputs.PriceUnit, inputs.AdjustmentSpec, inputs.InputScope, inputs.IntervalCoverage, specs.AvailabilitySpec. Approved core enums are results.Status, results.Reason, results.ValueType and inputs.DataKind. Proposed strategy/label records use the exact schema record names defined above; all their fields participate. Nonselected structured result classes remain unsupported. Nullable/default-valued fields are still encoded, never omitted. Core metadata full values, full quality/status/reasons, source revisions, values and evidence participate; metadata.identity_digest is supplementary only.

Normalization: request universe and output rows sort by Entity; feature_results sort by their content digest; FeatureColumn pairs (entity,value) sort by entity; columns sort by feature_id; quality sorts by (entity,feature_id), each reasons tuple by reason.value; evidence sorts by encoded canonical bytes including all fields; ResultMetadata.inputs sorts by role; BatchMetadata.interval_coverage sorts by name. All other named sequences preserve documented order: predicates and predicate dispositions preserve rule order; ranked/selected preserve rank order. Label observations sort by event_ns. Duplicate bindings are rejected before normalization. This makes harmless result/entity/column/evidence order permutations deterministic without discarding semantic rule order or revisions.

Digest(domain,record) is SHA256 over ASCII(domain)+one NUL byte+canonical encoded record bytes. Domains are strategy-config:1, strategy-request:1, strategy-result:1, core-feature-result:1, core-input-semantics:1, label-origin:1, label-config:1, label-request:1, label-result:1 and label-price-path:1. Canonical record bytes for each request include original input content, not only stored digest claims. Results include computed input/config/request digests but exclude their own identity_digest field; identity_digest is a derived property, avoiding a self-referential hash. Path hash encodes the normalized complete observations tuple. core-input-semantics:1 hashes the complete normalized InputSemantic tuple; it does not reuse core metadata.identity_digest. The two distributions expose serialization for their own supported values only; no dynamic cross-import or label object serialization through strategies.

Changing any selected value, null validity, quality, evidence, schema/algorithm/unit, source/basis revision, timing or semantic predicate order changes its affected content/config/request identity. Entity/result presentation permutations after normalization do not. Hash equality is a deterministic binding, not authenticity, access authorization or collision-proof mathematics.

## Exact failure vocabulary

Proposed StrategyError and LabelError are ValueError subclasses with immutable code:str and fixed public messages; no raw input/path/credentials in error text. Both use invalid_schema, invalid_config, incompatible_version, inconsistent_identity, duplicate, invalid_unit, bounds, unsupported_feature, unsupported_adjustment, numerical_bounds, precision_bounds. Codes are closed values. Core constructor ContractError remains a core API error when constructing inputs; package boundary checks of an already supplied valid object use the new package errors. Unknown enum/type/schema: invalid_schema; version mismatch: incompatible_version; unsupported ID: unsupported_feature; wrong declared dtype/unit: invalid_unit; malformed operator/direction/config: invalid_config; negative/out-of-range k/h or timestamp overflow: bounds; source/session/cutoff/origin/basis mismatch: inconsistent_identity; nonfinite/nonpositive input price: bounds; finite-input nonfinite ratio/return: numerical_bounds; positive-ratio underflow-to-zero: precision_bounds. Ordinary missing/unavailable supplied features/endpoints use result states, not exceptions.
