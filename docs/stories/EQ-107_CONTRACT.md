This is the proposed contract for [EQ107](https://github.com/atulsrivas1/equity-features/issues/207), not an implemented or qualified ledger. [EQ106 acceptance](https://github.com/atulsrivas1/equity-features/issues/206#issuecomment-6205931841) supplies the unchanged event profile. EQ097 is accepted. The [exact profile](EQ-107_PROFILE.json), [independent oracle](EQ-107_ORACLE.json), [literal vectors](EQ-107_CASES.json), [boundary cases](EQ-107_BOUNDARIES.json) and [qualification plan](EQ-107_QUALIFICATION_PLAN.md) complete this packet; separate readiness review precedes implementation.

## Exact identities, logical limits and errors

Keep EQ106 canonical event bytes<=16384, <=16 earlier references and exact scalar/clock/missing/redacted/truncated semantics. The ledger admits at most4096 events and33554432 canonical event bytes. Reserve those logical counts before INSERT in the transaction. SQLite pages, indexes, journals, old backing, kernel memory and nodes are outside these counters; they are not physical quotas or hard deadlines.

`Checkpoint(chain_id, sequence, head_hash)` is immutable and revalidated at every boundary. Chain identity is the exact EQ106 ASCII namespace pattern `[A-Za-z][A-Za-z0-9_.-]{0,62}:[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`, <=128 characters. Sequence is an exact non-bool integer0..4096. Hash is lowercase64hex; sequence0 requires the all-zero genesis hash. A checkpoint is a supplied assertion, never authenticated trust.

Checkpoint JSON has exactly domain=`equity-feature.agent-checkpoint`, schema_version=`1`, canonicalization=`agent-checkpoint-json-v1`, chain_id, sequence and head_hash. Encode sorted ASCII JSON with no insignificant whitespace and separators `,`/`:`. Decoder accepts exact canonical bytes, <=1024bytes. Validation order: exact bytes type, byte cap, ASCII/JSON syntax and duplicate-key rejection, exact root keys/domain, version/canonicalization, chain identity, sequence type/range, hash/genesis consistency, canonical byte equality. Independent empty/nonempty bytes and hashes are frozen in the oracle.

Export `LedgerError(ValueError)` with a fixed payload-free code: invalid_schema, unsupported_version, limit_exceeded, inconsistent_chain, inconsistent_reference, duplicate, stale_checkpoint, busy, storage_error, outcome_unknown or closed. Invalid namespace/hash/types are invalid_schema; a negative sequence is invalid_schema, >4096 is limit_exceeded and a nonzero genesis hash is inconsistent_chain. Map input event errors exactly as specified in the profile; stored decode/row/hash disagreement is inconsistent_chain. Never put paths, SQL, event data or raw SQLite messages in public text. Private exception causes are caller-controlled logging material.

## Public result construction

The profile freezes exact Enum member names/values and constructor signatures, validation order, immutable copies, bounds and cross-field errors for Verification, PageVerification and Reconciliation. Strings cannot substitute for status enums; bool cannot substitute for counts. Verification count must equal its checkpoint sequence, with consistent logical byte bounds. PageVerification retains at most1024 distinct content references, rejects split/conflicting identities and resolved/unresolved intersection, and always reports prior membership/global uniqueness as not_verified. Reconciliation requires observed for found_exact, forbids it for absent/base_not_covered, and checks observed against its current head. Arbitrary constructed results assert structurally consistent fields; only verification/reconciliation operations compute the corresponding history facts. Direct construction or object-forging never establishes authentication.

## Store schema and opening

The exact two-table SQL, columns, constraints, unique event_id index, application_id EAL1 and user_version1 are in the profile. Store canonical event bytes with mirrored sequence/event_id/kind/previous_hash/digest/byte_length. Singleton metadata binds chain/count/head/total canonical bytes. Verify complete table/view/trigger/index/column/collation inventory, including the automatic unique index; extra or incompatible schema refuses. There is no migration/repair hook.

`Ledger.create(path: str, chain_id: str)` requires a nonempty absolute exact str <=4096characters, no NUL, and an exclusively reserved new regular file. It refuses any existing destination. `Ledger.open(path: str)` uses an internally quoted SQLite mode=rw URI, never creates an absent store and never accepts caller URI options. Final symlink/regular-file checks are local preconditions, not race-free hostile path security. A failed new initialization leaves its owned path for explicit caller handling; it never deletes or overwrites another destination.

Creation selects DELETE rollback journaling, synchronous FULL, foreign_keys ON, trusted_schema OFF, extension loading disabled and timeout/busy_timeout0, with effective readbacks. Opening queries the existing journal mode/version first, rejects WAL/other unsupported profiles without converting or assigning persistent version IDs, then configures only supported connection-local settings. SQLite hot-journal recovery may physically write during supported open/read; there is no application logical repair. Fixed C/runtime/filesystem operations can block despite timeout0. No general power-loss, disk-failure, hosted recovery or hard cancellation guarantee follows.

Open fully validates one consistent read transaction: exact schema, quick_check/foreign-key checks, canonical event decode, contiguous sequence1..N, one chain, genesis/linkage, recomputed digests, mirrored row fields/size, global IDs, actual earlier reference identity/kind/hash, logical count/bytes and metadata/head agreement. Stream with bounded indexes and stop on excess limits. Empty requires count0/hashgenesis/bytes0. Unknown/corrupt state refuses rather than silently replacing an empty prefix.

## Append and acknowledgment

`append(event, *, expected)` accepts and revalidates an exact public EventRecord and Checkpoint. Use explicit BEGIN IMMEDIATE/COMMIT/ROLLBACK under the frozen CPython3.12 connection profile. Use separate connections per writer/thread; timeout0 lock contention returns busy with no internal retry. Inside the transaction validate profile/head/last row and exact expected checkpoint; require next sequence N+1, previous hash and chain; enforce ID uniqueness, resolve <=16 prior references through ID/sequence indexes and canonical target bytes, then logical quotas. Insert event and update metadata atomically.

Missing ID/partial/split lookup, wrong kind or wrong digest refuses inconsistent_reference. In a valid complete prefix every earlier sequence exists, so a missing ID normally has an existing but different sequence target; do not fabricate a both-absent reachable case. A genuinely missing stored row is earlier integrity failure. Corrections append while retaining original/replacement records; no edit/delete/redaction of stored bytes.

Return the new checkpoint only after COMMIT succeeds. A COMMIT exception may have committed: poison/close the connection and return outcome_unknown. A precommit refusal is known only after successful rollback; failed/uncertain rollback also poisons/closes and returns outcome_unknown. Never replay automatically or infer rollback solely from a caught exception/in_transaction becoming false. Preserve exact proposal and prior checkpoint for reconciliation. An acknowledgment does not authenticate an event, continuously recheck old rows, retain an external anchor or guarantee hardware durability.

Indexed append validates head and referenced rows rather than rereading the whole history. Out-of-band changes to other earlier rows may remain until explicit verify/reopen; there is no continuous tamper authentication. `head()` returns a validated stored head/row pair, not a fresh whole-history proof. `close()` is idempotent and closes only this connection, never deletes files. An underlying close failure is not physical cleanup success; poisoned/closed objects deny further operations.

## Full verification and anchors

`verify_events(events, *, chain_id, expected=None)` always requires explicit chain identity, including empty input. Exact list/tuple input is bounded to4096events/32MiB; perform one pass with ID/sequence/reference summaries, not repeated whole-chain copying. `Ledger.verify(expected=None)` performs equivalent checks over one consistent database snapshot plus schema/metadata integrity. Return Verification(head, anchor_status, verified_events, canonical_event_bytes) only for internally valid input; integrity violations raise.

Anchor status is separate: not_supplied, matched_terminal, matched_prefix, mismatch or not_covered. A covered wrong hash/chain is mismatch; a later expected sequence absent from the supplied prefix is not_covered; an earlier matching anchor is only matched_prefix. Only matched_terminal satisfies that expected full terminal request. Empty unanchored history has the explicit chain/zero genesis/not_supplied; matching expected genesis matches_terminal and a later expectation is not_covered. Genesis is not useful authenticity. A valid shortened prefix or replaced chain can be internally consistent; detecting it requires separately retained trusted expected count/hash. No signatures, witness service or R13 trust product is introduced.

## Contiguous pages and as-of meaning

`export_page(after, through, limit=64)` requires the same explicit through checkpoint for every page. Use one read transaction per call, verify its terminal still exists, derive before/after from actual canonical rows and return only contiguous `(after, through.sequence]`, excluding later appends. This fixes a logical prefix, not one SQLite transaction across calls. Maximum64events/1048576 summed canonical event bytes. Empty is allowed only at before=after=through. Page has immutable before/after/through checkpoints and detached event tuple.

`verify_page(page, *, start, through, prior=())` checks both explicit caller checkpoints, canonical rows, sequence/linkage and page after; a self-declared shorter terminal cannot satisfy the caller terminal. Prior context is exact list/tuple <=64events/1MiB, same chain, sequences<=start. Resolve supplied full references with ID/sequence indexes; missing context remains unresolved. Returned resolved/unresolved references mean supplied-content matches, not earlier-prefix membership. Report prior global uniqueness and prior membership as not_verified. reached_terminal only means the validated page reaches the caller terminal; it is not whole-history/authenticity certification. Full verify_events from genesis or full store verification owns global checks.

The as-of view is a contiguous recording-sequence prefix, not arbitrary timestamp filtering or knowledge admissibility. Occurred/recorded times may be equal or decrease. Redaction happens before append; later correction/disclosure does not erase plaintext or backups. No retention/deletion API or replay of absent content is promised.

## Unknown-commit reconciliation

`reconcile(event, *, expected_before)` first refuses closed/poisoned state, then copies/revalidates the event and prior checkpoint in that order. Before reading the store require matching proposal/prior chain, sequence exactly expected_before.sequence+1 and previous_hash exactly expected_before.head_hash, in that order; any disagreement raises inconsistent_chain. An invalid proposal never inherits absent/found/base-not-covered semantics. A self-consistent foreign-chain pair is instead a store conflict. A generic valid sequence4097 proposal may be reconciled against checkpoint4096, without granting permission to exceed append limits. Only then fully verify a consistent current snapshot and compare the exact proposal at expected_before.sequence+1. Check base coverage/hash first. found_exact requires identical stored canonical bytes and correct prior hash; later appends do not erase the result. absent_at_unchanged_head requires neither ID nor next row and current head exactly equal the prior checkpoint. A different next event, changed bytes under the same ID, wrong chain or covered mismatched base is conflict; an unavailable prior prefix is base_not_covered. Return current head and optional actual observed reference. Foreign-chain or mismatched covered base returns conflict with no observed reference; missing later base returns base_not_covered with none. Otherwise exact canonical ID/sequence match wins; conflict observes the existing ID row first, or the next-sequence row when the ID is absent. The profile fixes this precedence. Never mutate or return an automatic replay permission. Local observations cannot prove historical non-occurrence after out-of-band replacement.
