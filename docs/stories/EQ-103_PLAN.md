True is reserved for complete exact expected inventory with every actual full verified readback. verification_mode=live records that the fixed operational entry point was invoked; it is not an authenticated execution attestation. Backend errors normalize to readback_failed, not a synthetic waiting-success flag. Existing cooperative blocking/error limits remain; no hard deadline or synchronous callback cancellation promise. Invalid/mismatched records raise fixed payload-free ProvenanceError codes invalid_schema,unsupported_version,missing_provenance,inconsistent_binding,limit_exceeded,readback_failed. Bounds: at most16tasks per live request, exactly one trades role per supported task, at most512rows/16columns/8192cells per supplied batch and at most1MiB accepted canonical bytes per task, aggregate16MiB/131072cells. ## Generation return shape and public error boundary

`bind_supplied_provenance` returns one ProvenanceReport for one expected task. `verify_live_generation` returns a distinct frozen `GenerationProvenanceReport(generation_key, generation_identity, expected_tasks:tuple[str], task_reports:tuple[ProvenanceReport], generation_status, operational_readback)` for the exact at-most16 task inventory. Status/operational fields are init=False defaults waiting/False until the trusted entry point finishes; no downstream API trusts this record as execution authority. Each task report keeps its original anchors/input links even while output publication is absent. Complete only follows actual accepted store.read plus exact verified barrier full-result/receipt inventory. Waiting does not identify unobserved backend statuses from declared output omissions.

All supplied task inputs/results/anchors are checked before any live store operation, including tasks whose output is not yet published. The resumed native test can precompute A/B results once, publish only A, reopen the same store and observe waiting, then publish retained B and observe complete without a new acquisition/compute. TaskEvidence snapshots are newly constructed for output progression; original batches/configs/results/receipts never mutate. Public Python argument arity/type syntax errors remain normal Python errors; values crossing the supported typed entry points receive fixed ProvenanceError. No report or publicly constructible GenerationOutcome is accepted as a substitute for an exact GenerationStore in live mode.
