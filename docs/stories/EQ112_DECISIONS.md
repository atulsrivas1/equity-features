# EQ112 exact result schema and reviewed design decisions

Proposed normative decisions before public readiness; no runtime implementation or executed-kernel claim. This records dispositions of review5e6c9265/a09bff41 and targeted correction review468b0f16. Preserve earlier drafts/reviews as history. Current quality rules include the final correction section.

LIT01: Initial capability admits raw prices only, with exactly AdjustmentSpec(raw,raw-v1,none,none). Reused non-raw split/total_return or custom raw policy/action/anchor is rejected with ContractError(unsupported_adjustment). No claim that a historical price known_at proves a later action snapshot was known. This replaces V3's proposed admission of distinct adjusted snapshots. Existing core AdjustmentSpec and adjusted kernels remain unchanged; broader new capability needs its own original action-availability contract and fixtures.

LIT02: The complete result payload has exactly algorithm_version,operation,config_digest,input_digest,status,roles,metrics,selected,top_k,population_count,available_at_ns. Both digests are lowercase64hex of own canonical config/input envelopes. metrics is an ordered two-item tuple of(id,value), where value is null or reduced Rational(numerator,denominator); basis/premium,freeze_max_abs/freeze_mean_abs,reopen_gap/reopen_premium respectively, all prefixed cross_venue. roles is exactly the seven ordered roles from the closed-schema proposal. Each has role,status,reasons,proofs; status is ready,unavailable,blocked or not_applicable. blocked means no event/population exists to evaluate that dependent role, has no reasons/proofs, and does not invent an additional failure. Explicit failed roles are unavailable. An empty freeze continuous role is not_applicable/observed_empty, conversion is ready with no proofs. Ready-to-return metrics require every required role ready, except the admitted empty path. No rational arithmetic is attempted on a missing-input/incomplete result. Structural validation of all supplied records/config still precedes quality; malformed data cannot hide behind missing prerequisites.

selected holds ordered(role,observation_id) references: continuous rows in chronological order then the reference; the IDs are per-leg domains, so the same textual ID across legs is admitted and disambiguated by role. top_k contains(role,observation_id,reference_id,conversion_fact_id,deviation) witnesses with an exact signed rational deviation; order follows abs magnitude, then event/order/UTF8 ID. population_count is all continuous freeze rows (even when quality prevents metrics), otherwise null. Unavailable metrics and available_at are null; selected known market candidates remain bound where selection is defined. Roles' proof references use JSON pointers into the full input envelope payload: scopes+coverage for coverage roles, selected observation records for price roles, consumed feed fact records, and consumed conversion facts. A pointer binds the entire referred record through input_digest; there is no external URI or executable dereference. Config and complete input identities, including unused supplied records, remain bound. Result's own canonical envelope SHA256 is a separate serialization identity, not a recursive payload field.

Proof ordering is input collection order for feeds/conversions, chronological selected order for observations, scope then coverage then coverage_known_at for coverage. Deduplicate identical pointers only. Role reason order/deduplication follows the closed vocabulary. Coverage proof problems do not suppress otherwise independent price/feed/conversion role assessment; missing selected continuous event blocks reference selection in basis and dependent feed/conversion event checks. Conversion on empty freeze is not required; supplied facts still validate structurally. All required readiness must be assessed before rational arithmetic; otherwise-overflowing prices with a missing required mapping are unavailable without arithmetic overflow.

LIT03: order_key is exact nonbool nonnegative int64, zero admitted. IDs are nonempty strings with no leading/trailing whitespace,<=128UTF8bytes; Unicode code points are not normalized. Lexical ID ordering is encoded UTF8 byte order, independent of locale. Observation IDs are unique within each leg; duplicate rows/revisions for one per-leg ID fail duplicate, while cross-leg same ID is allowed. LIT04: Normalization stages are fixed: Fraction(p,10**s), then Fraction(scaled.numerator*D,scaled.denominator*N), reducing before each supported-stage cap check; do not cap unreduced integer temporaries. ## Completion of the two77-record quality contradictions

For an empty continuous freeze population, its role is not_applicable/observed_empty only when every non-population prerequisite is ready. Otherwise its role is blocked with no reason/proof; the independent incomplete/missing prerequisite remains the cause of the unavailable overall result. This prevents an empty ready price role from implying observed data. If no held reference exists, reference_feed is blocked with no proof because its required selected-live-event check cannot be made; a scheduled-freeze window alone cannot establish that role ready. Continuous whole-window feed assessment remains independent and can be ready on an empty complete population. Conversion is ready with no consumed proof for empty population, since no event requires conversion, regardless of the independent prerequisite failure.

Unrelated feed/product or conversion instrument-pair facts are bound in input identity but never consumed merely because their effective intervals overlap. A supplied foreign-domain late/unknown fact cannot delay or repair the selected pair. Matched-pair identity/units are checked against its legs; unrelated facts still validate their own exact fields/types/positive ratios/bounds/nonoverlap. The additional78th control includes one future unrelated conversion and unknown unrelated feed; full input digest changes, metrics/consumed proof references/available_at remain as the baseline.

Cross-leg mismatch failure is assigned to both continuous and reference price roles, with the same reason mismatch and each role's own selected observation proof. Per-leg staleness remains assigned to that leg only. Constructor Rational(n,d) reduces before cap checks; the strict codec admits only already reduced numerator/denominator fields. The separate6constructor boundaries and large-rational subtraction/comparison case distinguish these semantics. Unreduced comparison temporaries may exceed10^38, while supported reduced operands/results must fit. Result bytes over1MiB are ContractError(bounds) before parsing; from_json noncanonical2/2 is invalid_schema. Calculations must cap their result envelope before returning as well as before serialization; no valid numerical outcome is returned with a silently omitted witness/proof to fit the cap.
