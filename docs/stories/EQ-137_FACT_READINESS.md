# EQ137 exact pre-code supplement: facts and feature warm-up

This supplements the [public packet](https://github.com/atulsrivas1/equity-features/issues/471#issuecomment-6263736298) before Ready/code. It clarifies preparation-family readiness; EQ136's feature mathematics and result quality remain unchanged.

`anchored_closes` and `true_ranges` expose admitted facts over the supplied epoch, not the warm-up of a particular indicator. Their expected count is the actual unique operand-slot union in anchor..target. They can be available when those supplied facts qualify even if a future output still lacks its seed history. With a single admitted close anchor, anchored_closes has one value and true_ranges has an empty TR vector, both fact views expected1/observed1; neither invents a first TR. ATR output remains insufficient_history, expected N+1/observed1. EMA and RSI independently apply their N and N+1 close requirements; sharing this fact view cannot make either wait for the other's readiness.

`price_moments`, `high_extrema` and `low_extrema` are derived finite-window views requiring the last N slots inside the current epoch. If fewer exist, expected=N, observed is the actual qualifying slot count and status is insufficient_history (after the defined absent-input precedence). `simple_returns` requires the target and its immediate within-epoch predecessor, expected2; at the first close anchor it is insufficient_history with observed1 when that close qualifies. Pre-anchor observations cannot fill that reset/carry epoch warm-up silently.

The builder's generic N bound is1..4,096. Raw fact families and latest simple return do not acquire a different mathematical dependency from N, though exact config identity remains bound. Internal moments/extrema allow N1 (population variance0 for one complete price); this does not advertise band N1 or RSI/ATR out-of-range support. Feature dispatch retains the accepted per-output period limits and seeds. Derived unavailable family values remain None; zero-length admitted TR facts remain a legitimate empty vector and are distinguishable from missing delivery/coverage.

The complete-family projection retains these fact/derived readiness distinctions, actual source bindings/counts/reasons/units/evidence and exact values. Output kernels derive their own warm-up quality from those compatible facts; no global family or cross-feature status substitutes for it. Producer tests must include one-, N- and N+1-close cases, proving EMA can qualify before RSI while using the same admitted facts, and ATR cannot substitute H-L for a missing predecessor/TR seed. This is planned behavior, not executed producer or feature implementation.
