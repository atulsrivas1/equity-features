# Observable publication metadata amendment

Proposed by coordinator /root for fresh independent review. This amendment preserves the original V4 contract and fixture files as historical evidence. The accompanying publication fixture changes only 58 successful `expected_result.metadata.math_policy_version` literals from `observable-v2` to `v1`. All 89 input packets, configurations, numerical values, units, initialization, coverage, quality, evidence and 31 intentional errors are unchanged. The X15 invalid candidate remains unchanged.

Actual worker source integration reached publication and failed three tests with SDK `INCOMPATIBLE_VERSION`. Generic canonical constructors had accepted the label but did not establish SDK publication compatibility. The existing SDK and DuckDB sink support global math policy `v1`; extending their version allowlists would change unrelated protocols without a mathematical requirement.

Feature algorithm identity and global math-policy identity are independent, as described in VERSIONING.md and api/REMOTE_TRANSPORT.md. The new observable feature semantics remain `observable-v2`, including every feature column and ConfigSpec. Context remains `ef1-observable-context2`, mapping remains `ef1-observable-map2`, backend remains `ef1` version `0.0.4a5`, and canonical schema remains `1`. Exact integer nanoseconds, explicit integer second-floor calculation, typed nullable values, quality and bounded evidence fit the existing global `v1` policy; no new global rounding, precision or canonical representation rule is introduced. Existing composition restrictions remain intact.

Successful result metadata and corresponding task manifests therefore use global `v1`. Remove the candidate generic TaskManifest observable-policy extension and preserve its existing `v1` rejection guard. Closed observable routes continue requiring algorithm `observable-v2` and the exact backend, context, mapping, role and source contracts. Unknown global policies must still fail. SDK, sink, codec and canonical schema require no version or guard change.

`OBSERVABLE_PUBLICATION_FIXTURES.json` is the authoritative successful-result publication binding only when read with this amendment and the preserved V4 design. Its retained historical `input_transport.unchanged` sentence and proposed-stage labels do not override this explicit correction. The JSON amendment records original and amended hashes and every changed packet. This is a metadata correction within the admitted bounded subset, not release acceptance or an original-source parity claim.
