# EF1 status input slots and deterministic proof selection

Coordinator proposal for independent review before final status integration. Existing ef1-contract1 ledger bytes/hashes remain historical and unchanged. This clarifies source-authoring representation and ambiguous certificate admission; it adds no feature IDs, canonical schema, result codec or worker wire fields. Current EQ165 status subset only; original remaining scope/gates stay intact.

1. **Explicit missing roles at the pure entry point.** Status compute requires a concrete tuple/list of exactly four slots in canonical order calendar_provenance, status_states, status_prefix, status_validity. Each slot is an actual CanonicalBatch or None. None means missing delivery; a present zero-row batch retains its declared position and actual metadata. Reject shortened/extra/noncanonical slots before result construction. Never infer role from row vocabulary, source IDs, revision, presence, or observed row count. The public compute annotation widens to include None for status; existing anchor/clock calls and present-only shapes stay compatible and continue rejecting None. This is an in-process missingness marker, not a new canonical transport record.

2. **Worker and adapter boundary.** WorkItem/TaskManifest still contain only present CanonicalBatch objects and their existing complete/missing manifests. After ordinary admission, require exact four manifest roles/order and walk them mechanically: missing binding yields None; present binding consumes the next original admitted batch. Reject leftover/unconsumed batches; do not zip shortened present batches against four declarations. Never create a fake batch or alter a present object. Every present role contributes its original InputBinding; ResultMetadata retains existing canonical lexical role sorting, independently of declared pure-slot/task-input order. StatusInputs exposes `.slots` for direct pure calls and `.batches` for present-only worker input. A zero-row batch's caller-assigned position is authoritative; no row vocabulary exists to infer a hidden former role. Wrong-role tests require populated contradictory vocabulary or independently contradictory metadata. Partial missingness and actual covered-empty input remain distinct for all adapters. The same library entry contract applies to synthetic and observed sources.

3. **Narrow deterministic base64 operations.** Permit only explicit `from base64 import urlsafe_b64decode` and/or `urlsafe_b64encode` in pure calculations (aliases allowed). Do not allow `import base64`, star import, other names, or mixing an admitted name with encode/decode file helpers. Keep every existing denied operation. Validate reference grammar alphabet, no padding, strict UTF8, decoded safe labels, bounded lengths and exact re-encoding before accepting identity. The library author does not edit guards; coordinator authors and independently reviews the narrow policy plus positive/negative controls.

4. **No certificate arbitration or stitching.** Preserve all original prefix/validity grammar, target input/source/revision/namespace/entity/epoch and coverage/knowledge rules. Validate every present row structurally, including irrelevant rows. A selected prefix certificate individually covers seed original effective time through C (start<=seed_time and C<=end); a selected validity certificate individually contains C (start<=C<end). Multiple interval fragments do not jointly fabricate one full-scope certificate. More than one structurally applicable certificate for a role is ambiguous and rejects DUPLICATE; knowledge eligibility never selects among overlapping certificates. Distinct nonapplicable intervals may coexist without inferring completeness. Preserve existing missing/incomplete/late/expired status/reason precedence. A null seed_reference_id remains an absent selected seed; never infer it from seq0 or the first delivered row. Positive S01-S03 fixtures explicitly select their original seed row.

5. **Bounded selected-event witness.** When the complete causal proof establishes the actual current last event, emit a canonical EvidenceRow for each selected state/age output with that original status input_id, reference_id, effective event time, original known_at and original effective bounds. A max-age rejection can mark the state witness excluded/ineligible while its proved descriptive-age witness remains consumed. If current-event identity is not proved, do not label a last-observed event as the current witness. Existing actual input bindings remain complete and unchanged; source rows are never mutated, copied into context or silently discarded from caller-owned inputs. Result evidence is a bounded selected witness, not a complete copy/audit of up to4096 input rows. This amendment does not require unbounded evidence or authorize truncation.

   Witness admission is strict original event_ns=effective_start_ns<C, nonnull original known_at<=K in both requested availability modes, independently of generic REFERENCE/reconstruction allowances. Normal state and age each carry one consumed witness; explicit max-age rejection carries an excluded/ineligible state witness and consumed age witness. No current witness is emitted if prefix, transition knowledge, validity or state interval fails to prove current identity.

6. **Absent-state relations and factual prerequisites.** Validate every present proof row's complete grammar, labels, dimension/epoch, role vocabulary, bounds, namespace/entity and canonical order before semantic selection. If states are present (even empty), every proof binds the actual states input_id/source_id/snapshot_id. If states are missing, validate mutually coherent decoded target P and source_id/snapshot_id across all present status proofs without inventing an absent population's actual input identity or comparing P to proof input_id. Calendar source/revision remains separate. Factual state/age stay absent_input when states are missing, after structural contradictions reject.

   Prefix completeness and eligible required transitions must first establish current-event identity before semantic state-validity expiry and maximum-age evaluation are applicable. Continue structural validation of all later-proof rows even when this prerequisite fails. This preserves the literal S02 C17 fixture: prefix_end16 yields incomplete_coverage/governed_gap and incomplete_status_prefix, without asserting an expiry of an unproved current event from validity_end17. When the prefix is complete, validity_end=C yields missing_input/ineligible and outside_effective_interval, as its separate frozen mutation requires. Retain every independently applicable reason; dependent facts that cannot yet be established do not fabricate additional reasons. This adds no last-observed fallback.

7. **Request bound.** The existing max_reference_rows4096 is an aggregate bound over all present REFERENCE rows in this status call, including calendar and certificates. It is not4096 per slot and does not override actual smaller task admission limits. Retain overflow checks, caller-supplied unknown population counts and all other schema/transport budgets.

Independent fixture obligations: each missing slot and all-four-missing, present empty slot identity, wrong role at a present slot, shortened/extra slots, strict identity/reference encoding controls, multiple disjoint/applicable certificates versus rejected overlap and fragments, seed absent versus exact original selection, original known-at in both requested modes, S01-S03 exact tuples, and state/age witness identity including stale-state age.
