# Source-bound CI orchestration

CI002 changes internal qualification routing, without changing calculations, package APIs, versions or dependencies. [Plan](stories/CI-002_PLAN.md), [contract](stories/CI-002_CONTRACT.json), [preserved operations](stories/CI-002_WORKFLOW_EQUIVALENCE.json), [local validation](stories/CI-002_VALIDATION.json). Implementation and local tests are distinct from completed hosted qualification and release acceptance; the linked issue/Project records current status.

Every push and pull request starts `qualification.yml`. The scope job runs the [complete committed-source classifier](CI_SCOPE.md). Documentation/reference checks always run. Sixteen reusable package roots run only after successful valid FULL classification. The terminal `check` runs after every logical dependency, even when a dependency fails or is skipped, and validates their complete original results. It does not turn skipped package work into successful package qualification.

Only changes confined to existing regular UTF8 versions of the three reviewed reader pages can select DOCS. Packaged continuity documents, workflows, tools, fixtures, metadata and unknown paths select FULL. Unsupported or invalid source binding cannot qualify a successful aggregate. Classifier v1 supports branch pushes and pull-request merge checkouts; unsupported event/ref forms are rejected. Initial branch creation is valid FULL and makes no comparison/absence claim. Manual evaluation dispatch remains the original separate workflow, with its original required study reservation and predicates; R16 does not select a study.

FULL retains the original 33 executed jobs and adds scope/check, for 35 executed jobs. DOCS executes scope/docs/check and omits 32 package executions. Actual API records for omitted reusable calls must be reconciled separately from executed job counts. FULL therefore adds orchestration cost; no universal speedup or threshold is claimed. Routine release changes containing packaged continuity prose remain FULL.

## Required aggregate

The terminal job receives `toJSON(needs)` as environment data. Its eighteen exact logical keys are scope, docs and the sixteen literal package roots in the contract. Source scope and docs must succeed. FULL requires all sixteen package successes. DOCS requires all sixteen expected skips. Malformed/missing/extra fields, non-string results, invalid or changed classification, duplicate JSON keys, nonstandard constants, failures, cancellations and unexpected execution/omission reject qualification. It recomputes classification from the actual event and checkout rather than trusting a recorded decision alone.

The root grants only contents:read/actions:read, with existing leaf permissions preserved. Literal same-commit local reusable paths retain the existing builders, OS matrices, pins, typing, mathematical fixtures, archive/source/installed/RECORD assertions and qualification commands. The immutable baseline fixture compares their permissions/jobs bytes after reversing only the documented trigger/upload migration and added docs tests. No branch-protection or account administration is part of this change.

## Source policy and artifact identity

`ci_provenance.py` emits `dist/ci/policy/qualification.json` after successful logical gate evaluation. It binds repository/event/ref, actual run ID/positive attempt, checkout head/tree, workflow ref/definition SHA, classifier record, original logical results and every tracked canonical Git blob. Entries contain the Git blob ID, regular mode, byte length and SHA256. It reads the complete immutable tree/batch object stream and checks Git blob framing; duplicate/malformed/nonportable paths, symlinks, gitlinks, unknown modes and missing/corrupt objects reject this version. Executed root tool working bytes must match their declared blobs. Every declared workflow-definition blob must match its checkout counterpart; definition SHA and checkout SHA may differ when those definitions are identical.

The sidecar stage is `GATE_EVALUATED_NOT_FINAL_RUN_ACCEPTANCE`. Its success field records procedure outcome before the workflow finishes. It cannot attest its own completed run, upload receipt, platform implementation or physical cleanup. The outer independent collector must join actual registered workflow/run/event/attempt, PR merge parents/tree or push source, actual OS jobs/steps, immutable artifact identities/digests/expiry and package verification proof. Existing Actions/runtime/interpreter/native dependency boundaries remain explicit.

Root artifact names include checkout/event/run ID/attempt. Normal package artifact names retain their prefixes and source/OS fields and add `-attempt-N`; evaluation retains its event field. Historical accepted artifact IDs/readers and manual evaluation upload names remain unchanged, including quickstart's fixed accepted foundation proof. New policy evidence is separate from the historical scope of package verification archives.

Use exact run-ID artifact queries and a complete same-attempt job inventory. A failed-jobs-only partial rerun cannot establish complete both-OS/form qualification. Do not reuse artifacts or successful jobs from earlier attempts. Earlier failures and cancelled planning runs remain separately recorded. Required fresh output files, no overwrite, 30-day retention and upload errors are part of the gate. Rejected producer output uses a fixed error schema and nonzero exit; stale output cannot make a failed job qualify.

## Verification and rollout

Run `python tools/test_ci_gate.py` and `python tools/test_ci_provenance.py` for synthetic CI/Git fixtures. The existing classifier suite remains `python tools/test_ci_scope.py`. These fixtures do not prove a real GitHub orchestration run, installed package forms or failed production gate. Independent source review and actual current candidate/main FULL qualification are required before CI002 acceptance. CI003 additionally supplies an actual reader-only DOCS case, reviewed deliberate negative probes, final current artifact/archive/RECORD audit and release reconciliation. No whole R16 completion follows from a passing local suite.
