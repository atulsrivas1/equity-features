# EF2 Ichimoku and price-channel implementation

[EQ-151 #485](https://github.com/atulsrivas1/equity-features/issues/485) and [EQ-170 #511](https://github.com/atulsrivas1/equity-features/issues/511) library layer: the six pure `ef2.*` producers `ichimoku`, `keltner`, `donchian`, `pivot_levels`, `band_width_percentile` and `bollinger_keltner_squeeze` (algorithm `ef2-channels-v1`, contract version `ef2-v1`, 25 headers under `trend.ichimoku.*` and `channel.*`) in `packages/intraday`. The frozen [contract](ICHIMOKU_CHANNELS_CONTRACT_PROPOSAL.md) (decisions D1 to D15, rulings O1 to O12 and its coordinator freeze) governs; this slice implements it and redefines nothing. The EF2 I/O mapping (#609), worker (#610) and release acceptance (#486) layers remain separate.

## Structure

`_channels_config` (builder, closed decoder), `_channels_registry` (own catalog and digest), `_channels_math` (operands and Decimal120 recurrences) and `_channels` (readiness, quality, evidence, dispatch). The R17 admission, context, `anchored_closes` and `true_ranges` arithmetic and the per-slot readiness assessment are reused unchanged. The additive internal operand families (ruling O3) are `rolling_extrema_at` (high and low extrema of the `P` bars ending at an arbitrary slot, with the two sides readable independently), the window-end-offset `rolling_moments_at` and the exact squared band-width keys used for ranking, `prior_session_bars` for the pivots and the unrounded `ema_atr_decimal` chains. The R17 preparation record and catalog are untouched; the channels catalog is separate (`describe_channels`, `channels_catalog_digest`), so `describe_intraday()` still lists exactly the eight accepted R17 IDs and its digest is unchanged.

## Mathematics and numeric policy

R17 policy: exact `Fraction` arithmetic where the contract is rational, ordered Decimal recurrences in a fresh local context (precision 120, ROUND_HALF_EVEN, R17 traps), one guarded float64 conversion, exact zero published as `+0.0`, whole-call `OVERFLOW` on arithmetic failure. Ichimoku, Donchian, pivot and percentile values are exact rationals converted once (correctly rounded). Keltner and the squeeze consume the unrounded Decimal120 EMA and Wilder ATR chains written exactly as the R17 `indicator` recurrences (a Decimal-returning copy, so R17 sources are not edited); `channel.keltner.middle` equals R17 `intraday.ema` bit for bit. The percentile ranks by integer cross-multiplication of the exact key `(N sum c^2 - (sum c)^2) / (sum c)^2` (the squared width up to the common factor `4 k^2`), target excluded, ties counting half, result `(2 Lt + Et) / (2 c)`. The squeeze decides the inclusive relation by exact algebra on the Decimal120 operands (`x >= 0 and x^2 >= k^2 V`, likewise for `y`) and publishes the signed gaps from one Decimal square root.

**Exact-zero limit (release-gate item).** `+0.0` is guaranteed only for the contract's marked zero fixtures and operands that are exactly representable (flat bars, equal integer extrema, integer rank counts, `ema_period` 1 and `atr_period` 1 squeezes with representable roots). Where the EMA or ATR is non-terminating in decimal (for example 110/9 or 37/3 with `ema_period` 2 to 7 and tied bars), an exact-zero squeeze gap can be published as a Decimal120 residual of about 1e-119 or -1e-118 instead of `+0.0`, and `channel.squeeze.bollinger_inside_keltner` can flip to false on an exact boundary tie (the inclusive relation is decided on the Decimal120 operands). An independent review found about 2% of 1,187 exact-zero gaps in a 400,000-configuration random search deviating this way. Values are deliberately not snapped to zero and the arithmetic is unchanged, as for the EF2 momentum slice. Release acceptance must account for this.

## Readiness, counts and evidence

Every header owns its closure slots and fields (conversion and base lines and observed spans: high and low of their window; displayed spans: the window ending at `t - d`; `lagging_line_observed`: the close at `t`; `lagging_line_reference_close`: the close at `t - d`; Keltner and squeeze: close on every epoch slot and high/low from the second; Donchian upper reads only highs and lower only lows; pivots: high and low of every slot of the immediately preceding governed session and the close of its last slot; percentile: the closes of `c + N` bars), so an unrelated gap, null or absent column never blocks it. A window that would reach before the anchor is `insufficient_history` with the closure truncated to the anchored grid (observed counts the slots that exist). Status precedence is `missing_input`, `insufficient_history`, `incomplete_coverage`, `available`, with every applicable reason in enum order; no delivery gives only `absent_input` with observed 0 and the expected closure size. A context without a preceding session is `missing_input/absent_input`, expected 1, observed 0 (ruling O8). A `missing_input` header has no evidence rows; otherwise evidence follows R17 (consumed or knowledge-excluded supplied rows, `slot:<index>`, `completed_interval`, sorted by feature then slot, truncated to the result-wide `evidence_limit`).

## Points the contract leaves open (implemented conservatively)

1. **Header selection.** The contract returns the complete sorted header set of a producer but also requires `UNKNOWN_FEATURE` (RF17). `compute_channels` therefore takes an optional `features` tuple that defaults to the complete set; any ID outside the producer is `UNKNOWN_FEATURE`.
2. **Convention label.** `convention_version` is a closed config parameter whose single legal value is the producer's label; the builder defaults it, and any other value is `INCOMPATIBLE_VERSION`.
3. **Cutoff refusal (RF01).** The config builder already requires the market cutoff to cover the target slot end, so a bar ending after the cutoff is reachable only through admission (`BOUNDS` there and in the builder).
4. **Context mode (RF21).** A non-reset context is `INVALID_CONFIG` in both the builder and the decoder, before any identity comparison.
5. **Package version and digest.** Changing `PACKAGE_VERSION` would change the R17 catalog digest and every R17 result's metadata, which this slice keeps byte-identical, so `0.1.0a3` is unchanged. The channels digest includes it.
6. **Absent price unit.** The builder rejects a non-`PriceUnit` (including an absent one) by type check as `INVALID_CONFIG`; the decoder reports a config without a price unit as `INVALID_UNIT` (RF12).
7. **Reused helper.** The per-closure readiness assessment is imported from the momentum module rather than copied.

## Author source validation

A standalone manual script (not committed, no test files added) built canonical bars for the 74 result fixtures and compared every header value (R17 tolerance, `+0.0` where marked, exact rank and boolean), status, reasons, expected and observed counts and evidence rows with the contract literals: all 74 matched. All 21 refusal fixtures raised the contract's typed error (50 refusal probes including variants). All 7 cross-fixture invariants (including the Ichimoku lookahead pair) held. Deliberately perturbed expectations were detected. A randomized oracle built from independent exact-rational formulas (every prefix of random single- and two-session series) matched all 19,272 runs, correctly rounded for the rational producers, and `channel.keltner.middle` equalled R17 `intraday.ema` in 200 of 200 runs. A before/after snapshot of 2,657 R17 requests (EMA, RSI, ATR, bands, preparation views, refusals, `describe_intraday()`, its digest and the package version) was byte-identical against `origin/main`. The existing `tests/intraday` suite and `tools/check_intraday_boundary.py` pass. Strict typing was not run (mypy is not installed in this environment). `CONTRACT.json` is not amended here; the additive producer, header and unit amendment note remains owed.
