# EF2 money flow and retracement level implementation

[EQ-150 #484](https://github.com/atulsrivas1/equity-features/issues/484) and [EQ-238 #663](https://github.com/atulsrivas1/equity-features/issues/663) library layer: the pure `ef2.money_flow` producer (`intraday.obv`, `intraday.ad_line`, `intraday.cmf`, in `packages/intraday`) and the pure `ef2.retracement_level` producer (`retracement.level`, in `packages/features` as `equity_features.ef2`). The frozen [contract](MONEYFLOW_RETRACEMENT_CONTRACT_PROPOSAL.md) (`ef2-mf1` and `ef2-retrace1`, decisions DP-M1 to DP-R9, rulings O1 to O10 and its coordinator freeze) governs; this slice implements it and redefines nothing. The EF2 I/O mapping (#609), worker (#610) and release acceptance (#486) layers remain separate.

## Money flow

Exact integers and rationals with one final rounding, no Decimal recurrence (the contract fixes exact-rational mathematics; every published float64 is therefore the correctly rounded value and well inside the R17 acceptance tolerance `max(8 ulp, 1e-12 |r|)`). With `C`, `H`, `L` the positive integer coefficients, `V` int64 shares and `a..t` the reset epoch:

- multiplier `(2C-H-L)/(H-L)`, `0` for `H = L`; the volume of a zero-range bar still counts in the CMF denominator;
- OBV starts at `0`; the first priced bar of the epoch only supplies the base close (so the anchor volume is not accumulated), a tie adds `0`, an empty slot adds `0` and never becomes the base; the exact integer is published as int64 and a value outside `[-2^63, 2^63-1]` is a typed `OVERFLOW` refusal of the whole request, raised only when `intraday.obv` is selected and available (intermediate excursions that return in range are fine);
- A/D is the exact sum `sum(MFM_i * V_i)` from the anchor, anchor bar included, published as `numerator / denominator` of two Python integers (one round-half-even conversion; an exact zero is `+0.0`). The sum is formed gcd-free over distinct range denominators, pairwise, so the 4096-slot worst case with 62-bit ranges takes about 0.2 s;
- CMF is `sum(MFV) / sum(V)` over the last `N` governed slots wholly inside the epoch; `N` has no default and is bound in the config exactly when `intraday.cmf` is selected; a zero volume sum is `not_applicable/zero_denominator`.

A slot is priced (row with volume > 0 and the output's required columns), proven empty or unready. Proven empty is either a per-slot coverage entry that is complete with expected 0 (no row), or a row with volume exactly 0 on a slot whose coverage is complete (the shared BAR rule already requires null OHLC, and refuses a zero-volume row with non-null OHLC with `INVALID_SCHEMA`). A null volume is `null_field`, never zero. A slot with no row and no coverage entry, an absent required column, or an empty delivery is `absent_input`; declared incomplete coverage is `governed_gap`; knowledge is enforced on the original `known_at` in both availability modes.

Each output decides readiness from its own dependency slots and columns (OBV needs close and volume; A/D and CMF need high, low, close and volume), so a missing high column leaves OBV available. Reasons are all retained in lexical order and the status follows the contract precedence (`absent_input`, `unknown_availability`, `future_knowledge`, `null_field`, `ineligible`, `governed_gap`, `insufficient_history`, `no_eligible_observations`, `zero_denominator`). Expected is `t-a+1` (OBV, A/D) or `N` (CMF); observed counts ready slots inside the output's own window. An entirely absent delivery (`None`) reports only `absent_input` with observed 0. Witnesses (available outputs only) are the original rows `slot:<index>` anchor then target, or first then last window slot, boundary `completed_interval`, truncated to the result-wide `evidence_limit`; a coverage-proven empty slot that has no row is never invented as evidence.

Admission is the unchanged R17 admission. Its fact record gains an additive internal `volume` field that no R17 output reads; the published R17 EMA/RSI/ATR/band results, identities and catalog digest are byte-identical. The money-flow catalog is a separate own catalog (`describe_money_flow`, `money_flow_catalog_digest`), so `describe_intraday()` still lists exactly the eight accepted R17 IDs.

## Retracement level

`level = (H - r R) / 10^s` for `from_high`, `(L + r R) / 10^s` for `from_low`, `R = H - L`, `r = ratio_num/ratio_den` an exact reduced pair in `0..1` with no default, evaluated as one integer division (a single correctly rounded conversion). It uses no close price. `H = L` is `not_applicable/zero_denominator` (also for `r = 0`); `H < L` or a non-positive coefficient is `ineligible`, and a non-positive side is not counted as observed. A side that is absent, not causal or not completely covered is never inspected. A priced row must carry equal `factor_num`/`factor_den`; a null price with `1 <= factor_num < factor_den` is `insufficient_history`, otherwise `null_field`. Structural refusals precede assessment (`DUPLICATE`, `INCONSISTENT_IDENTITY`, `INVALID_SCHEMA`, `INVALID_UNIT`, `UNSUPPORTED_ADJUSTMENT`, and the shared validator's positive-factor rule).

## Points the contract leaves open (implemented conservatively)

1. **Catalog placement.** The contract speaks of additive entries in the intraday catalog with a changed digest, but the accepted R17 tests and typing example assert exactly eight entries. The three IDs are therefore in an own catalog; merging them into `describe_intraday()` is a one-line change that needs those assertions updated by their owner.
2. **No-row empty witnesses.** A coverage-proven empty slot with no row has no `known_at`, so a consumed evidence row for it would fail the shared `FeatureResult` causal check; such a slot is omitted from the witnesses (values, status, reasons and counts are unaffected). The row form (volume 0, null OHLC) cites normally.
3. **Unspecified refusal codes.** A `text` that differs from the batch snapshot, an observed count above the required window length, and a malformed `x1:` grammar are refused with `INCONSISTENT_IDENTITY`, `INCONSISTENT_IDENTITY` and `INVALID_SCHEMA` respectively (the same classes the EF1 reference producers use); the contract lists no fixture for them.
4. **Fixture M36.** The compact notation lists `known_at: null` for the null-volume slot while expecting only `null_field`; the slot is treated as causal (known_at 50, the notation's default) so that `unknown_availability` does not also apply.
5. **Config shape.** `cmf_period` is bound exactly when `intraday.cmf` is selected, in both directions (`INVALID_CONFIG` otherwise). `policy_version` is a required keyword with no default label.

## Author source validation

A standalone manual script (not committed, no test files added) built canonical bars and extremum packets for the 36 money-flow and 32 retracement result fixtures and 20 plus 18 refusal fixtures, compared every value (bit-exact `float.hex` and the R17 tolerance, `+0.0` where guaranteed), status, reasons, expected/observed counts and witnesses with the contract's literals, and compared every refusal code: all 68 results and all 38 refusals matched with no expected value altered. Money flow was also run with the empty slot as a zero-volume row and as a per-slot coverage entry, with one batch and one batch per slot, and in both availability modes. A before/after snapshot of 2,520 R17 requests (EMA, RSI, ATR, bands, preparation views, refusals, the oracle fixtures and the catalog digest) was byte-identical, and the existing intraday (78) and EF1 (426) test modules passed. Strict typing was not run in this environment. `CONTRACT.json` is not amended here; the additive producer/header amendment note in the contract remains owed.

See the [money-flow API](../api/EF2_MONEY_FLOW.md) and [retracement API](../api/EF2_RETRACEMENT_LEVEL.md). No acquisition, source rights, installed, cross-layer, performance or release claim follows from this source result.
